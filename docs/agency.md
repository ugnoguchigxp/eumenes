# 会話エージェント（agency）と agenda の思考表示

会話の返事と自分からの話しかけは `eumenes-agency` が担う。背景で動く runtime は保存済み設定の `agency.runtime` で決まる。設計と決定は [spec/agency-agenda-integration-2026-11-11.md](../spec/agency-agenda-integration-2026-11-11.md)。

## runtime

| `agency.runtime` | 背景で動くもの | 思考の表示 |
| --- | --- | --- |
| 未設定・`"F"` | 旧 F host（idle の判断で話すか待つかを選ぶ。ログは `agency.decision` / `agency.idle_cycle`） | なし |
| `"always-on"` | agenda エージェント（計画・調べもの・自分からの発話。ログは `agency.llm_call` の `purpose: "think"`） | あり |

既存の環境は未設定（F）のまま。agenda を動かすには設定 API（`POST /api/settings/apply`）で `agency.runtime` を `"always-on"` にする。保存すると host がその場で作り直され、再起動は要らない。どちらが動いているかは `bun run logs -- --component agency` の上の event 名で分かる。

## 自分から話す間合い（agenda）

agent の規則は参照ホスト（agenda の CLI）と同じ。Eumenes が違うのは、言葉を画面が読み上げることと、サーバーの再起動が会話の区切りではないことで、その差は host が埋める（[設計](../spec/agency-agenda-integration-2026-11-11.md)の「参照ホスト（CLI）との挙動差の解消」）。

| こと | 規則 |
| --- | --- |
| 入力中 | 利用者が自分で書いた文が直近4秒以内に変わった間だけ。音声認識が入れた文字、置いたままの下書きは入力中ではない |
| 言葉を「言った」時刻 | 画面が読み上げる言葉は、読み上げが終わった時。そこから15秒（問いの後は60秒、設定の最短間隔がそれより長ければその値）待って次を話す。画面がない・3秒たっても読み上げが始まらないときは、現れた時 |
| 読み上げの間 | その会話は忙しい扱い（計画と発話は止まる。待っている調べものは始まる）。途中で利用者が話せば、その時点で言ったことになる |
| 忙しい瞬間に出そうとした発話 | 同じ文を持ったまま、入力・応答・読み上げが終わるのを待って出す。その間に利用者が話したら出さない |
| 再起動・設定変更の後 | 会話の最新60件を元の時刻で読み直してから計画する（何を聞いたか、最後にいつ話したかを引き継ぐ）。頼まれた静かな時間は残る |

自分から話さないときは、まず画面の状態を見る: `GET /api/agency/conversations/:id/status` の `idle.blockedBy` が `"busy"` のままなら、入力中・読み上げ中・応答中のどれかが続いている。ログでは、返事のあとに `agency.llm_call`（`purpose: "think"`）が出ていれば計画は動いている。

## 会話の返事から担当に頼む

Router が担当に決めた回は、従来どおり host が引き渡す。Router が会話に決めた回（決められずに会話へ回した回も）では、agenda の返事が自分で担当を探して頼める。「作りましょうか？」に「はい、お願いします」と答えた回のように、利用者の言葉だけでは依頼の中身が分からない場合のための道（[設計](../spec/router-package-integration-2026-11-04.md)の「会話の返事から担当に頼む道」）。

| 道具 | すること |
| --- | --- |
| `find_toolchain`（`query`） | 担当を検索する（全文検索・埋め込み・過去の選択）。候補は `id`・`title`・`summary`・`useWhen`・`produces` |
| `delegate`（`toolchain`・`request`） | その返事で見つけた担当に頼む。欄埋め・予告・確認・TODO は Router の引き渡しと同じ host 操作。依頼文は返事が書いた `request` |

- 渡すのは、agenda が返事を担う会話で、利用者の発言に答える回だけ（通知・作業報告・Router の聞き返しの回には渡さない）。
- 引き渡したら返事はそこで終わり、host の予告（「〜に頼みます。」）が回の答えになる。既存のものを変える依頼は、host が確認文を言って待つ。即答の担当の答えは、返事が自分の言葉で伝える。
- 確かめ方: ログの `dialogue.read_tools_offered` に `source: "work"` があれば道具は渡っている。探した回は `dialogue.candidates_selected`、頼んだ回は会話ログの `acted`（`delegate`）に残る。

## 思考の表示

agenda が動いている会話では、考えたこと（足した・落とした予定、重複の確認、聞かない問い、見送った発話、渡した調べもの、返った結果、予定と関心のメモ、静かな時間、失敗）を会話欄に薄い1行で出す。

| 表示 | 意味 |
| --- | --- |
| `💭 + 調べる: 週末の天気（土曜に出かける予定）` | 計画が予定を足した（聞く・調べる・話す） |
| `💭 - 週末の天気（もう答えた）` | 計画が予定を落とした |
| `💭 見送り: 週末の天気 — 今は作業中` | 発話を書く段階で見送った |
| `🔎 [頼まれた] 週末の天気` | 調べものを渡した（`（受付拒否）` `（できませんでした）` が付くこともある） |
| `📝 週末の天気: 土曜は晴れ…` | 調べものの結果が返った |
| `🗓 土曜に出かける予定` | 予定と関心のメモを書いた |
| `🤫 30分、自分から話しかけません（調べものは続けます）` | 返事が静かな時間を変えた |
| `⚠ 考えられませんでした（llm_timeout）` | 計画・step が失敗した |

- 吹き出しではなく、読み上げ・記憶・モデルへの履歴・会話の保存のどれにも入らない。
- サーバーのメモリーに会話ごと最新100件だけを持ち、再起動で消える。その会話で忘却があると全部消える。
- API: `GET /api/agency/conversations/:id/thoughts` → `{ thoughts: [{ id, at, kind, text }] }`。増えたときは SSE の change で画面が取り直す。

## 調べもののメモを見る

調べものの結果はメモになり、できた時点で Markdown の文書として保存される。agency が持つメモの一覧は新しい 30 件までだが、一覧から外れても文書は残る。「メモを見せて」と頼むと、返事が `show_note` を呼び、その文書が開く。

| 項目 | 内容 |
| --- | --- |
| 保存先 | Docling がつながっていれば `eumenes` の `notes/<日付>_<題>_<noteId>.md`。あわせて一時ファイル（`<題>.md`、再起動で消える） |
| 画面 | 会話に文書のチップ付きのメッセージ（題と要約）が出て、Markdown の画面が開く。Docling に保存できた文書は編集でき、一時ファイルだけのときは読み取り専用 |
| 後から開く | メッセージのチップ、または Markdown の一覧の `notes/`（Docling に保存できたもの。表示を頼んでいないメモもここにある） |
| 失敗 | 保存できなかったときはメッセージを出さない。ログは `agency.show_note_failed` |

設計は [agency-agenda-integration](../spec/agency-agenda-integration-2026-11-11.md) の「メモは Markdown 文書として表示する」と「メモを Markdown に蓄積する」。

## 調べものと会話の仕事

agency が自分で始めた調べものは、会話の仕事の一覧（`## State`）には出るが、ルーターの候補（確認・訂正・取消）にはならない。利用者の発言が agency の調べものの取消として扱われることはない。調べものの結果は、返事の `read_note` / `show_note` から使う。
