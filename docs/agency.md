# 会話エージェント（agency）と agenda の思考表示

会話の返事と自分からの話しかけは `eumenes-agency` が担う。背景で動くのは always-on の agenda エージェント（計画・調べもの・自分からの発話。ログは `agency.llm_call` の `purpose: "think"`）だけで、設定の切替はない。設計と決定は [spec/agency-agenda-integration-2026-11-11.md](../spec/.todo/agency-agenda-integration-2026-11-11.md)。記憶系の作り直し（即時の層と睡眠の層）の設計は [spec/memory-architecture-redesign-2026-11-22.md](../spec/.todo/memory-architecture-redesign-2026-11-22.md)。

## 設定変更と host の作り直し

host が設定から読むのは、`agency.thinkResourceId`・`agency.speechIntervalSec`・`agency.interests`・`agency.emotion`・`agency.actions.enabled`、`general.agentName`・`general.userName`・`general.persona` だけ。このどれかを保存すると host を止めて作り直す。保存済みの記録は作り直しの前の設定の `settingsDigest`（この 8 項目の hash）を持つので、新しい host は記録の `settingsDigest` が合わないものを破棄（revoke）する。進行中の調べものの結果は採用されず、計画・メモ・調べものは捨てられる（再起動は要らない）。思考レベル・画面・音声・接続など、ほかの設定を保存しても host は作り直さず、記録も有効のままで、進行中の調べものの結果も採用される。

## 返事に渡す Agency の状態

返事の入力には、末尾の利用者のメッセージの先頭に `## Agency` の節として Agency の状態（計画・関心・メモ・調べもの・問いの候補・静かな時間など）を入れる。現在時刻は `## State` の「今:」だけに置く。記憶は会話エージェントが必要なときに `read_memory` で読み、その返事で読んだ記憶だけを返事の出典として記録する（忘却で消えると、その返事の記録も無効になる）。`## State` には期限の近い予定と、枠に入った目標が載る（[会話の入力](dialogue.md#state-の予定目標の欄)）。登録済みの目標が0件のときは、目標の処理を動かさず、返事には `register_goal` とその規則だけを出す。

背景の呼出し（`plan`・下書き・`askCheck`）には、host が読む時に渡す。記憶に当たる記録（`known`。呼出しごとに plan 12・下書き 6・問いの確認 6 件まで）、計画・目標・未解決の矛盾・質問の台帳（`records`）、それらの印（`marks`）の 3 つで、除外・抑制されたものは渡さない（[設計書](../spec/.todo/memory-architecture-redesign-2026-11-22.md) §5.4）。

- 印の「見直し中」は、変更フィードの訂正（`correction`）で置き換わった旧版を、今の項目（と計画）が根拠に持っているものだけに付ける。項目が現行の版で作り直されれば外れる。見直し中の項目は、返事にも話しかけにも使わない。「抑制」は、事実に付いたものと話題の語の両方で、Agency の話題選びと問いかけから外す。印の読みは、続けて選ぶ 1 回の間は 1 度だけで、読めなければその呼出しを失敗にする（読めなかったものを通さない）。
- 意味の変わらない版の更新（統合。`consolidation`）は、旧版を参照する項目を新版へ付け替える（保存する checkpoint も新版の参照になる）。訂正は見直し中、忘却は落とす。
- 記憶の担当が「止めている」と言うもの（忘却の途中の除外）は、発言・目標・記録のどれからも一つの判定で外す（`withheldMessagesInTransaction`）。除外が起きたら、ref の有無によらず、その根拠を持つ項目・発言・メモを即時に落とす。
- 背景の呼出しの入力は、変わらない部分を先に、変わる部分（agenda・メモ・調べもの・現在時刻）を後に並べ、発言とメモには呼出しをまたいで変わらない時刻を付ける（入力のキャッシュが効く）。利用者の番（入力中・返事の生成中・読み上げ中）の間は、話しかけの下書きを始めない。

## 背景のパス（本人の言葉の記録）

以前の「予定と関心」の Markdown（プロフィールの更新）は廃止した。返事を聞き終えたあとの背景のパスが、会話から構造化した記録を書く（設計書 §5.3）。

| 項目 | 内容 |
| --- | --- |
| 書くもの | 期限付きの計画（L3）と質問の台帳だけ。事実・好み・候補・記憶との食い違いは書かない（記憶は記憶担当の curate-memory が会話から直接書く。[設計](../spec/.archived/memory-direct-curation-2026-11-23.md)）。パッケージが事実・候補・食い違いを返しても捨てる |
| 読まない発言 | 記憶の操作を頼んだ発言（覚えて・忘れて・訂正して・話題にしないで・取り消して。会話の `memory.request` の行為が根拠にした発言）。入力にも記憶の根拠にもしない（パッケージの指示文にも 1 行ある） |
| 処理済みの位置 | 会話ごとに、読み終えた出来事の位置を持つ。記録を書く transaction の中で checkpoint の行と一緒に保存する。設定の変更・epoch の変化で checkpoint が取り消されても、位置は残す（会話の読み位置であって、Agency の記憶ではない）。位置が無い会話は、末尾の 16 件の手前から読み始める（読み飛ばさない） |
| 読む範囲 | 位置より後の発言を 1 回に 8 件・16 KiB まで。超えた分は次のパスで読む。忘却・取り下げ済みの発言は読まない。入力には、関係する計画と質問の台帳を短い参照で付け、重複を書かせない（記憶の一覧は付けない） |
| 起動 | 返事を聞き終えたとき、走っていなければすぐ。走っている間に来た分は、終わった直後にまとめて読む（待ち時間・件数の閾値は置かない）。主会話の呼出しが来ると取り消され、位置は進めず、主会話が空いたときにやり直す |
| 失敗 | 位置を進めず、タイマーは置かない。次の返事を聞き終えたとき（次の起動）に同じ範囲を読み直す |

## 対象の解決（自由文の訂正・忘却・抑制）

会話エージェントが `memory` で `ref` を付けずに訂正・忘却・抑制を頼むと、依頼は steward の inbox に永続で積まれる（記憶担当は ref なしの依頼を扱わず、Agency だけが解決する）。Agency は inbox の未解決の依頼（`pendingTargetsInTransaction`）を、起動時と、commit・run の終わりのたびに読み、構造化出力の呼出し 1 回で解決する。

- 流れは 1 本（single-flight）。走っている間に来た依頼は終わった直後にまとめて読む。会話の忙しさは待たない。主会話に呼出しを取り消されたら、その run が終わった直後にやり直す。固定の待ちは置かない。
- host が検索で選んだ候補（記憶・計画・Agency の項目・直近の発言）に短い参照を付けて見せ、モデルが選んだ参照だけを受け付ける。依頼の語との関連も確かめる。
- 決まった対象には記憶の即時の操作（除外・抑制・訂正）を run の ID 付きで呼ぶ。
  - 忘却: 除外 → `excludedInTransaction`（false なら除外の結果をログに残し、隠す処理は続ける）→ 同じ transaction で `dialogue.hideExcludedInTransaction` → Agency の項目を落とす。閉包削除は記憶担当が行う。
  - 訂正・抑制: 適用後に `settleTargetInTransaction(applied)`。
  - 決まらなかった場合・記憶が断った場合は何も変えず `unresolved`。
- 確定したあと（transaction の外で）`dialogue.targetsSettled(conversationId)` を呼ぶ。dialogue は、その会話の ref なしの忘却が残る間、次の生成を待たせる。

## 自分から話す間合い（agenda）

agent の規則は参照ホスト（agenda の CLI）と同じ。Eumenes が違うのは、言葉を画面が読み上げることと、サーバーの再起動が会話の区切りではないことで、その差は host が埋める（[設計](../spec/.todo/agency-agenda-integration-2026-11-11.md)の「参照ホスト（CLI）との挙動差の解消」）。

| こと | 規則 |
| --- | --- |
| 入力中 | 利用者が自分で書いた文が直近4秒以内に変わった間だけ。音声認識が入れた文字、置いたままの下書きは入力中ではない |
| 言葉を「言った」時刻 | 画面が読み上げる言葉は、読み上げが終わった時。そこから15秒（問いの後は60秒、設定の最短間隔がそれより長ければその値）待って次を話す。画面がない・3秒たっても読み上げが始まらないときは、現れた時 |
| 読み上げの間 | その会話は忙しい扱い（計画と発話は止まる。待っている調べものは始まる）。途中で利用者が話せば、その時点で言ったことになる |
| 忙しい瞬間に出そうとした発話 | 同じ文を持ったまま、入力・応答・読み上げが終わるのを待って出す。その間に利用者が話したら出さない |
| 再起動・設定変更の後 | 会話の最新60件を元の時刻で読み直してから計画する（何を聞いたか、最後にいつ話したかを引き継ぐ）。頼まれた静かな時間は残る |

自分から話さないときは、まず画面の状態を見る: `GET /api/agency/conversations/:id/status` の `idle.blockedBy` が `"busy"` のままなら、入力中・読み上げ中・応答中のどれかが続いている。ログでは、返事のあとに `agency.llm_call`（`purpose: "think"`）が出ていれば計画は動いている。

## 会話の返事から担当に頼む

担当への依頼は、会話エージェントが判断する（雑談か実行依頼か）。依頼なら、返事が自分で担当を探して頼める。「作りましょうか？」に「はい、お願いします」と答えた回のように、利用者の言葉だけでは依頼の中身が分からない場合も同じ道を通る（[設計](../spec/.archived/conversation-first-toolchain-2026-11-21.md)）。

| 道具 | すること |
| --- | --- |
| `find_toolchain`（`query`） | 担当を検索する（全文検索・埋め込み・過去の選択）。候補は `id`・`title`・`summary`・`useWhen`・`produces` |
| `delegate`（`toolchain`・`request`） | その返事で見つけた担当に頼む。依頼は返事自身の担当（`assignments`）になり、host が確認なしで始める。依頼文は返事が書いた `request` |
| `assignment`（`id`・`action`・`text`） | `assignments` の担当への回答（`answer`）・条件の変更（`amend`）・取消（`cancel`）。構造化された質問の答えは `text` に JSON |

- 渡すのは、agenda が返事を担う会話で、利用者の発言に答える回だけ（通知・作業報告の回には渡さない）。
- 担当へ頼んだ返事は、結果を待たずに話して終わる。進捗と担当の質問は状態の `assignments` に出て、終わると「作業報告: …」のメモになり、返事が自分から知らせる（作った物は報告の発言に資源チップとして付く）。起動前の確認はしない。session 型（専門担当への切替）だけは、host の予告（「〜に頼みます。」）が回の答えになる。即答の担当の答えは、返事が自分の言葉で伝える。
- agenda が会話の返事を担当していないときは、`delegate` は `agency_unavailable` で断る。
- 形式・規則・検証は [assignments.md](assignments.md)。
- 確かめ方: ログの `dialogue.read_tools_offered` に `source: "work"` があれば道具は渡っている。探した回は `dialogue.candidates_selected`、頼んだ回は会話ログの `acted`（`delegate`）に残る。

## 思考の表示

agenda が動いている会話では、考えたこと（足した・落とした予定、重複の確認、聞かない問い、見送った発話、渡した調べもの、返った結果、背景のパスが書いた記録、静かな時間、失敗）を会話欄に薄い1行で出す。

| 表示 | 意味 |
| --- | --- |
| `💭 + 調べる: 週末の天気（土曜に出かける予定）` | 計画が予定を足した（聞く・調べる・話す） |
| `💭 - 週末の天気（もう答えた）` | 計画が予定を落とした |
| `💭 見送り: 週末の天気 — 今は作業中` | 発話を書く段階で見送った |
| `🔎 [頼まれた] 週末の天気` | 調べものを渡した（`（受付拒否）` `（できませんでした）` が付くこともある） |
| `📝 週末の天気: 土曜は晴れ…` | 調べものの結果が返った |
| `🗓 土曜に出かける予定` | 背景のパスが記録（記憶・計画など）を書いた |
| `🤫 30分、自分から話しかけません（調べものは続けます）` | 返事が静かな時間を変えた |
| `⚠ 考えられませんでした（llm_timeout）` | 計画・step が失敗した |

- 吹き出しではなく、読み上げ・記憶・モデルへの履歴・会話の保存のどれにも入らない。
- サーバーのメモリーに会話ごと最新100件だけを持ち、再起動で消える。その会話で忘却があると全部消える。
- API: `GET /api/agency/conversations/:id/thoughts` → `{ thoughts: [{ id, at, kind, text }] }`。増えたときは SSE の change で画面が取り直す。

公開調査の受付で参照の失効や権限不足が判明したら、同じ依頼と根拠の版での受付拒否を1度表示します。一時競合は期限内に同じ受付IDで再試行し、受付結果を読めない間はそのIDを照会します。担当の進捗や完了報告は、状態の `assignments`・担当の状態・作業報告メモから確認します。自律処理は、担当の状態更新を受けて確認し直します。

## 調べもののメモを見る

調べものの結果はメモになり、できた時点で Markdown の文書として保存される。agency が持つメモの一覧は新しい 30 件までだが、一覧から外れても文書は残る。「メモを見せて」と頼むと、返事が `show_note` を呼び、その文書が開く。

メモの末尾の「出典」から、調査で参照した資料ページを開ける。URLを確認できた資料がない場合は、その旨を記す。

| 項目 | 内容 |
| --- | --- |
| 保存先 | Docling がつながっていれば `eumenes` の `notes/<日付>_<題>_<noteId>.md`。あわせて一時ファイル（`<題>.md`、再起動で消える） |
| 画面 | 会話に文書のチップ付きのメッセージ（題と要約）が出て、Markdown の画面が開く。Docling に保存できた文書は編集でき、一時ファイルだけのときは読み取り専用 |
| 後から開く | メッセージのチップ、または Markdown の一覧の `notes/`（Docling に保存できたもの。表示を頼んでいないメモもここにある） |
| 失敗 | 保存できなかったときはメッセージを出さない。ログは `agency.show_note_failed` |

設計は [agency-agenda-integration](../spec/.todo/agency-agenda-integration-2026-11-11.md) の「メモは Markdown 文書として表示する」と「メモを Markdown に蓄積する」。

## 調べものと担当への依頼

担当に頼んだ仕事（assignment）の結果も、調べものと同じ形のメモ「作業報告: …」になる。`read_note` / `show_note` と保存の規則は上の表のとおりで、作った物は報告の発言に資源チップとして付く。依頼・状態・規則は [assignments.md](assignments.md)。

| 種類 | 状態に出る場所 | 返事が操作できるもの |
| --- | --- | --- |
| 利用者に頼まれた担当への依頼（`delegate`） | `assignments` | `assignment`（回答・変更・取消） |
| agency が自分で始めた調べもの | 調べものの欄（`researching` など） | なし。利用者の発言が agency の調べものの取消として扱われることはない |

調べものの結果は、返事の `read_note` / `show_note` から使う。

## 登録目標の思考（待機中の1周）

登録目標は、利用者が席を外して Eumenes が待機中のとき（前景の会話・音声認識・読み上げが止まって2分）に進む。1回の自発行動（登録・更新・本人の回答から、完了・質問まで）は、[eumenes-thought-plan](../vendor/thought-plan/manifest.json) 同梱の思考プラン `goal-pursuit` の1回の実行で、最初の段から最後の段まで1つのモデルのセッションで考える。最初のラウンドで、前回どこまで何をやったか、達成しているか・続けられるかを判断し、達成の手順と影響を見積もる。手順はホストが推論なしで1手ずつ実行し、結果が期待どおりなら次の手へ進む。外れたとき（失敗・部分的な成功・検査の不合格、手順を使い切っても未達）だけ、同じセッションの次のラウンドに結果を渡して振り返り、手順を立て直す。思考は1回の自発行動で4回まで（セッションも4ラウンドまで）で、使い切ったらモデルを呼ばずに元の会話へ一度だけ知らせ、本人の回答で新しいセッションを始める。各段の入出力とラウンドは SQLite の台帳（`thought_plan_*`）に残る。完了した目標はそれ以上考えない。目標の進み具合・質問・完了は、担当への依頼と同じく `assignments` の項目（担当「登録目標」）と作業報告メモで会話エージェントに届き、エージェントが自分の言葉で伝える（[assignments.md](assignments.md)）。設計は[1つのセッションで進める](../spec/.archived/goal-thought-session-2026-11-26.md)と[思考の上限](../spec/.archived/goal-thought-budget-2026-11-26.md)。

登録目標の開発作業は、通常の Claude Code と同じ checkout で進める。作業場所やファイルごとの指定は不要。実装が揃っていれば検証へ進み、改修した場合も元の達成条件を別の実行で確認する。実行枠の空きや停止の状態は目標の詳細に残す。 [通常の Claude Code 実行の設計](../spec/.todo/registered-goal-claude-execution-2026-11-26.md)
