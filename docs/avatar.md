# アバター

会話画面の背景メニュー、または「表示」設定の「会話の背景」で、光の妖精・Spatial・桃瀬ひより（Live2D）を選べます。既定の背景と保存済みの選択は変えません。桃瀬ひよりのモデルがなくてもアプリは起動し、会話・音声・設定の操作を続けられます。選択時の読込み失敗は背景内に案内し、別の背景へ切り替えられます。

## Live2Dの表示調整

「チャットを隠す」を押すと、画面左下に「モデルの表示調整」が出ます。開くとズーム（50〜300%）・左右の位置・上下の位置を1%刻みで調整できます。「上半身」は220%へ拡大し、「リセット」は100%・中央へ戻します。拡大は画面上寄りを基準にするため、顔を残しながら胸より下を見切らせる構図にもできます。位置は画面幅・高さに対する割合で、正の値は右・下へ動きます。

調整した構図は同じブラウザーへ自動保存し、チャットの表示、ページの再読み込み、アプリの再起動、別の背景から戻ったときにも復元します。「リセット」した結果も保存します。別の端末・ブラウザーとは共有しません。動きを減らす設定でも表示調整を使えます。モデルの回転やライティングの操作は今回追加していません。

## 桃瀬ひよりのモデルの置き場所

`web/public/live2d/hiyori/` に配置します。このディレクトリのモデル・画像はGitから除外し、`.gitkeep`だけを管理します。現在の作業環境には公式のサンプルを配置済みです。別のcheckoutや配布先には自動で入りません。

[公式サンプル](https://www.live2d.com/learn/sample/)のSDK対応の桃瀬ひよりを取得するか、[公式SDKサンプルのHiyori](https://github.com/Live2D/CubismWebSamples/tree/5-r.5/Samples/Resources/Hiyori)を、ファイル名と相対ディレクトリを保って配置してください。動画向け素材・編集用cmo3だけでは動きません。必要なファイルは次のとおりです。

```text
web/public/live2d/hiyori/
  Hiyori.model3.json
  Hiyori.moc3
  Hiyori.physics3.json
  Hiyori.pose3.json
  Hiyori.2048/
    texture_00.png
    texture_01.png
  motions/
    Hiyori_m01.motion3.json ～ Hiyori_m10.motion3.json
```

moc3・テクスチャ・物理設定・ポーズは公式データを改変しません。モデルの[個別利用条件](https://www.live2d.com/learn/sample/model-terms/)と[無償提供マテリアル契約](https://www.live2d.com/eula/live2d-free-material-license-agreement_jp.html)が適用され、桃瀬ひよりはデザインの改変が禁止されています。画面に著作権表示を付けています。モデルの同梱・再配布は今回行いません。

SDKのCore・Framework・shaderはアプリ側に同梱しており、モデル選択時のファイル取得も同一origin内だけです。[SDKリリースライセンス](https://www.live2d.com/sdk/license/)は開発・検証と製品公開を分けて規定しています。第三者へ配布・公開するときは、事業規模や拡張性アプリケーションの条件も確認してください。出典とSDKの契約は `vendor/live2d/` と `web/public/live2d/*-license.html` にあります。

## 音声と表情

- TTSの発話・読み上げは既存のWeb Audio再生経路を使い、音量調整後の発話だけを解析します。通知音・効果音の再生では解析入力を作りません。
- GPT Liveは既存の主WebSocket中継・SSE・PCM予約再生を維持し、出力Gainの発話音量を同じ制御へ渡します。マイクの解析値や字幕・パケット到着時刻は使いません。
- 音楽の再生・ビジュアライザーは別経路です。口パク用のAnalyserの出力はスピーカーへ接続せず、音声の二重再生を防ぎます。
- 描画ループ（最大24fps）がRMSを読み、0.008以下の小音量を除外します。開きは最大0.7、attack 35ms / release 80msで平滑化します。停止・取消・context休止では0に戻します。毎フレームの通信・React状態更新はありません。
- 新着の応答に感情絵文字が付くと、桃瀬ひよりが同じ感情を短時間表現します。初回に表示した履歴からは感情表現を起動しません。読み上げ中は再生している応答の感情を使い、停止・終了後は会話の状態に戻ります。
- 判定済みの感情で、桃瀬ひよりの公式モーションを単発再生します。素材は公式モデルの `Idle` と `TapBody` から、表情や身振りが合うものを使います。近い感情で同じ素材を使う場合があります。モーションを未配置でも、既存の笑顔・目・眉・頬・口形のプリセットで反応します。口の開閉は音声解析に連動します。
- 発話のcueがないときは、光の妖精と同じく会話の「聞き取り中」「考え中」を表情に反映します。待機中は頭・首・上半身を中心に動き、体の揺れを抑えて足元を安定させます。モデル全体の回転・横移動・跳ねは行いません。通常の表情にも小さな笑顔・目元・眉・口角の変化があります。動きを減らす設定では静止します。
- Liveには現行の表情情報がないため、待機時と同じ通常の表情変化だけを使います。既存判定器を字幕へ適用する案は追加推論・字幕区間・失効の設計が必要で、今回実装していません。
- 瞬きはフロント内で3〜7秒間隔・160〜280msの閉眼を生成します。表情で目を細めた状態に掛け合わせ、口の開閉とは別に最終適用します。動きを減らす設定とタブ非表示では描画ループを止めます。

光の妖精の既存の表情・身振り・瞬きは維持し、今回の新しい顔制御は桃瀬ひよりへ接続しています。精密な音素同期は行いません。Liveのマイク休止は入力だけを止める操作なので、既に再生するアシスタント音声には引き続き口パクします。接続終了・切断では再生と解析を解放します。Providerの発話途中の割込みは、現行Live契約に独立した出力取消イベントがないため、今回新しい取消プロトコルを追加していません。

## 検証

`bun x playwright test tests/browser/avatar-control.spec.ts` はサーバーを起動せず、消音したブラウザーで確認します。モデルがある場合は実際のWebGLモデルとTTS/Live再生経路を使い、音楽・マイクの分離、閉口、再接続とモデル再作成、Coreの重複読込みを確認します。音声は固定データで、外部Providerへの接続試験ではありません。モデルがない場合は実モデルの試験だけをskipし、モデル欠落時の起動継続・入力・切り替え試験は実行します。

実Provider、本人のマイク・スピーカー、3往復の実機器受入は別途必要です。
