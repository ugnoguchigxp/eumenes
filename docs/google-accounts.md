# Googleアカウント連携

設定アーティファクトの「Google連携」で、Googleアカウントを1件接続する。基本プロフィール（名前・画像）とメールアドレスだけを取得する。Calendar・Gmailの権限、同期、通知、AI操作は今回の対象に含めない。別アカウントへの切替は、現在の連携を解除してから接続する。

## 初回設定

1. Google CloudのGoogle Auth PlatformでOAuth同意画面を設定し、**ウェブアプリケーション**のOAuthクライアントを作成する。テスト公開の場合は利用するGoogleアカウントをテストユーザーへ追加する。
2. 承認済みリダイレクトURIに、EumenesのWeb画面のオリジン＋`/oauth/google/callback`を登録する。標準構成の例は `http://127.0.0.1:5173/oauth/google/callback`。実際の`EUMENES_ORIGIN`とホスト名・ポートまで一致させる。バックエンドの8787番ではない。
3. バックエンドに `EUMENES_GOOGLE_CLIENT_ID` と `EUMENES_GOOGLE_CLIENT_SECRET` を設定して再起動する。秘密を`VITE_`変数や画面へ渡さない。Google連携の設定がない環境では、画面の接続ボタンは無効になる。
4. 設定 → Google連携 → Googleアカウントを接続。別タブでアカウントを選び、アクセスを許可する。完了したタブを閉じると元の設定画面に接続状態が反映される。ポップアップがブロックされた場合は「認証画面を開く」を使う。

Eumenesをログイン済みのChromeプロファイルで開けば、Googleのアカウント選択時にそのログイン状態を利用できる。Eumenesへのアクセス許可は別途必要であり、ChromeのCookieを取り出して使う方式ではない。Codex等の埋め込みブラウザはChromeとログイン状態を共有するとは限らない。

Webフロントは `/oauth/google/callback` と `/oauth/google/result` を同じバックエンドへプロキシする。Viteの開発構成には登録済み。他の配信構成では同等の経路を用意し、この2経路へAPIのBearer認証を注入しない。URLの認証コードをアクセスログに記録しない。

## 接続状態と保存

- 未接続・接続済み・再接続が必要・解除中を表示する。通常の設定の「保存」操作は不要。
- 許可するscopeは `openid email profile` のみ。追加のサービス権限は要求しない。
- IDトークンの署名・発行元・宛先・有効期限をGoogle公式ライブラリで検証し、nonce、メール確認済み状態、安定したアカウントID（`sub`）も検査する。再接続では同じ`sub`を必要とする。
- 認証要求は10分で失効。state、PKCE、HttpOnly/SameSite=Lax Cookieでブラウザと認証応答を対応付け、一度しか処理しない。取消・解除・新規認証後に古い結果が届いても採用しない。
- トークンと保留中の認証情報はsettingsの既存マスターキーから用途別に派生した鍵でAES-256-GCM暗号化し、専用テーブルに保存する。Webへの返却や共通操作台帳にはトークン・認証コードを含めない。DBと既存キーのバックアップは一組で管理する。
- バックエンド稼働中、60秒ごとに期限間近のトークンを更新する。Google側で許可が取り消された場合は、次の更新時に再接続状態へ移る。即時検出を保証するものではない。
- 解除は確認後にGoogleの許可を取り消し、保存情報を削除する。通信に失敗した場合は「解除中」で保存し、再起動後も再試行する。解除中は新しい接続を開始できない。
- Googleの取消APIは当該アプリに与えた許可に影響する。将来別ドメインで権限を増やす際は、OAuthクライアントの共有と解除の単位を改めて設計する。

## 実装と確認

`google-accounts` domainが認証・暗号化保存・失効管理を所有する。画面は `artifact:settings.google-accounts@1`、設定入口は `artifact:settings.hub@6`。既存の登録式アーティファクトとWeb adapterを使用する。DomainAdapterは公開状態の読み取りのみで、操作・AI用toolchain・packageは登録しない。

OAuthの開始・取消・解除は認証済みの専用API、GoogleからのcallbackはCookieとstateを検証する専用経路を使う。Googleのリダイレクトは共通APIのBearerを送信できず、トークン交換は外部通信を伴うため、同期transactionの共通操作台帳に入れない。

固定試験ではGoogle応答を置き換える。実Googleアカウントでの同意・取消はOAuthクライアントを設定して別途確認する。
