# 音声会話

入力欄の補助操作にある波形付きの「Live」で開始し、四角の停止アイコンで終了します。横の設定アイコンから専用設定を開けます。送信ボタンは従来どおり右端にあります。Live中も文字で補足できます。マイクの休止は接続の終了とは別の操作です。

## 最初の設定

1. 歯車から「音声会話」を開き、OpenAI公式の接続を登録します。接続名は「OpenAI音声」など、見分けるために自由に付ける名前で、OpenAI側のキー名と一致させる必要はありません。APIキーは画面の秘密入力欄へ入力します。このチャットへ貼る必要はありません。既存の接続も選択できます。
2. 接続の登録を保存してから、音声会話の利用とクラウドへの音声・必要な会話の送信を許可し、「音声会話」タブでその接続を選んで保存します。保存ボタンはタブの上の共通バーに常時表示します。
3. 「接続を確認・モデル一覧を更新」で利用可能なモデルを取得します。モデル一覧だけではLive対応や権限は確定しません。利用するモデルを選択して保存します。声もSelectBoxから選び、APIの既定を選ぶこともできます。話し方の補足は固定候補がない自由記述です。モデル名はコードへ固定せず、声の候補は公式仕様に列挙された識別子を登録しています。
4. 「音声会話を試す」でマイク・応答を確認し、テストを終了します。通常の会話履歴・記憶には追加せず、テスト字幕は終了時に削除します。接続と試用にはAPI料金が発生します。
5. チャットに戻り、波形アイコンから開始します。マイクへのアクセス許可が必要です。

未保存の変更がある間は接続確認・試用を開始できません。APIキーの更新・削除は、同じ画面の「APIキーの管理」から共通の接続設定で行います。同じ接続を使う他の機能にも変更が反映されます。

## 会話の記録と既存機能

Liveでも通常会話で設定したエージェントの名前・人格・口調を引き継ぎます。「声の指定」は声質を選ぶ設定です。声質が変わっても、エージェントの名前・役割・口調は維持します。字幕の進行中・履歴・作業開始前の返答には同じエージェント名を表示し、文字起こしの注記は回答者名と分けます。

受信した字幕の空白・反復を保ち、進行中の字幕をチャットへ表示します。受信範囲を閉じると通常履歴へ一度だけ保存します。音声ファイルは保存しません。「正確な記録」はAPIから受信した字幕の原文を保持する意味で、聞き間違いのない文字起こしを保証するものではありません。出力字幕も、スピーカーで最後まで再生された証拠とは区別します。

Live中は、通常会話のASR・TTSを停止して、状態の吹き出しを両方OFFにします。自動読み上げ・読み上げ直し・通常の音声サンプルと重ねて実行しません。Live終了後、通常のマイクは自動再開せず、利用者の開始操作を待ちます。

外部の情報・記憶・仕事は既存のツールチェーンへ委任します。担当選択と承認の判断は既存のLLMが行います。文字補足も同じ処理に渡します。確認が必要な内容は画面へ正確に表示し、「内容を確認しました」の操作後、音声または文字で承認・拒否を伝えます。音声の言い換えやAPIの受付だけで承認された扱いにはしません。

設定の無効化、送信許可の取消、APIキーの変更・削除、接続の切断、会話の訂正・削除ではLiveを停止します。途中まで受信した字幕と、終了時の利用量を確認できたかどうかを区別して残します。再接続は開始ボタンから明示的に行います。モデル・声・話し方の変更は次の接続から反映されます。

## キーの保存

既存の接続・資格情報管理を共用します。キーはbackendでAES-256-GCMにより暗号化し、SQLiteの資格情報領域へ保存します。暗号鍵は既存の環境設定、またはDBと同じ場所の `keys/settings.key` を使用します。鍵ファイルは0600、親ディレクトリは0700です。ブラウザのlocalStorageや会話ログにキーを保存せず、保存後のキー全文は再表示しません。バックアップではDBと暗号鍵を一緒に保全します。

## 検証状況

固定試験・ブラウザでの画面確認と、実API・本人の機器を使った受入は別に管理します。[実装・検証記録](../spec/verification/live-voice-2026-10-31/results.md)を参照してください。実機器で3往復の受入が済むまで、音声MVPの受入完了とはしません。
