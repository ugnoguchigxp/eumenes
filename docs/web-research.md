# Web 取得

Web取得はnpm版 `llm-fetch@0.1.2` をbackendから利用します。検索と通常のページ取得は毎回実行し、`web read --stable` で指定したページだけ専用SQLiteに保存します。`--fresh` は保存済み本文を使わず取得し直します。保存データは最大24時間だけ再利用し、14日間使われなければ起動時・1時間ごとの掃除で削除します。HTTPが保存を禁止するページは保存しません。結果の受取期間は15分で、backendの再起動でも失われます。

会話担当は一回の生成で回答または調査依頼を返します。調査は一つの子が固定の `invoke/finish` 契約で進め、元依頼・許可されたツール・提示済み根拠を使います。検索語、資料の選択、対象・日時・単位・条件の読み取り、要約はLLMが担当します。ホストは契約、権限、予算、取消、根拠の存在と版を検査します。

現在の調査担当は `package:web.quick@1` を使い、`web.lookup` と `web.read` だけを提供します。検索1回・ページ取得1回、モデル呼出しは報告候補の意味検証・修正分を含めて最大5回です。保存本文の探索や複数資料の比較を行う従来の経路は、現在の担当から外しました。HTMLとJSONは同じガードを通し、JSONの項目を天気・株価向けに変換しません。専用の地域辞書、銘柄辞書、固定URL生成、本文抽出、固定回答生成、旧取得先学習の実行経路は削除しました。保存済みの旧取得先と手順は閲覧・停止・解除・削除できますが、新しい調査へ自動適用しません。

大量・詳細なWeb調査はCodex Lunaへ委任します。Lunaの実行接続は実装済みで、`package:web.research@9` の検索・本文取得・保存本文内検索・範囲読取りを使います。長文用の共通処理はLunaが利用します。語句確認や簡単な最新情報の取得は現在の担当を使い、振り分けはLLMが判断します。接続設定は[toolchain](./toolchain.md)を参照してください。

関連: 保存済みの取得先と手順は [research-routes.md](research-routes.md)、会話からの調査は [toolchain.md](toolchain.md)。
