# Web 取得

Web取得はnpm版 `llm-fetch@0.1.4` をbackendから利用します。検索と通常のページ取得は毎回実行し、`web read --stable` で指定したページだけ専用SQLiteに保存します。`--fresh` は保存済み本文を使わず取得し直します。保存データは最大24時間だけ再利用し、14日間使われなければ起動時・1時間ごとの掃除で削除します。HTTPが保存を禁止するページは保存しません。結果の受取期間は15分で、backendの再起動でも失われます。

HTMLとJSONは同じガードを通し、JSONの項目を天気・株価向けに変換しません。ヒューリスティックが見つけた箇所は、会話履歴も実行ツールも持たない制御推論が分類します。接続は会話と同じ経路（設定の会話用途）を使います。文書全体を指示の注入または判定不能とした場合、その本文を根拠として採用しません。専用の地域辞書、銘柄辞書、固定URL生成、本文抽出、固定回答生成、旧取得先学習(research-routes)は削除しました。同じ依頼で取得し直すページは、`web_search` ツールチェーンの手順キャッシュ(一致判断はLLM、値は毎回取得)が扱います。

検索地域を省略した場合、検索サービスが指定言語に対応する地域を選びます。言語だけを変更した入力へ日本を一律に補いません。明示された地域はそのまま渡します。

検索の応答は最大10秒待ちます。検索サービス内の通信と代替経路への切替もこの上限に含みます。

Web担当の報告は、依頼を満たす必要最小限の情報量にします。回答案には必要な事実・留保・出典リンクを残し、要約や主張で長い説明を繰り返しません。詳しい比較や列挙を依頼された場合は、その項目と詳細を保ちます。取得本文・出典と根拠の対応は既存のSQLite保存を使い、保存のための本文転載は生成しません。`skill:web.guided@5`で指示を調整し、会話担当が最終回答を作る経路、出力schema、生成上限と時間配分は維持します。直接回答への切替は今回の対象外です。

2026年10月21日の[検証記録](../spec/verification/toolchain/web-report-volume-2026-10-21.json): 固定試験は成功。実モデルの単純確認1例では生成が207→123トークンとなりましたが、入力は増えており、総トークン削減を示す結果ではありません。不明・矛盾を含む新版の1例が空JSONとなったため、実モデル受入は未達です。稼働中backendへの登録・再起動、Web取得から音声までの通し受入は行っていません。

会話からの調査経路(担当・予算・報告)は [toolchain.md](toolchain.md)、Web検索の実装目標と未達は [Web検索 実装目標](../spec/.archived/web-search-target-2026-10-11.md)、手順キャッシュと選択の記録は [toolchain.md](toolchain.md) を参照してください。

会話のWeb担当が選んだ複数の取得先は、通常のツール呼出しとQueueで実行し、選択した組の結果をまとめて担当へ戻します。専用の追加取得タイマーや到着数の正本を設けません。再試行の待ち時間はQueueのavailableAtで扱い、取得開始後の通信上限と元のタスク期限は維持します。指定URLの権限照合は日本語パスや国際化ドメインを含む同じURL正規形で行います。
