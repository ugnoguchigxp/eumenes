# 会話本文の生成中表示

2026-11-15。利用者は[待ち時間の診断で提案した設計](../verification/conversation-latency-2026-11-15.md)に合意し、生成中の文字表示と取消・失敗時の除去を明示的に依頼した。本書は実装前の具体化であり、その範囲で進める。

## 範囲と契約

- 既存の `AnswerStreams`、進捗SSE、共通client、`useRunProgress`、`LiveMessageList` を接続する。モデルの指示・判断・接続先、保存処理、DBスキーマ、認証方式は変更しない。
- `RunProgress.text` は running 中に暫定本文を持ち、`provisional: { generationId, sequence }` で生成と更新順を識別する。採用済み・本文なしは `provisional: null`。従来の接続との互換のため項目は optional とする。
- 通知は差分文字列でなく、現在の全文のスナップショット。既存の遅い受信側向けの最新値保持を使う。各生成内の連番は単調増加し、新しい生成の開始は空本文で置き換える。
- 本文はメモリにのみ存在する。本文通知ごとにDBを読まず、購読開始・保存確定・明示の進捗通知で得たrun状態へ重ねる。履歴や新しい永続台帳には保存しない。
- 生成の取消・失敗・権限や参照情報の失効でsignalが中止されたら、端末への空本文通知とバッファの破棄を行う。古い生成や遅れて戻った通知では新しい内容を上書きできない。
- run完了では保存済み回答を返す。失敗・取消・削除では暫定本文を返さない。購読中のrun削除は取消状態を通知して接続を閉じる。
- 再接続時は画面の暫定本文を一旦消し、サーバーに残る現在の生成だけを受ける。旧接続の遅い通知は無視する。認証拒否・削除でも表示を消す。
- 画面の暫定本文は既存のplain text表示とし、途中のMarkdownリンクを操作可能にしない。履歴に同じrunの採用済み回答が届いたら暫定行を除き、二重表示を防ぐ。読み上げや確定回答のアクセシビリティ通知は既存の責務を使う。

## 作業順・完了条件

1. 既存動作と差分を保存し、部分試験で「生成中に本文が届かない」を再現する。
2. 生成ストリーム→進捗の橋渡しとメタデータを実装する。置換・中止・削除・保存完了の順序、再購読、未保存を検証する。
3. 共通clientで生成と連番を検証し、Webで接続切れや取消・失敗を消去する。保存済み回答との重複も検証する。
4. 公開SSEの結合試験と、消音Chromiumで実client・hook・表示部品を使う画面試験を行う。途中表示を確認してから取消・失敗を発生させ、除去と遅い通知の拒否を確認する。
5. `bun run verify -- --domain dialogue --domain conversation --domain voice-dialogue`、型・静的検査を行う。既存の失敗と今回の回帰を分け、通っていない検査を成功扱いしない。

画面試験は既存のブラウザー通信の差替え方式を用い、検証用サーバーの起動を必要としない形で準備する。稼働APIを新版へ反映する再起動が必要なら、実装と検証を終えてから別途許可を得る。通常画面でのlive確認は固定試験と区別する。
