# 登録目標の結果を、担当への依頼と同じ経路で伝える

2026年11月26日。利用者合意（「はい、実装まで進めてください」）・実装済み・固定試験済み・実稼働の確認待ち（§6）。利用者の指摘（「会話エージェントが考えてやるのではなく、サブエージェントなんですね。まあそれはそれで良いけど、結果共有は他のツールと同等の動きになるでしょうか？」）と、その方向での設計の依頼（「はい、その方向で設計書を書いてください」）による。

目標の思考と実行は、これまでどおりサブエージェント側（[1つのセッションで進める設計](goal-thought-session-2026-11-26.md)）で行う。変えるのは、結果と質問を利用者へ届ける経路だけ。担当への依頼（[assignments](../../docs/assignments.md)）と同じにする。

## 1. 今の違い

| 項目 | 担当への依頼（`delegate`） | 登録目標（今） |
| --- | --- | --- |
| 会話エージェントの状態 | `assignments` に、状態・進捗・質問が出る | `## State` の目標の枠に、目標の文と状態だけが出る。進捗・質問は出ない |
| 完了 | 作業報告メモになり、会話エージェントが自分の言葉で知らせる。作った物は資源チップとして付く | ホストが決まった文（`report.text`）を assistant の発言として会話に書き足す（`goal-report-delivery.ts`） |
| 質問 | `assignments[].question` に出て、会話エージェントが利用者にたずねる | ホストが質問文をそのまま会話に書き足す（`goal-question-delivery.ts`）。上限の知らせも同じ |
| 回答 | `assignment(answer)` | `update_goal(answer_question)` |
| 途中経過 | `progress` に出る（担当の持ち主の view から毎回読む） | 出ない。`list_goals` で聞いたときだけ分かる |
| 読み返す・見せる | `read_note`・`show_note` | 書き足した発言だけで、メモがない |
| 画面にない会話 | 依頼した会話で、約束を守るまで段取りが回り、そこで伝わる（`keepsPromise`） | 書き足しなので、画面にない会話でも黙って増えるだけ |

## 2. 変えた後

| 項目 | 内容 |
| --- | --- |
| 状態 | 自発行動中の登録目標を、`assignments` に担当と同じ形で出す。`id` は会話エージェントの項目の id（担当の項目と同じ採番）、`assignee` は「登録目標」、`request` は目標の文の先頭80字、`askedByUser: true` |
| 状態の値 | 下の表のとおり、担当と同じ語を使う |
| 途中経過 | `progress` に、いま実行中の手と、最後の結果の観測（120字まで）を出す。サブエージェントの手順の各手は、ここで読めるだけで、会話エージェントからは知らせない（担当の進捗と同じ） |
| 質問 | 目標の質問（`judge`・`reflect` の ask）と上限の知らせを、`question` に出す。文面は会話エージェントが自分の言葉にしてたずねる。ホストは会話に書き足さない |
| 回答 | 利用者の答えを、会話エージェントが `assignment(id, action: "answer", text)` で渡す。ホストは目標の質問への回答として記録し（既存の `answerGoalQuestionInTransaction`）、新しい自発行動が始まる |
| 取消 | `assignment(cancel)` は目標の取下げ（既存の `update_goal` の取下げと同じ処理）。条件の変更 `amend` は目標の改訂（`update_goal` の改訂）に写す |
| 完了 | 作業報告メモにする。会話エージェントが、担当の完了と同じく自分から知らせる |
| 止まった目標 | 取下げ・改訂・権限の取消・停止・忘却で目標が見えなくなったときは、項目を何も言わずに終える（`やめた`）。目標の止まった理由は `list_goals` で読める |
| 画面にない会話 | 目標の元の会話（`deliveryConversationId`）で、伝えていない完了・質問がある間は段取りを回す（担当の `keepsPromise` と同じ） |

| `status` | 目標のときの意味 |
| --- | --- |
| `待っている` | 待機中の判定待ち、待機条件の待ち、時間を置いた見直し、実行先の空き待ち |
| `進めている` | 考えている、または手順の手を実行中 |
| `質問がある` | 本人への質問（上限の知らせを含む）の回答待ち |
| `終わった（メモ n… になった）` | 達成した。メモは `notes` にある |
| `やめた` | 利用者の取下げ、または目標が見えなくなった（改訂・権限の取消・停止・忘却） |

## 3. 作業報告メモ

担当の作業報告と同じ形にする。題は `作業報告: <目標の文の先頭50字>`。

| 欄 | 中身 |
| --- | --- |
| 依頼 | 目標の文（達成条件を含む原文） |
| 結果 | 達成した条件と、それを確かめた検査の判定の観測 |
| 達成したこと | 条件ごとに、合格した検査と根拠 |
| 残ったこと | 未確認の点（検査の判定が挙げたもの） |
| 作ったもの | 手順の中で作った物（改修したファイルの一覧など、担当が返したもの） |

```markdown
# 作業報告: Live2Dの背景を設定でさまざまな色に変更できるようにすること。達成条件は、

## 依頼

Live2Dの背景を設定でさまざまな色に変更できるようにすること。達成条件は、設定から背景色を変更できること。

## 結果

設定画面の「表示」から背景色を保存し、会話画面の描画領域に反映されることを、関連する試験4件で確かめた。

## 達成したこと

- useAvatarBackdrop.test.tsx: 背景色の保存・削除・失敗時の保持
- HiyoriAvatarBackground.test.tsx: 選んだ色の描画と、保存・再表示
```

## 4. 責務の分け方

| 部品 | 変更 |
| --- | --- |
| agency パッケージ（`eumenes_agency`） | `assignments` に、ホストが渡す登録目標の項目を担当の項目と並べて出す。`assignment` ツールが目標の項目の id を受け、回答・変更・取消をホストの目標の口へ渡す。完了した目標の作業報告メモを、担当の完了と同じく自分から知らせる対象にする。`update_goal` の `answer_question` は外す |
| 本家（ホスト） | 目標の進行（`goal_progress` と `state.cycle`）から項目の状態・進捗・質問を作って渡す。完了時に作業報告メモを作る（担当の `reportNote` と同じ形）。回答・取消・改訂を既存の目標の操作に写す |
| 外すもの | `goal-report-delivery.ts`・`goal-question-delivery.ts` の会話への書き足し。ホストが作る上限の知らせの文面（`ownerNotice` は質問の中身だけを返す） |
| 変えないもの | 目標の登録（`register_goal`）、枠と優先度（`list_goals`・`update_goal` の改訂・取下げ・枠の解放・許可）、思考と実行（サブエージェント側）、`## State` の目標の枠 |

## 5. 順序と合格条件

| 段 | 内容 | 合格条件（固定試験） |
| --- | --- | --- |
| 1 | 会話エージェントの項目: 目標の項目を `assignments` に出し、`assignment` で回答・変更・取消を受ける。完了の作業報告を知らせる対象にする（agency パッケージの既存の口で足り、パッケージは変えなかった） | 項目が担当と同じ形で出る。目標の項目への回答がホストの口へ渡る。完了の報告が自分からの発言になる |
| 2 | 本家: 項目の組み立て、作業報告メモ、回答・取消・改訂の写し。書き足しの削除 | 目標の質問が `question` に出て、会話には書き足されない。回答で新しい自発行動が始まる。完了で作業報告メモが1件でき、知らせが1回だけ出る。画面にない会話でも伝わる |
| 3 | 本家での確認 | 利用者による再起動後、目標の質問・完了が会話エージェントの言葉で届く |

## 6. 実装

agency パッケージは変えずに済んだ。会話エージェントの項目（`requestResearch` の `delegatedTo`・`userRef`）、進捗と質問（`assignmentObserved`）、結果（`researchReturned`）、取消（`assignmentEnded`）の既存の口に、目標を担当として載せた。

| 部品 | 内容 |
| --- | --- |
| `goal-assignments.ts` | 担当名「登録目標」、目標の見え方（`GoalWorkView`）と口（`GoalWorkPort`）、項目の作成（`offerGoalItems`）、項目と目標の結び付け（`goalTicket`）、作業報告メモ（`goalNote`） |
| `goal-work.ts` | 目標の見え方を目標の進行から作る（自発行動中か、伝えていない完了報告があるもの）。回答・改訂・取下げは `update_goal` と同じ処理に写す。失効した完了報告は起動時に外す。会話には書き込まない |
| `always-on-flow.ts` | 目標の項目の発行は、作業を始めずに目標の券として持つ。目標が消えていれば何も言わずに項目を終える |
| `always-on-cycle.ts` | 結果の取込みで、項目を作り、進捗と質問を伝え、完了報告を作業報告メモにする（目標の報告を伝え済みにするのと同じ書込み）。消えた目標の項目は何も言わずに終える |
| `always-on-assignments.ts` | `assignment` の回答・変更・取消を目標の口へ渡す |
| `always-on-goal-reply.ts` | `update_goal` から質問への回答（`answer_question`）を外して見せる |
| 削除 | `goal-report-delivery.ts`（会話への完了報告・質問の書き足し）、`goal-question-delivery.ts` の配送（以前に書き足した質問の発言を忘却で取り消すための ID だけ残す） |

| 固定試験 | 内容 |
| --- | --- |
| `goal-assignments.test.ts` | 目標が会話の項目に1回だけなる。質問が項目に出て、エージェントが一度たずねる。`assignment(answer)` が目標へ届き、利用者の発言なしでは断る。完了報告が作業報告メモ1件になり、エージェントが知らせ、目標の報告が伝え済みになる。消えた目標の項目は黙って終わり、`cancel` は取下げになる |
| `goal-question-delivery.test.ts` | 目標の静かな時間が終わるまで質問は出ない。答えると質問が消える。会話に書き込まない。改訂・取下げ・忘却した目標は出ない |
| `goal-completion.test.ts` | 完了の報告が完了後の版でも出る。会話に書き込まない。根拠を忘れると消える。伝え済みの報告は出ない |

| 変えた扱い | 内容 |
| --- | --- |
| 構成の変化で解ける質問 | 思考プランが質問の解消を出さなくなったので、構成の変化で解ける質問も本人にたずねる |
| 元の会話が分からない完了報告 | 目標の元の発言の会話で伝える |

### 独立レビューで直したこと（11月26日）

| 指摘 | 対処 |
| --- | --- |
| 目標の質問・完了が、目標側の書込みだけでは会話エージェントに取り込まれなかった（旧配送の購読とタイマーを消したため） | 取込みの契機（`dbSignature`）に、その会話の目標の見え方（進捗・質問・完了報告）を加えた。目標側の静かな時間で止めている質問は、明ける時刻にタイマーで取り込む（`heldUntilInTransaction`） |
| 会話エージェントの指示が、外した `answer_question` を使えと言っていた | `goal-work.context.toml` を、`assignments` の項目と `assignment` の回答・取消・変更で扱う文に改めた |
| 再起動で目標の券が捨てられ、券のない間の取消が目標に届かず「やめた」とだけ答えた | 目標の券は項目が続く間は残す。券のない項目への回答・取消・変更も、会話と文面で目標を見つけて届ける |
| 回答が、利用者にたずねた質問ではなく、その時点の目標の質問に付いた | たずねた質問（項目の `question`）と目標の今の質問が違えば `goal_question_not_current` で断る |
| 完了メモと質問が、根拠の忘却に連動しなかった。質問の発行元の検査も落ちていた | 完了メモの `inputs` に報告の根拠を入れた。質問は、根拠の忘却・発行元の作業と許可の失効で出さない |
| 目標側の例外が、担当の結果の取込みまで止めた。読取りの一時失敗で「やり遂げられなかった」と話した | 目標側の取込みを分けて失敗を記録するだけにした。項目の発行時の読取り失敗は再試行にした |
| 項目と目標の結び付けが会話を見ていなかった | 会話も照合する |

| 残る制約 | 扱い |
| --- | --- |
| 同じ会話に同じ文面の目標が2つあると、2つ目は項目にならない（会話エージェントが同文の依頼を重複として断る） | 目標は登録の時点で別の文面になる前提。起きれば2つ目は `list_goals` でだけ読める |
| 完了報告を取り込んだ直後、チェックポイントの保存前に落ちると、知らせが出ない（メモは残る） | 担当の結果と同じ窓。メモは `read_note` で読める |
