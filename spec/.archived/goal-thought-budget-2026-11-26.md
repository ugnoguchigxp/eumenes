# 登録目標の思考に上限を設ける

2026年11月26日。対象は[待機中の思考の連続で進める再設計](../.todo/goal-idle-deliberation-redesign-2026-11-26.md)。利用者の指摘と決定（「無限に思考して良いわけじゃないぞ」「1回でやっていいthought-planはせいぜい3,4回を上限にするべき」「タスクが完了したら達成し、それ以上はするべきではない。やったとしてもレトロスペクティブ1回」）による設計変更。実装済み・固定試験済み・実稼働の確認待ち（§6）。思考の1周の作りは[1つのセッションで進める設計](goal-thought-session-2026-11-26.md)で置き換え、上限は「1回の自発行動の思考（ラウンド）4回」として残した。答えの決まった周（`mustPause`）は、止まり続けの判定とともに削除した。

## 1. 実測（11月26日、目標1）

| 項目 | 値 |
| --- | --- |
| 思考プランの実行 | 完了11回・失敗6回（入力の上限超過）。振り返りの入力は平均35,615字、方法の段は30,145字 |
| 答えの決まった推論 | 17:23・18:23 の2回は「変化なし・待つか聞くだけ」の状態で振り返りを呼び、`wait` を返させた |
| 上限 | なし。止まった目標は1時間から倍々（上限24時間）で永久に見直す |
| 推論量の記録 | 台帳のトークン数がすべて0。推論の接続口が使用量を返していない |

## 2. 規則

| 規則 | 内容 |
| --- | --- |
| 1回の自発行動 | 目標が本人の発話なしで進む区切り。始まりは、登録・目標の更新・本人の回答。終わりは、完了・本人への質問・上限 |
| 思考の上限 | 1回の自発行動でモデルを呼ぶ思考プランの実行は **4回まで**。同じ入力の結論の再利用、計画どおりの次の手、検証の組み立てなど、モデルを呼ばない周は数えない。入力の上限超過などモデルに届かなかった失敗も数えない |
| 上限に達したとき | 5回目は実行しない。目標を待機に入れ、時刻による見直しをやめる。元の会話へ一度だけ伝え、本人の回答で次の1回が始まる |
| 答えの決まった周 | 変化がなく、待つか聞くことしか選べないとき（`mustPause`。定義上つねに変化なし）は、モデルを呼ばずに上限と同じ知らせを出して本人の回答を待つ。この周は上限に数えない |
| 完了 | 目標が達成されたら、その目標についてそれ以上は考えない。振り返り（レトロスペクティブ）を行う場合も1回までとする。現在は振り返りの結果を読む仕組みがないため行わない |
| 構成・検査の変化 | 能力・検査の版・証拠などの変化は、上限が残っている目標だけを起こす。上限を使い切った目標は起こさない（本人の回答だけが再開の条件） |
| 推論量の記録 | 各段の入力・出力トークンを台帳に残す。周の数とトークンの合計を `agency.goal_cycle` のログにも出す |

## 3. 上限に達したときの知らせ

既存の質問配送で元の会話へ届ける。新たな推論はしない。最後の振り返りがモデルの書いた理由を持つので、それを添える。

```text
目標「Live2Dの背景を設定でさまざまな色に変更できるようにすること。」について、4回考えて進めましたが、達成を確かめられていません。
最後の判断: 設定画面からの経路は確認できたが、独立検査は不成立で達成条件を確認できていない。
続けてよいか、やり方の指定があれば教えてください。
```

| 項目 | 内容 |
| --- | --- |
| 配送 | 既存の質問として1件。同じ自発行動の中では再送しない。発話休止・全停止・元会話不明の既存規則に従う |
| 回答 | どの回答でも新しい1回の自発行動を始める。回答本文は既存の回答と同じく目標の入力に入る |
| 取下げ | 本人が取り下げれば、既存の取下げに従う |

## 4. 保存

周の数は目標の進行状態の `cycle` に置く（既存の `remaining`・`parks`・`stalled`・`seen` と同じ場所）。

| フィールド | 意味 |
| --- | --- |
| `thoughts` | 今回の自発行動でモデルを呼んだ思考の回数 |
| `answers` | 始まりの時点で回答済みだった質問の数。増えていれば新しい1回として `thoughts` を0に戻す |
| `reason` | 最後にモデルを呼んだ周の理由（方法の段、なければ振り返りの段）。知らせに添える |

知らせは本人への質問なので、目標は回答まで `needs_user` に留まり、時刻・構成の変化では起きない。別の印は持たない。

## 5. 受入

| 段階 | 合格条件 |
| --- | --- |
| 固定試験 | 4回考えても進まない目標が5回目を呼ばず、知らせを1件だけ出す。回答で次の4回が始まる。答えの決まった周でモデル呼出し0回。検査の版が変わっても上限を使い切った目標は起きない。台帳にトークン数が残る |
| 本家 | 利用者による再起動後、思考プランの実行が1回の自発行動あたり4回以内に収まり、台帳とログにトークン数が出る |

## 6. 実装

| 規則 | 実装 |
| --- | --- |
| 上限・知らせ・数え方 | `goal-thought-budget.ts`（`THOUGHT_LIMIT = 4`、`thoughtCounted`、`ownerNotice`） |
| 1周の判断 | `goal-deliberation.ts` の `deliberateGoal`。回答数が増えていれば新しい1回として `thoughts`・`parks`・`stalled` を0にする。`mustPause` または上限で、モデルを呼ばずに知らせの質問を返す。完了した実行で結論の再利用でなければ1回と数える |
| 失敗した周 | モデルに届いた失敗（`thoughtCounted`）はキューで再試行せず（`classify` が `fail`）、`problem()` で1回と数える。入力の上限超過・先取り・取消は数えず、従来どおり再試行する |
| 保存 | `goal-advance-handler.ts` の settle が、適用・実行先待ち・停止のどれでも `budget` を `cycle` に書く |
| トークン数 | `registered-goals.ts` の目標用推論口に、試行記録から使用量を読む `attemptUsage` を渡す（会話側の `assembly.ts` と同じ読み方） |

| 固定試験（`goal-deliberation.test.ts`） | 内容 |
| --- | --- |
| 4回で止まり、回答で次の4回 | 4回目まではモデルを呼び、5回目はモデル呼出しなしで知らせを返す。回答数が増えると1回目から考える |
| 止まり続けた目標 | 変化なしで2回止まった目標・3周進まなかった目標は、モデル呼出し0回で知らせを返し、最後の理由を添える |
| 数え方 | 出力不整合・推論の時間切れは数え、入力の上限超過・先取りは数えない |
| 検査の版 | 版が同じなら知らせ、上がれば検査へ進む |
