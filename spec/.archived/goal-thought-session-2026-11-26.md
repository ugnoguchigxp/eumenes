# 登録目標の思考を1つのセッションで進める

2026年11月26日。利用者の決定:

- 「sessionid を引き継ぐのは、この thought plan の最初から最後まで継続が基本。設定で独立した物にすることができても良い。input cache を引き継ぐのも前提だが、設定で off にもできる」
- 「前の段の Session を引き継いだり、次のラウンド時に新たな入力を受け付ける想定」
- 「タスクが完了したら達成し、それ以上はするべきではない。やったとしてもレトロスペクティブ1回」

[待機中の思考の連続で進める再設計](../.todo/goal-idle-deliberation-redesign-2026-11-26.md)のうち、思考の1周の作りを置き換える。思考の上限（[思考の上限](goal-thought-budget-2026-11-26.md)）はこのまま使う。実装済み・固定試験済み・実稼働の確認待ち。

## 1. 置き換えた理由

| 0.2.0 までの作り | 問題 |
| --- | --- |
| 本家専用のプラン `goal-thought-plan.json`（`review-judge-plan` の写し）を、手の結果が出るたびに最初から実行した | 利用者が「意味ない」とした、スケジューラーでただループする作りの再現。手を1つ打つたびに一から考え直し、思考が止まらなかった |
| 各段が状態を持たない1回の呼出しだった | 前の段のやり取りを引き継がず、毎回すべての入力（約36,000字）を送り直した |
| 段の system context に本家の事情を書き足した | 段の役割がぼやけた |
| 止まり続けの判定（`seen`・`stalled`・`mustPause`）、同じ方法の禁止（`goal_method_repeated`）、検査の版 | ループを前提にした歯止めで、ループをやめれば要らない |

## 2. 作り

| 項目 | 内容 |
| --- | --- |
| プラン | パッケージ同梱の `goal-pursuit`（[eumenes_thought_plan](../../vendor/thought-plan/manifest.json) 0.3.0）。本家はプランを持たない |
| 1回の自発行動 | 1回のプランの実行（`runId`）＝1つのモデルのセッション。始まりは登録・更新・本人の回答 |
| 最初のラウンド | 前回どこまで何をやったか（`recall`）→ 達成しているか・続けられるか（`judge`）→ 手順と影響の見積もり（`devise`） |
| 手順の実行 | ホストが手順の手を順に実行する。結果が成功なら、モデルを呼ばずに次の手へ進み、その手と観測を `since` に積む |
| 次のラウンド | 手の結果が成功以外（部分・失敗・拒否・検査の不合格）か、手順を使い切っても達成しないとき、同じセッションの次のラウンドに `since` と結果だけを渡す。`reflect` が違いと原因を考え、立て直すなら `devise` |
| 待つ・聞く | `judge`・`reflect` が待つと決めたら待機条件で待つ（`recheck-later` なら時間を置いて見直す）。聞くと決めたら本人に一点を聞く |
| 上限 | セッションは4ラウンドまで（プランの `rounds.max`）。1回の自発行動の思考も4回まで（失敗した思考を含む、`THOUGHT_LIMIT`）。超えたら、モデルを呼ばずに本人に一度だけ知らせる |
| 完了 | 検査が全条件で合格すれば目標を閉じ、それ以上考えない。振り返り（レトロスペクティブ）は1回までとし、結果を読む仕組みがないので今は行わない |

## 3. セッションの渡し方

| 項目 | 内容 |
| --- | --- |
| モデルへの送り方 | 本家の推論口は system と、その後のメッセージを送る。system は全段で同じ文（`SESSION_SYSTEM`）にし、各段の system context はその段の依頼の先頭に置く。前の段は user／assistant のメッセージとして並ぶので、先頭がそろい、入力キャッシュが効く |
| セッションの識別子 | 推論の試行に、エージェント `thought:<実行ID>` として残す |
| 台帳 | 段の行にラウンドを残す。次のラウンドは台帳から実行の状態（`loadRunState`）を読み直して続ける |

## 4. 保存（`state.cycle`）

| フィールド | 意味 |
| --- | --- |
| `runId` | 今回の自発行動のセッション。null なら次の思考は最初のラウンド |
| `current` | 最後に行った手（結果を読む対象） |
| `remaining` | 手順の残り |
| `since` | 前のラウンドから期待どおりに進んだ手と観測 |
| `pending` | 実行先が空くのを待つ手 |
| `parks` | 止まった回数（時間を置いた見直しの間隔） |
| `thoughts`・`answers`・`reason` | 思考の回数、始まりの時点の回答数、最後の理由（[思考の上限](goal-thought-budget-2026-11-26.md)） |

## 5. 固定試験と測定

| 試験（`goal-deliberation.test.ts`） | 内容 |
| --- | --- |
| 1つのセッション | 最初のラウンドの3段が同じ system・同じセッションで、前の段がメッセージとして並ぶ |
| 推論しない経路 | 決めた手の再開、検証の組み立て、手順どおりの次の手でモデル呼出し0回 |
| 次のラウンド | 検査の不合格で同じセッションの次のラウンドになり、`reflect`・`devise` だけが動く。台帳のラウンド数が2になる |
| 待つ・聞く | `recheck-later` で一時停止、聞くなら質問の手 |
| 上限 | 思考4回で知らせ、回答で新しいセッション。セッションのラウンドを使い切ると知らせ |

パッケージ側の測定（gpt-6-luna・effort low、7シナリオ×10回）は70/70。Live2D の目標を、8回の失敗から検査、改修、成功後の推論0回まで1つのセッションで進めるシナリオを含む（[パッケージの設計書 §11.5](https://github.com/ugnoguchigxp/eumenes_thought_plan/blob/main/spec/thought-plan-design-2026-11-26.md)）。

## 6. 外したもの

| 外したもの | 扱い |
| --- | --- |
| `goal-thought-plan.json`、止まり続けの判定、同じ方法の禁止、同じ入力の結論の再利用 | 削除。セッションの中でモデルが前の失敗を見ており、思考の回数は上限で抑える |
| 検査の版（`workspaceCheckRevision`、11月26日に利用者が選んだもの） | 削除。止まり続けの判定を外したので読む所がない。止まった目標は、時間を置いた見直しか本人の回答で再開する |
| 通常作業先での実行の質問を待機に変える扱い、古い質問の解消（`resolvedQuestionRefs`） | 削除。新しいプランは質問の種類と解消を出力しない。作業先の許可が要らないことは能力の説明に書いてある |

## 7. 独立レビューで直したことと、残る制約

| 指摘 | 対処 |
| --- | --- |
| 推論せずに取る手（実行先待ちの手、手順の次の手、上限の知らせ）が、提示の範囲を確かめずに返り、範囲外なら同じ手で止まり続けた | 取る前に提示の範囲を確かめる。範囲外の次の手は「実行できなかった」結果として同じセッションの次のラウンドに渡す。知らせが出せないときは一時停止 |
| 実行されなかった手のあと、前の手の試行を結果として読んだ | 手を取った時点・結果を読んだ時点の最新の試行を `consumed` に残し、それより新しい試行だけを結果にする。新しい試行がなければ「実行できなかった」として渡す。不採用・一時停止では手順を保存しない |
| 回答数の比較が、質問の失効で崩れた | 回答済みの質問の参照で比べる（`answers` は参照の一覧） |
| 回答直後の失敗で、新しい自発行動の始まりが保存されず、上限が効かなかった | 一時停止の保存（`problem()`）でも回答を見て新しい自発行動として数える |
| 手順のない一時停止で、思考を二重に数えた | 一時停止の保存で数えるのは、結論を持たない失敗だけ |
| 割込み・停止・不採用の経路で、考えた回数とセッションが保存されなかった | どの経路でも、考えた回数・セッション・読んだ結果を保存する |

| 残る制約 | 扱い |
| --- | --- |
| 2ラウンド目以降も、能力・検査・証拠は最初のラウンドの入力のまま | 途中で範囲外になった手は、取る前の確かめで「実行できなかった」として次のラウンドに渡る |
| 待機からの再開も1回の思考に数える | 時間を置いた見直しを3回続ければ上限の知らせになる。待つだけで考え続けないための意図どおり |
| モデルの応答が得られずに失敗したラウンドでは、セッションが続かない（次は新しい実行の最初のラウンド） | 正しさには影響しない。失敗も思考に数えるので上限で止まる |
