# 過去の会話の訂正を記憶へ反映する

## 目的と根拠

利用者は、ASRによる「回線／改善」の取り違えを説明して過去の発言を訂正したが、記憶が訂正されなかったと報告した。本人が過去の会話内容を訂正するときは、「記憶を更新して」という言い直しを求めず、記録済みの内容の訂正として既存の受付へ渡す。

既存設計は `docs/memory.md` と `spec/memory-integration-2026-11-05.md`。会話には `memory(operation=request, kind=correct)` が既にあり、stewardの依頼キュー、参照・版・引用の検査、単一writerで保存する。Agencyの会話も同じ経路を使う。新しい分類器や保存経路は追加しない。

現状の会話Factsは記憶の訂正を「渡せます」と説明するだけで、過去の発言やASRの誤認の訂正がその対象であることを明示していない。stewardには、会話エージェントの返答への指摘を本人の好み・制約に変えない指示があるが、指摘された誤りに対応する既存記憶は訂正するという境界が不足している。これらは原因の候補であり、当該runの履歴はAPIへ接続できず未確認。

## 変更範囲と順序

1. 既存の会話FactsとAgencyの会話Factsに、本人の訂正を `memory` へ渡す同じ規則を補足する。
2. 既存の記憶依頼の説明に、過去の発言の訂正も `correct` で受け付けること、対象と訂正内容を渡すことを明記する。
3. stewardの既存指示を補足する。ASRや聞き取りの誤りは元の内容の訂正であり、新しい好み・習慣や恒久的な語句置換規則にしない。該当する長期記憶・短期メモを既存操作で訂正し、requestsの対象はresolveにまとめる。
4. 既存の依頼受付・保存試験を使って、訂正内容と条件の引継ぎ、受付と完了の区別、旧版の置換、無関係な記憶の保持を検証する。

本人による訂正と、質問・仮定・引用・第三者からの指示を区別する。対象や訂正内容が特定できない場合は不足だけを確認し、推測で変更しない。既存の会話履歴を直接書き換えず、DB・API・権限・モデル・ルーターの判断方式・ツール回数制限は変えない。専用の語句判定、正規表現、固定応答は製品へ追加しない。

## 完了条件と検証

- 部分: `./api/domains/dialogue/test/read-tools.test.ts` と `./api/domains/steward/test/requests.test.ts` の既存試験を基準に、訂正受付から保存までの契約を検査する。
- 結合: Agencyのsystem接続、会話の記憶依頼とMemoryの版管理を関連試験で確認する。固定応答の試験と実LLMの意味判断の評価は別に記録する。
- 通し: `bun run verify -- --domain dialogue --domain steward --domain memory`。失敗時は対象外の既存変更との関係を確認し、基準を緩めない。
- 実会話: 起動済みAPIが利用できる場合だけ検証用の会話IDを使う。サーバー起動・停止・再起動は今回の依頼では許可されていないため行わない。稼働反映と実LLMの受入ができなければ未検証として報告する。
- 最後に担当外の差分も含めて点検し、固有の訂正語句に依存した製品処理がないことを確認する。

## 検証結果

変更前の既存試験は19件成功。ASR誤認の訂正を模した合成データの回帰2件を追加し、部分21件、Agency・会話・steward・Memoryを含む結合70件が成功した（21件は70件の内数）。モデルの解釈を固定応答で与え、対象と訂正内容の受付、訂正版の保存、旧版のsuperseded化、無関係な記憶の保持、訂正元の本人発言への出典更新を確認した。これは実LLMが訂正を選ぶことの合格ではない。

生成catalogの整合性、変更した試験の書式・lint、全体型検査（3,356ファイル）、`git diff --check`が成功。`verify`は以前からある `artifacts/pursuit-integration-20261106/` 等のコピー内の試験をinventoryが拾って停止した。検査基準や担当外のファイルは変更していない。記録は `verification-reports/memory-conversation-correction-20261115/`、全体verifyの記録は `verification-reports/runs/2026-11-15T10-32-57-409Z-9a1f2141-8fac-4609-9d45-8a62060d9738/report.json`。

実会話はAPIへ接続できず未実施。サーバー起動・停止・再起動および製品の記憶の直接修正はしていない。再開時は、通常の内容訂正・ASR誤認の訂正で既存のcorrect受付と反映を確認する。対象不明なら確認を行い、単なる質問・引用なら変更しないことも実モデルで確認する。

差分点検では、製品変更は既存4指示資産と生成物だけで、語句判定や新しい判断機構を追加していないことを確認した。診断表示・ルーター・設定・ログなどの並行変更は保持した。context_compileとcompile_evalは各1回。
