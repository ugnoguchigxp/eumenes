## 1. 全体の流れ（実装後）

- 起動時、capabilities は builtin seed の後に `api/domains/capabilities/bundles/*.bundle.json` を、application が渡す `BundleHost`（登録adapter・query・input adapter・projection・domain schema）で検査して登録する。timer bundle は `toolchain:timers.manage@2`（表示名「タイマー（データドリブン）」、`bindingRevisionId: binding:timers.command@1`、`artifactRevisionId: artifact:timers.workspace@1`、`package:timers.manage@1` を pin）と binding・artifact を含む。`toolchainBuiltins` から `timers.manage@1` を削除する。DB上の旧revisionはデータとして残るが、旧版用の固定runtime（`runtime-meta.ts` の `timers.manage`）は旧コードを残さない方針で削除したため、公開ポインタを `@1` へ戻すとタイマーは会話・入口から外れる（停止スイッチとして働く）。切戻しの対象は binding を持つ以前のrevision（例: `@3` 公開後の `@2`）とする。
- 会話: 候補は `catalogInTransaction`（有効catalog ∩ host対応adapter/runtime ∩ 現在の可用性）から得る。bound chain の command 担当は `commandSetInTransaction().binding` の tools と `bound.snapshotInTransaction` を受け、invoke は `bound.parseInvocation` で検査、agent-runtime の汎用 action 経路（route `"action"`）で tool-runtime → application の registry action adapter → `DomainAdapter.invokeInTransaction` に到達する。未知backendのtimer fallbackは削除。clarify は `command_interactions` に質問を保存する。
- UI: Web の共通 Artifact host が `GET /api/toolchain-artifacts/:artifactRevisionId` で登録artifactを得て、Web側のdomain別source adapter（timerは時計・期限再取得・保存済み選択）でsnapshotを作る。書込みactionは `POST /api/toolchain-actions` に送り、tool-runtime の受付台帳が単一writer transactionで受付行・domain実行・receipt参照を保存する。

## 2. 分担と書込み範囲

各担当は自分の範囲外のファイルを変更しない。共有ファイル（`package.json`、`bun.lock`、`scripts/domains.ts`、`api/application/**`、`docs/domains.md`、生成物）は親担当が編集する。`spec/excalidraw-*`、`tests/browser/excalidraw-live.spec.ts`、`spec/verification/excalidraw-*` は他作業の未commit変更なので触れない。git の stash/checkout/reset/commit は禁止。試験は自分の範囲の対象試験だけを実行する（`bun test <file>` または `bun run test:domain -- <name>`）。全体検証は親担当が最後に行う。

### W1 capabilities（`api/domains/capabilities/**`）

1. `repository`: 追加migration `capabilities/0004-bindings`（`after: ["capabilities/0003-toolchain-vectors"]`）で `capability_documents(id TEXT PRIMARY KEY, kind TEXT NOT NULL CHECK(kind IN ('binding','http-binding','artifact','schema')), item_id TEXT NOT NULL, revision INTEGER NOT NULL, digest TEXT NOT NULL, document_json TEXT NOT NULL, bundle_id TEXT NOT NULL, created_at_ms INTEGER NOT NULL, UNIQUE(kind,item_id,revision))`。revision id は `binding:<id>@<n>` / `artifact:<id>@<n>` / `schema:<id>@<n>`（http-bindingも `binding:` 接頭辞）。同IDで別digestは `capability_revision_conflict`。
2. `Definition` に toolchain 専用の任意field `bindingRevisionId?`, `artifactRevisionId?` を追加。既存revisionのJSON/hashは変わらない（未指定fieldはJSONに出ない）。toolchain以外で指定したら `invalid_capability`。指定時の検査: binding が存在し execution=command、binding.tools の toolRevisionId 集合が package の toolRevisionIds の部分集合、各toolの `schemaKey` と binding の `inputSchemaRef` が `builtin:<schemaKey>` で一致、`artifactRevisionId` が binding のものと一致し artifact が存在。
3. `service/json-schema-subset.ts`: 設計書§5.1の有限subset（object/properties/required/additionalProperties:false、string(minLength/maxLength/enum)、number/integer(minimum/maximum/enum)、boolean、array(items/minItems/maxItems)）をZodへ変換。`$ref`、`pattern`、`format`以外の未知キーワード、`oneOf/anyOf/allOf/if/then/not` 等は `unsupported_schema` で拒否し、黙って捨てない。top-levelはobjectのみ。
4. schema provider: `schemaInTransaction(db, ref)` → `builtin:<SchemaKey>` は `validators`、`schema:<id>@<n>` は保存済みsubsetをZod化。`domain:` は host が持つので null。新しい validators キーを追加: `answerText`（`{text: string trim 1..500}`）、`timerDurationAnswer`（`{durationSeconds: int 1..86400}`）、`timerTargetAnswer`（`{timerId: uuid}`）、`timerHms`（UI生入力 `{hours, minutes, seconds}` 各 `string` regex `^\d{1,5}$`）、`emptyInput`（`z.strictObject({})`）。既存キーのschemaは変えない（hash不変）。
5. `service/bundles.ts`: `importBundleInTransaction(db, raw, host, { dryRun })` → `{ issues: BundleIssue[]; registered: string[] }`。dry-run は書込みなしで全issueを列挙。非dry-runでissueがあれば `invalid_capability_bundle` を投げる（呼出し側のtransactionがrollback）。検査: 形式、pins の digest が保存revisionの `definition_hash` と一致、definitions は既存 `registerRevision` 経路（`origin:"builtin"`）で検査、未知参照、循環、binding の adapter/operation/query/input adapter/projection/availability が host に登録済み、operation の `inputSchemaRef` と binding tool の inputSchemaRef 一致、schema が subset、functionName 重複。登録順: schemas → bindings/artifacts → definitions（toolchain登録が公開ポインタ切替）。既存同一digestは冪等。
6. seed: `createCapabilities(store, backends, options?: { bundleHost?: () => BundleHost })`。`seed()` は builtin 後に bundle を登録（bundleHost が無い、または bundle の adapter が host に無い場合は登録しない＝その能力は提供されない。warnログ `capability.bundle_skipped`）。bundle file: `api/domains/capabilities/bundles/timers.bundle.json`（設計書§5.2の例に沿う。pinsのdigestは実際の `package:timers.manage@1` の `definition_hash` を計算して記入）。
7. 読取りAPI（`Capabilities` に追加）: `documentInTransaction(db, revisionId)`（binding/artifact/schema）、`toolchainBindingInTransaction(db, toolchainRevisionId)` → `{ binding: FixedDocument<CommandBindingV1>, artifact: FixedDocument<ArtifactDefinitionV1> } | null`、`artifactsInTransaction(db)` → 有効toolchainが参照するartifact一覧 `{ toolchainId, toolchainRevisionId, artifactRevisionId, title, adapterRef }[]`、`publishToolchainRevisionInTransaction(db, toolchainId, revisionId)`（切戻し用。既存revisionのみ）、`prepareBoundInTransaction(db, owner, packageRevisionId, toolRevisionId, input, expect?)`（packageのschemaKeyではなく対象toolの schemaKey で input を検査した `Prepared`。package が有効revisionでなければ `capability_unavailable`）。`toolchainSetInTransaction` に `binding?`（`FixedDocument<CommandBindingV1>`）を追加。
8. `runtime-meta.ts`: `ToolRuntimeMeta.localAction` を削除、`timer.*` は `{ operation: "local_action" }` のみ。toolchains map から `timers.manage` を削除（bound chain は application が binding から runtime を作る）。`builtinToolchainFunctions` は bundle 内 toolchain の functionName（`timer`）も含める（bundle JSONから読む）。
9. 試験: `api/domains/capabilities/test/bundles.test.ts`（dry-run issue列挙、各拒否、旧revision hash不変、公開切替のatomicity＝途中失敗で旧active保持、切戻し）、`json-schema-subset.test.ts`、既存 `timer-compatibility.test.ts` の更新。

## 4. 実装後の変更（2026-10-14）

- 利用者判断により、タイマー画面の「保存済みタイマーを選ぶ」（`TimerPicker`）と、共通hostのWeb adapterの `chrome` 枠（この部品専用だった）を削除した。再読込み後に既存timerを画面から開き直す手段はなく、会話のreceiptと期限到達の通知から開く。
- これに伴い、自然言語受入の凍結ケース `timer-rediscovery-01` とその専用check（`page-reloaded`・`timer-unchanged`）・fixture（`one-active-timer`）を削除し、lockを更新した。固定ブラウザ試験 `tests/browser/timers.spec.ts` は保存済み選択を使わない形へ書き換えた。
- タイマー固有の部分を汎用層から外した。確認質問の回答schema（所要時間・対象timer選択）はdialogueの固定一覧ではなく binding の `questions` で宣言する（`binding:timers.command@2`）。binding を持つtoolchainでは旧形式の `artifact` 項目を不要（使わない）にした（`toolchain:timers.manage@3`）。@2・binding@1 は残るので、公開を@2へ戻す切戻しも引き続き可能。
