# 音声取得や再生終了報告の単発失敗で読み上げが途切れる不具合

2026-11-28 JST。音声入力に対するWebの句単位再生を修正し、固定入力と標準検証で確認した。

修正前は、2句目の音声取得または1句目の再生終了報告で一時的な通信失敗が発生すると、再生キューが発話全体を取り消した。音声入力から製品のWeb再生処理を通す試験で再現した。

音声取得と再生終了報告は、それぞれ一時的な通信失敗に限り、同じ発話・句の要求を250ms後に一度だけ再試行する。次の句は前の句が終わるまで待つ。終了報告の応答は次の句の再生を止めず、再送によって音声を再生し直さない。明示停止や再生キューの破棄で、通信と再試行の待機を取り消す。

- 音声取得だけ、再生終了報告だけ、同じ発話で両方がそれぞれ一度失敗する条件で、2句を順番どおり一度ずつ再生し、発話全体の取消が発生しないことを確認した。
- 各再試行の待機中に明示停止し、再生中の出力が停止し、未再生の句も再試行も始まらないことを確認した。権限拒否に対する再試行は0件だった。
- サーバーが受理した再生終了報告を再送しても、発話の版や記録が二重に更新されないことを確認した。
- 固定コピーで `bun run verify -- --domain voice-dialogue --domain audio --domain dialogue --domain inference` が合格した。Bun 1082件、Web 199件が合格し、検証前後の入力は一致した。試験では通信と音声出力を制御し、稼働環境や実機器での受入は未実施。
