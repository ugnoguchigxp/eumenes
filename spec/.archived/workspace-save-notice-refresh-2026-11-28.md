# 保存通知が続くと画面の更新が止まる不具合

2026-11-28 JST。修正済み。画面の結合試験と関連領域の標準検証で確認した。

保存通知が来るたびに画面は取得対象を更新し、進行中の取得を取り消していた。先行調査では100ms間隔の通知8件と250msかかる取得を使い、取得9回、取消8回、通知が続く間の完了0回を再現した。

修正前の版でEumenesの画面を描画し、製品のSSE購読、会話取得クライアント、会話表示を通す回帰試験を実行した。試験用HTTP応答で最初の再取得を保留したまま保存通知を送ると、最初の会話取得が中断された。

保存通知は取得先ごとにまとめる。進行中の取得が終わると結果を表示し、取得中に届いた通知があれば、その取得先をもう一度だけ更新する。接続し直して全体の再取得が必要になった場合も同じ処理を使い、接続先の診断など必要時だけ読む情報は再取得せずに古い状態として扱う。画面を閉じた時点で待機中の更新を取り除く。

- 画面の回帰試験で、最初の結果の表示、複数の保存通知をまとめた再取得、再接続後の最新表示、会話取得を待たない他の取得先の更新、画面を閉じた時の取得取消を確認した。関連するWeb試験126件が合格した。
- 固定コピーで `bun run verify -- --domain conversation --domain docling --domain kanban` が合格した。Bun 318件、Web 131件、DesignSystem 3件が合格し、Bun 2件はスキップした。対象外の警告12件は検証レポートに記録した。変更した4ファイルは作業ツリーと固定コピーで一致した。
- 画面の回帰試験では固定のHTTP応答を使った。稼働環境での発生頻度と修正後の動作は未確認。
