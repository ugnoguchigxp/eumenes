# Agenda の目標を本家の会話につなぐ

> **整理判断（2026-11-28）: 今後取り組む。** 一部実施。現行コードに10枠の読取と `agenda-goals` scopeの取扱いがあり、対象scopeを使う固定試験もある。設計・許可・再開など全文書の条件について、この文書に実施結果はなく、後続実装との完全な対応は未確定。 実装済みの部分をやり直す指示ではない。未合意の設計は、着手時に現行方式と照合し必要な合意を得る。

会話で明示された目標を利用者の10枠に登録する。目標の正本は本家の Goals とし、枠、設計、実行許可、作業ID、報告の状態を同じ SQLite writer に保存する。Memory 本体と Memory Host 0.2.0 は同じソースから作った配布物を組み合わせる。

会話から新規登録する目標は、Goals の `profile:owner:agenda-goals` スコープを使う。記憶担当の既存スコープが採用上限30件に達していても、空き枠に登録できる。以前に作った枠付き目標は元の保存先から参照し、同じ登録操作の再送は同じ目標を返す。Memory の参照、設計書、作業IDと報告は従来のプロフィールに紐付ける。

既存の Agenda が会話の空きを判断する。Agency は対象を分析し、共有 Memory の State と期限・条件付きの `agendaItems`、その会話で利用できる調査メモを資料として設計担当に渡す。資料の関連性と条件の解釈はモデルが判断する。ホストはスコープ、出典、版、待機時間、許可、同時実行数を照合する。

設計担当の Markdown を普段の調査メモと同じ文書経路に保存する。会話から閲覧できる本文と委譲に渡す本文を同じ保存参照で照合する。登録目標の委譲は Claude Code モックを通し、受付済みの作業を再起動後に同じIDで照会する。成果物の確認後、既存の会話履歴へ報告IDから決まる同一IDで追加する。

配布物の検査、目標・Memory・許可の部分試験、本家 Agenda の会話と SQLite を使った結合試験の順で確かめる。10枠、設計書の閲覧、待機後の承認、モック受付、隔離環境での再起動、保存済み成果物と報告1件を照合する。

## レビュー指摘の回帰条件

設計担当に渡した全調査メモの出典を保存し、忘却された入力を含む設計書は閲覧と委譲から外す。モックの照会は状態取得に限り、再開時にも目標・設計書・許可・Memory を照合する。設計前の許可は最初の設計書のIDとハッシュに結び付ける。Memory のスナップショットは既存の共有 writer での予約・採用とモックの開始時にも照合する。

目標の判断には通常の Agenda と同じ時計を渡す。会話の目標ツールは返答中に実際に届いた追加発話も、現在の会話に属する利用者発言として照合する。各修正を個別に再現する試験を先に行い、更新した配布物を使って本家の通し試験を再実行する。
