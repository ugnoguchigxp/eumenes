# 会話の感情と桃瀬ひよりのモーション

> **整理判断（2026-11-28）: 今後取り組む。** 一部実施。通常の表示・動作は検証済み、Liveの発話単位の感情適用は上流契約待ち。 実装済みの部分をやり直す指示ではない。未合意の設計は、着手時に現行方式と照合し必要な合意を得る。

2026-11-12。新着の応答に感情絵文字が付いたら、音声の有無にかかわらず桃瀬ひよりが同じ感情を表現する。読み上げは実際の再生に合わせ、停止・割り込みで表情を戻す。

## 会話と読み上げ

- 新着のアシスタント発言に対し、吹き出しと同じ `acceptedEmotion` と保存済み `SpeechDelivery.motion` を使う。メッセージ ID ごとに一度だけ短時間表示する。初回履歴、再取得、古い発言への遅着、再生中に押し出された表示は反応を再開しない。
- 読み上げは、本文との一致を既存処理で検証してから、回答に採用済みの v2 感情があれば表示に再利用し、絵文字と表情を揃える。通常の回答の音声合成には既存の文ごとの判定を使う。発話側が明示的に決めた `host` の感情は、実行に紐づく場合も既存の音声合成の準備へ渡す。採用済みの回答感情がない場合は合成結果の動作を使う。
- 音声の再生開始時に感情と動作を渡し、再生中は音声側を優先する。文の切れ目で同じ身振りを最初から繰り返さない。表示強度に判定確度を流用しない。

## 桃瀬ひより

- SDK 5-r.5 の `Hiyori.model3.json` が参照する公式 `.motion3.json` を同一オリジンから読み込み、同版の `CubismMotionManager` で単発再生する。モデルデータは従来どおりローカル配置とする。
- 公式マニフェストの区分は `Idle` と `TapBody`。各クリップの頭・腕・視線・頬・眉などを確認し、感情ラベルから対応を設定する。近い感情で素材を共有できる。顔プリセット、公式モーションのフェード、待機動作を重ねる。口の開閉には描画の最後に既存の音声解析値を適用する。
- クリップ欠落時も既存の顔プリセットを表示する。動きを減らす設定では表情・モーション・口パクの動きを止める。読み込み中に終了した指示は遡って再生しない。

### 待機姿勢との切り替え（2026-11-17）

- 実モデルでは、「喜び」の同じ時点でも待機の首振りが混ざり、頭の左右の制御値が +3.86 と −3.14 になった。終了後は頭が待機に戻っても両手を上げたポーズが残った。
- Cubism SDK で一つの公式クリップを評価する。再生中はクリップが制御する頭・体・視線にその値を使い、顔にはこれまでのプリセットの強さを反映する。開始・終了・途中切り替えは、直前に表示した姿勢から素材のフェード時間で補間する。自然終了では最後の姿勢から待機へ戻す。
- 腕のパーツ選択はモデルのポーズ定義を待機の基準とし、Cubism Pose でフェードする。実描画で異なる腕の形が透けて見えたため、同じフレームから始まるパーツのフェードを最大0.125秒にする。頭・体の補間には素材のフェード時間を使う。音量による口の開閉と自動瞬きは姿勢を合成してから反映する。
- 同じ発話の次の音声が再生待ちの間は、身振りの指示を保持して発話中フラグを下げる。最終チャンクの終了と既存の取消処理で指示を解除する。
- 部分試験で補間と音声チャンクの指示を確かめ、avatar・conversation・voice-dialogue のドメイン検証を行う。消音ブラウザーの実モデルで、開始時の姿勢、待機の位相による差の解消、自然終了・明示停止・途中切り替え時の連続性、腕の復帰、口パクと瞬きを確認する。

#### 検証結果

- 関連Web試験197件、隔離した作業コピーでの `bun run verify -- --domain avatar`（32件）が成功した。conversation と voice-dialogue は、ドメイン検証にローカルHTTPを起動する試験が含まれるため、Webの固定入力で確認した。
- 消音ブラウザーの `avatar-control.spec.ts` と `avatar-view.spec.ts` は計7件成功した。実モデルの頭・体・視線の8軸は、開始・自然終了・割り込み・途中停止の切り替えフレームで直前の値と一致した。待機の位相を変えても「喜び」の再生中は同じ8軸の値になった。
- 24fpsの描画では、感情モーションの開始・自然終了・途中切り替えで腕パーツが重なるのは各2フレームだった。自然終了・途中停止・動きを減らす設定に変えた後は、待機側の腕だけが表示された。

#### 腕の重なりへの追加調整

短いフェードでも、喜びへ切り替える途中の2フレームで、下ろした腕と上げた腕の両方が描画された。頭・体・視線・顔は引き続き補間し、腕パーツは補間の中ほどで一組ずつ切り替える。表示するパーツは公式クリップと既存のポーズ定義で決め、Cubism Pose の1回の更新で不透明度を確定する。

消音ブラウザーの実モデルで、開始・再生中・自然終了・別の感情への切り替え・途中停止の全フレームに腕が一組だけ描画されることを確認する。切り替え前に取り消した場合と、腕を切り替えた後に取り消した場合に待機へ戻ることも調べる。

追加した回帰試験では、修正前の切り替えで両方の腕の不透明度が約0.78と0.33になり失敗した。修正後は全検証フレームで一組だけが表示された。切り替え前後の停止で待機に戻り、姿勢の補間、瞬きと口パクの試験も通過した。関連Web試験39件、avatarドメイン検証、消音ブラウザー試験7件が成功した。

## GPT Live の実装条件

現行の上流契約では出力 PCM に発話 ID や字幕の時刻と共通の位置情報がなく、出力の取消も通知されない。字幕には区間時刻がある。再生区間へ感情を割り当てるには、上流が同じ発話 ID または同じ時間軸を音声と字幕に付け、取消を通知する必要がある。その契約が利用できる段階で、既存の感情判定を確定した発話区間に非同期で適用する。音声の開始は判定を待たず、発話が変わった後や停止・取消の後に届いた判定を失効させる。[GPT-Live の公式 WebSocket 仕様](https://developers.openai.com/api/docs/guides/voice-websockets?api=live)

## 検証

- 新着発言、初回履歴、再取得、音声優先、終了時の復帰を固定データで確認する。読み上げでは、表情に保存済み判断を再利用し、通常の回答で文単位の音声合成が続くこと、明示された感情は合成にも渡ることを確認する。
- 消音したブラウザーの実モデルで、新着の感情表示から公式モーションが動き、無音のとき口が閉じ、再生時は口パクすることを確認する。モーションがない場合と、動きを減らす設定も試す。`bun run verify -- --domain avatar --domain conversation --domain delivery --domain voice-dialogue` と `tests/browser/avatar-control.spec.ts` を使う。
