2026-11-17 提案。Eumenes の計画的な再起動の前後で、まだ有効な Codex スレッドを再開して `thread.id` の変更を減らす。対象は inference の Codex 接続とバックエンドの終了・起動手順。

11/17 22:55 のバックエンド再起動後、同じ Eumenes 会話の 22:59 の初回 Codex 呼び出しは新規スレッドとなり、入力 19,319 トークンのうちキャッシュ読取は 0 だった。23:01 のスレッド再利用では 30,976 トークンを読み取った。現行設計は起動時と最後の Codex プロセスの終了時に専用ホームを初期化するため、再起動後には新規スレッドが必要になる。[現行の設計と通信捕捉](../.archived/codex-input-cache-structure-2026-11-12.md)

Codex は保存済みスレッドを `thread/resume` に `threadId` を指定して開ける。手元の CLI 0.162.1 が生成する RPC 型で、この指定と `excludeTurns` を確認した。型に `prompt_cache_key` の指定欄はない。リポジトリ内の別の Codex SDK 経路ではプロセスをまたいだ同一 ID の再開を確認済み。既存の inference 経路の送信捕捉では、Codex がスレッド ID をキャッシュキーに使った。[OpenAI Docs](https://learn.chatgpt.com/docs/app-server#start-or-resume-a-thread) · [既存のプロセス間再開の記録](../verification/codex-tasks-2026-10-15/README.md)

## 再開の条件と手順

1. 通常終了の際に、ターンが完了していて続きのツール呼び出しを待っていないスレッドを候補にする。Codex の既存の保存記録と、再開に必要な `threadId`、最初のターン ID、作成・最終利用時刻、接続と入力条件を照合するための指紋を Eumenes 専用のデータ領域に保持する。Codex の保存を確認して正常終了した場合にだけ、次の起動が再開できる状態を確定する。
2. 作成から30分と最終利用から10分の両方の期限を、停止時間を含めて適用する。起動時に再開情報を一度だけ取り込み、期限切れ・破損・前回の異常終了が分かった場合は初期化する。起動後に使われなかった候補は期限到来で破棄する。
3. 最初の該当呼び出しで、同じ認証スコープ・接続先・Web検索設定と、現行のスレッド照合条件（モデル、指示とツール一覧、出力スキーマ、思考量）の一致を確認する。途中で資格情報やアカウントが変わった可能性を除ける場合だけ再開する。`thread/resume` を `excludeTurns: true` で呼び、応答の `thread.id` が保存値と一致することを確認する。
4. 再開後の初回は現行の `reset` と同じく `thread/revert` で先頭に戻し、今回の入力を Eumenes から組み立てて送る。利用量は巻き戻し後の累計から計数する。再開や巻き戻しに失敗した場合は、その候補を破棄して `turn/start` の前に新規スレッドへ切り替える。

忘却時は再開資格を失効させ、専用ホームを削除する既存の処理に復元待ちの記録も含める。起動時の再開情報の取り込みは、通常の要求受付より前に完了させる。忘却と再開が重なった場合は、失効を優先する。追加の運用ログは再開の成否と既知の理由コードを記録する。

この案では、会話本文を含み得る Codex の記録が停止中もディスクに残る。停止中に期限を過ぎた記録は、次の起動時に削除する。同じ ID で再開できた場合も、上流でのキャッシュ読取は先頭トークンの一致、上流の保持期限、ルーティングに依存する。[OpenAI Docs のキャッシュ仕様](https://developers.openai.com/api/docs/guides/prompt-caching#cache-location)

| 段階 | 確認する結果 |
| --- | --- |
| 固定試験 | 接続条件と入力が同じ場合は同じ ID を再開し、巻き戻してから入力を送る。期限切れ、認証・入力条件の変更、取消・忘却、異常終了、再開・巻き戻し失敗の場合は、その記録を使わずに処理する。並行要求に同じ復元候補を二重に渡さない。 |
| 通信捕捉 | 既存の `scripts/codex-wire-capture.ts` の検証を再起動前後に拡張し、スレッド ID、送信された `prompt_cache_key`、巻き戻し後の先頭と利用量の基準を確認する。 |
| domain 検証 | `bun run verify -- --domain inference --domain dialogue` で再開、既存の会話、取消、忘却を確認する。 |
| 実接続 | 許可済みの通常再起動を挟み、同じ検証会話・設定で初回のキャッシュ読取と応答開始時間を確認する。再開の成否と、上流のキャッシュの成否をそれぞれ記録する。 |
