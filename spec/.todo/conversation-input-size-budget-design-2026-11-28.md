# 1回の入力を 2,000 token 以下にする最適化計画

- 日付: 2026-11-28
- 状態: 実装中（2026-11-28 着手、利用者「その方針で構いません。実装開始してください」）。済んだ段と残りは §13。固定試験のみ。実測（再起動後の運用ログ）は未実施
- 目標（利用者の指示）: 1回のモデル要求の入力を平均 2,000 token 以下にする。今は平均 約 11,600
- 数え方: プロバイダーが数える入力 token（キャッシュ読取りを含む）。主会話・背景呼び出し（agency・steward）の両方
- 対象 domain: `inference`（Codex 経路）、`dialogue`（system・履歴・State・ツールの載せ方）、`capabilities`（ツール定義・担当の bundle）、`memory`（常時載せる量）、`web-note`（会話内検索の削除）、agency パッケージ（背景の規則文・メモ系ツールの説明）
- 位置付け: [会話のキャッシュ・圧縮](conversation-cache-compaction-and-history-design-2026-11-22.md) の「大きい入力をキャッシュに乗せる」方針を「入力そのものを小さくする」へ変える。同書の要約・忘却の仕組みは使い続け、閾値と履歴に残す量を変える
