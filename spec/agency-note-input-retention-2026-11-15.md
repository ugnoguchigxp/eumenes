# 調査メモの根拠保持の不具合修正

2026-11-15。生成中の回答が表示されては消え、`memory_stale` になるとの利用者報告を受けた。既存の「一覧から外れただけのメモは忘却ではない」「忘却・取消後の内容は採用しない」という契約を満たす修正とする。モデルの意味判断、回答の採用条件、取消・忘却時の破棄方針は変えない。

## 根拠

- 対象run `c92565ac-99c3-4da6-a92e-8febdcf65c53` は2回生成後に `memory_stale`。保存された入力は `complete:false` で、回答は採用されていない。
- 調査時のmainのメモ30件に、保存対象から外れたメモへの参照が1件あった。これだけでは失敗当時の入力全体を復元できないが、同じ失敗を起こす構造が存在する。
- 固定試験で、親メモを30件の一覧から外し、保存・復元すると `retired` が1→0件になり、元の利用者発言が存在するまま `referencedInput.complete` がtrue→falseになることを再現した。
- `startResearch` は既に元の根拠を `ticket.inputs` と作業台帳の `source_refs_json` に保存し、結果採用時にも有効性を検査している。メモ化時にこの情報を引き継がず、`note:<id>` の参照だけを残すことが欠落点。

## 修正範囲

1. 新しいメモは、既に検査済みの `ticket.inputs` を `inputs` として引き継ぐ。本文の複製や新しい台帳は追加しない。既存JSONの後方互換な追加項目とし、DBスキーマは変えない。
2. メモを根拠として使うときは、この元の根拠に既存の `currentInput` 検査を適用する。親メモが一覧から外れても根拠を失わず、元の発言の撤回や権限変更は引き続き不採用にする。
3. 既存形式のメモは、会話・epoch・scopeを含むroot ID・ticket IDが一致し、取消されず結果取得済みの作業台帳から、同じ根拠を読み出す。これは保存形式の読取り互換処理であり、欠けた根拠を推測しない。対応する記録がないメモは従来の検査のままとする。
4. 依存関係の登録・忘却・メモの入替えも `inputs` を引き継ぐ。根拠が失効したメモは生成中・保存済みいずれの状態でも既存の除去対象とする。
5. 表示コードと再生成の優先順位は変えない。正常に採用された回答は既存の確定履歴に残る。失敗した今回のrunを自動で再実行しない。

## 検証と完了条件

- 変更前に、メモの上限・保存復元で有効な根拠が失われる回帰を確認する。
- 変更後に、メモ入替え・保存復元後も根拠が有効、同じ元発言の忘却後は無効となることを部分試験で確認する。
- 古い形式の読取り互換、他会話・別scope・別epoch・取消済み台帳の拒否を確認する。
- 既存Agencyの保持・忘却・会話の採用・ストリームの取消試験を結合で実行する。
- `verify --domain dialogue --domain memory --domain conversation` と型・静的検査を行い、既存の失敗を区別する。
- 稼働反映が必要な場合は再起動の許可を得る。固定試験とliveの結果を分けて記録する。
