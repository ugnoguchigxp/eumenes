# 会話の感情と桃瀬ひよりのモーション

2026-11-12。新着の応答に感情絵文字が付いたら、音声の有無にかかわらず桃瀬ひよりが同じ感情を表現する。読み上げは実際の再生に合わせ、停止・割り込みで表情を戻す。

## 会話と読み上げ

- 新着のアシスタント発言に対し、吹き出しと同じ `acceptedEmotion` と保存済み `SpeechDelivery.motion` を使う。メッセージ ID ごとに一度だけ短時間表示する。初回履歴、再取得、古い発言への遅着、再生中に押し出された表示は反応を再開しない。
- 読み上げは、本文との一致を既存処理で検証してから、回答に採用済みの v2 感情があれば表示に再利用し、絵文字と表情を揃える。通常の回答の音声合成には既存の文ごとの判定を使う。発話側が明示的に決めた `host` の感情は、実行に紐づく場合も既存の音声合成の準備へ渡す。採用済みの回答感情がない場合は合成結果の動作を使う。
- 音声の再生開始時に感情と動作を渡し、再生中は音声側を優先する。文の切れ目で同じ身振りを最初から繰り返さない。表示強度に判定確度を流用しない。

## 桃瀬ひより

- SDK 5-r.5 の `Hiyori.model3.json` が参照する公式 `.motion3.json` を同一オリジンから読み込み、同版の `CubismMotionManager` で単発再生する。モデルデータは従来どおりローカル配置とする。
- 公式マニフェストの区分は `Idle` と `TapBody`。各クリップの頭・腕・視線・頬・眉などを確認し、感情ラベルから対応を設定する。近い感情で素材を共有できる。顔プリセット、公式モーションのフェード、待機動作を重ねる。口の開閉には描画の最後に既存の音声解析値を適用する。
- クリップ欠落時も既存の顔プリセットを表示する。動きを減らす設定では表情・モーション・口パクの動きを止める。読み込み中に終了した指示は遡って再生しない。

## GPT Live の実装条件

現行の上流契約では出力 PCM に発話 ID や字幕の時刻と共通の位置情報がなく、出力の取消も通知されない。字幕には区間時刻がある。再生区間へ感情を割り当てるには、上流が同じ発話 ID または同じ時間軸を音声と字幕に付け、取消を通知する必要がある。その契約が利用できる段階で、既存の感情判定を確定した発話区間に非同期で適用する。音声の開始は判定を待たず、発話が変わった後や停止・取消の後に届いた判定を失効させる。[GPT-Live の公式 WebSocket 仕様](https://developers.openai.com/api/docs/guides/voice-websockets?api=live)

## 検証

- 新着発言、初回履歴、再取得、音声優先、終了時の復帰を固定データで確認する。読み上げでは、表情に保存済み判断を再利用し、通常の回答で文単位の音声合成が続くこと、明示された感情は合成にも渡ることを確認する。
- 消音したブラウザーの実モデルで、新着の感情表示から公式モーションが動き、無音のとき口が閉じ、再生時は口パクすることを確認する。モーションがない場合と、動きを減らす設定も試す。`bun run verify -- --domain avatar --domain conversation --domain delivery --domain voice-dialogue` と `tests/browser/avatar-control.spec.ts` を使う。
