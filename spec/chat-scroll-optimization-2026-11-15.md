# チャット欄の描画と最新位置への追従

2026-11-15。利用者の依頼は、チャット欄の重さを減らし、普段は最新の会話を表示し、上へスクロールしたときに履歴を読めるようにすること。本書はその依頼を既存の表示部品に適用する作業範囲と完了条件。

## 既存機構と変更範囲

既存の `MessageList` は最新20件を表示し、追加操作で20件ずつ履歴を展開する。確定行とMarkdownの描画はメモ化済み。`LiveMessageList` が本文SSEを購読し、workspaceから独立して更新する。スクロールはworkspaceのrefと下端80px以内の判定で管理している。

- 既存の本文SSE、確定行、20件単位の段階表示を再利用する。履歴の選択と独り言の配置は、関連するデータが変わった時だけ再計算する。入力中に変わらない一覧も再描画しない。
- 初期表示、新着、生成中の本文、画像の遅延読込み、会話欄の大きさの変更では、最新追従中なら下端を維持する。スクロールの読取り・書込みを描画フレーム単位にまとめる。
- 利用者の上方向のスクロールで追従を止める。生成途中も読んでいる範囲の先頭を保つ。下端まで戻るか既存の「最新の発言へ」で追従を再開する。
- 履歴閲覧中に上端へ近づくと、既存の履歴を20件ずつ追加表示する。追加前に見ていた位置を保ち、既存の追加表示ボタンも残す。最新へ戻ったら通常の20件へ戻す。
- スクロールを、入力欄のキーボードフォーカスを奪う操作にはしない。

LLMの指示・利用可能情報・ツールには表示位置を決める責務がない。今回の変更はブラウザーの表示・操作状態の管理に限る。会話内容の意味判断、モデル、API、DB、音声の採用・再生、背景表示の設計は変更しない。新規ライブラリや汎用フレームワークは追加しない。関連設計は [本文ストリーム](conversation-text-stream-design-2026-11-15.md) と [背景表示](background-play-mode-design-2026-10-29.md)。

## 作業順と完了条件

1. 既存差分を記録し、部分試験と現行スクロール処理のブラウザー試験で基準を取る。
2. スクロール処理を既存責務のままhookへ取り出し、寸法変更の監視、利用者による追従停止、フレーム単位の更新を補う。
3. 一覧の計算・描画を抑え、履歴の段階表示と位置保持を繋ぐ。変わった本文・確定通知・失敗表示が消えないことを部分・結合試験で確認する。
4. 消音ブラウザーで初期下端、新着、連続ストリーム、上スクロール中の位置保持、過去ページ追加、最新復帰、遅延高さ変更、画面サイズ変更を確認する。通信差替え方式を使い、サーバーを起動しない。
5. `bun run verify -- --domain conversation --domain dialogue`、workspaceの関連試験、型・静的検査、全体差分点検を行う。既存差分や並行変更により検証できない項目は区別する。検証入力を固定し、検証中に編集しない。

完了は、上記表示契約の回帰試験成功、不要な再計算・再描画の削減を同条件で確認、関連検証と差分点検の終了。fixtureと通常画面のlive受入は別記する。稼働サーバーの操作は含めない。

### 試行途中の修正と測定

- PageUpの移動中に「最新の発言へ」を押すと、遅れたスクロールイベントが追従を再び止めた。明示操作では即座に位置を合わせ、通常の本文更新は引き続きフレームに集約する。
- 最新へ戻る時の履歴縮小と新着の拡大が続くと、遅延したスクロールイベントを上方向の操作と誤認した。前回の寸法との比較を加え、表示サイズによる移動と区別した。
- 履歴の追加位置は、整数の `scrollHeight` の差で補正すると0.75pxずれたため、実際の一覧の高さで計算する。残る0.25pxはDPR 1のChromiumが `scrollTop` を整数へ丸めることによる。独立測定で800.25→800、800.5→801を確認した。試験は曖昧な許容差にせず、要求した補正位置の丸め値と、その丸めによって必然的に残る表示座標をそれぞれ厳密に照合する。新着中の同一行・同一位置の検査も維持した。
- 一度の大きな上スクロールが監視開始前に上端へ達するケースを追加試験で発見した。監視開始時にも現在位置を一度確認して追加表示する。

試験運用の俯瞰評価は、部分・静的検査の3ラウンド後と、ブラウザー修正の3ラウンド後に実施した。前者は成功した部分試験を根拠に結合へ継続、後者は座標差の実装調整を止めて測定へ方針変更した。新たな測定後、全9ブラウザー試験が成功した。

### 入力の固定と差分

稼働中の開発画面と共有部品の出力を混ぜないため、第三者依存への読取りリンクとコピー内のworkspace依存を持つ固定コピーを使用した。製品DB、秘密、設定、運用ログはコピーしていない。各検証中のコピーは編集せず、修正後は次の検証前に同期した。最終の型・domain試験の前後で、7,290ファイルの固定入力と原本のhash一致を確認した。初回verifyは最後の上端監視補正前の版で、後続の個別検査は最終版で実施した。

変更前からあった担当外53ファイルの差分は保存したpatchと一致する。`useWorkspace` に先行して入っていた音声入力の変更も保持した。全体差分、追加ファイル、意味判断を代替する処理の有無を点検した。

詳細ログ・hash・測定結果は `verification-reports/chat-scroll-20261115/`。ブラウザー試験は実際のclient・進捗hook・一覧・スクロールhook・CSSを使用し、通信相手を固定している。通常画面を使う利用者によるlive受入や、マイク・音声の実機器受入とは区別する。稼働サーバーの停止・再起動は行っていない。
