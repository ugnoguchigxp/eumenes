# 時計画面のコンパクト化とストップウォッチ

目的: 左上タイトル、上寄せの時計、右側の縦プリセット、名前欄削除、近接した開始/停止操作により高さを減らす。タイマーとストップウォッチを同じ画面のタブで切り替える。

範囲と再利用: タイマーのAPI・保存receipt・時計補正・取消・通知、DesignSystem/OpenUI・既存Tabsを再利用する。会話担当の指示とtimers.manageのツールは確認済みで、今回変更しない。ストップウォッチの画面操作はホストの独立した計測hookに分け、共有の表示viewへ渡す。意味判断や担当選択を追加しない。

ストップウォッチの契約: 開始、停止、再開、リセット。performance.nowの起点と停止までの累積時間を正本とし、表示tickを積み上げない。内部タブと別のアーティファクトを見ている間も計測が続く。時計タブを閉じる/ページを再読み込みすると破棄する画面内の計測とし、APIや保存DBのないストップウォッチを永続化済みとは扱わない。

依存: 共通dialとコンパクトな表示pane → stopwatch hookと操作port → OpenUI資源/操作への接続 → workspaceで時計セッション保持 → 回帰試験・明暗/狭幅の画像確認 → domain/全体gateと差分点検。

完了条件: 名前入力なしで開始できる。時計・プリセット位置と縦幅を実画面で確認。ストップウォッチの停止中の固定、再開、リセット、タブ切替中の継続、遅延tickの正確さを確認。タイマーの開始/取消/通知に回帰がない。担当外は修正しない。

ベースライン: 前版は設定画面763px・計測画面675pxの画像、ブラウザ8件成功。広範囲の既存未コミット変更があるため保持する。

追加依頼: タイマーの停止後に同じタイマーを再開する。現在は取消しかないため、残り時間を保存するpaused状態とpause/resumeの公開操作を追加する。既存の操作台帳・scheduler・epochによる古いジョブの失効を再利用する。旧migrationを変更せず、保存済みtimer/receipt/通知を保つmigrationを追加する。以前の取消済みタイマーも残りがある場合は明示操作で再開できるようにする。

更新した範囲: UIの停止は一時停止に変更。再開は同じIDを維持し、期限を停止していた分だけ先へ移す。取消APIは独立した廃棄操作として維持し、会話の担当指示・選択処理は変更しない。新しいbackend操作は画面からのみ呼ぶ。

追加完了条件: 停止/再開の冪等性、revision競合、scope外の拒否、元期限を超えて停止した場合と再起動後の残り時間、古い終了jobの拒否、再開予約失敗時のrollback、通知の一意性、旧DB移行を部分試験で確認。ブラウザでは停止 → 固定 → 再読み込み → 同じIDで再開 → カウントダウンを確認する。

現時点: 配置とストップウォッチの部分40件・DS4件、artifact gate、ブラウザ結合2件は成功。設定450px/狭幅約380px。timers gateは並行のSubtitlePreview追加の未buildによる型参照エラー、verify:allは担当外createStepActionsの306行制限で停止。依存buildは再実行して成功。担当外は編集しない。

残作業（実装中の記録）: pause/resume契約とmigration・処理・画面接続 → 部分/移行/API結合 → ブラウザ → 最終gateと結果記録。


最終実装: timer-workspaceのタイトルを左上へ移動し、時計を上げ、右に縦プリセットを配置。名前欄を削除、44pxの操作を時計の直下にまとめた。設定画面は763pxから450px、375pxの画面では約382px。明暗/狭幅でタブの全文と入力が収まる画像を確認した。

停止/再開: UI停止はPOST /api/timers/:id/pause、再開は/resumeへ接続。残りミリ秒を保存し、再開は同じID・startedAtで期限を先へ移す。既存の取消済み表示も残りがあれば再開できる。停止中は古い終了予定を非表示にし、再開と新しいタイマーを隣接表示。pausedを起動後の時計一覧と担当へ渡す既存情報に追加した。新しい会話ツールや担当選択処理は追加しない。

保存互換性: 0001/0002 migrationを変更せず0003を追加。通知子テーブルの内容をtransaction内で保持してから親テーブルを置換し、通知の外部キーと旧receipt digestを維持。旧receiptにはpausedAtが無くてもparseで補完しない。timers.manage@1の入力schema hashはHEADの値と一致したまま維持し、返却情報のみpausedを受け入れる。停止中の時計は終端データの30日削除から除外し、live時計の容量に含める。
