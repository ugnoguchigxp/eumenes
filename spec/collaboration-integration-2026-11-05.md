# 共同作業サブエージェントの本流導入

2026-11-06更新。mainの既存session実行機構へ導入し、許可された再起動後に、保存済み設定でUI制作と新Pipelineの受入を行った。interactは既存の試験運用設定を維持し、隔離したHTTP・実ブラウザーの経路で確認している。本流全体の点数を、独立プロジェクトの80点超評価から転用してはいない。

[承認済み設計](collaboration-followup-design-2026-11-05.md)、[機械可読記録](verification/collaboration-integration-2026-11-06/summary.json)、[継続評価用の入力・期待結果](verification/collaboration-integration-2026-11-06/behavior-cases.json)を参照。

## 接続した機構

- 配布物は `eumenes-collaboration@0.2.0`。source commitは `b407ecd8372b2718f05c23a2340e0483833a0296`、tgzのSHA-256は `52a7041f47cfafa148db132144d82a0f436c19bb9de4aedca6761b1e846fabbd`。共通のaction契約、指示、メッセージ構築を利用し、独立側のexample storeや別の実行ループを持ち込んでいない。
- UI自由制作は既存のsession・文書編集・保存・ArtifactHostを使う。新Pipelineとinteractも同じ担当との継続対話として登録した。
- 下書きの正本、版、実際の入力の出所、確認、receiptを本流が管理する。新Pipelineは、別の利用者発言で確認された現在版を既存の親実行へ直接渡す。確認後にcomposerで作り直さない。
- 質問・結果は既存Queueと保存されたホスト観測で同じ担当へ戻す。待機中に推論slotを保持せず、観測から新しい利用者発言や承認を作らない。ホスト観測の返答はreplyに限定する。
- 所有session・epoch・版・出所の検査、取消、保留、期限、忘却と遅い結果の失効を接続した。寄与した別発言を忘れた場合も、観測本文・下書き・子データを残さない。
- モデル、接続先、認証は本流の保存済み設定を使う。製品コードに検証用モデル名やprofileを固定せず、キー・製品DB・設定を複製していない。

## 再起動後に見つけて修正した点

| 問題 | 修正 |
| --- | --- |
| 複数候補が高得点になると、一つの共同編集も直接実行のPipelineへ変換される | 対話型担当も提示された複数候補の場合、既存のLLM呼び出しで依頼全体と作業段階に合う担当を選ぶ。検索済みの関連担当は構成の参考として渡す。選べる宛先は公開された作業全体の担当に限り、一つ目だけの実行に縮めない |
| 文書操作の余分な引数が拒否されても、どの項目を直せばよいか分からない | 既存の検査結果に余分な項目名・期待する型を含める。引数の値は返さず、契約と再試行回数も維持する |
| 本文修正と題名の関係が伝わりにくい | 既存の文書ツールに、内容と矛盾する題名も同じ編集で整える旨を記載。実際の受入では、初回に指定した題名を追随させるかも追加の利用者発言で明示した |
| 子の操作だけが保存済み経路を引き継がず、LARM固定で45秒後に失敗する | 計画側と同じ既存の `route: subagent` を指定。設定、モデル、制限時間を変更せず、保存済みの経路を引き継ぐ |
| 完了画面に内部の実行JSONが表示される | 同じsession・同じchildについて採用済みのホスト観測の返答を読み、既に生成された短い説明を表示する。別session・別child・未採用の返答を使わず、忘却後は読めない。追加の推論や結果の独自解析は行わない |
| catalog増加で試験用vectorが衝突する | 全登録項目に別の方向を持つ試験データに変更し、順位・件数・類似度・異なる空間の拒否という期待値は維持した |

発言の特定語句・正規表現・辞書で担当を決める処理は追加していない。意味と作業段階はLLM、コードは候補・所有権・入出力契約・状態遷移を担当する。

## 稼働環境での受入

ユーザーの「再起動して、検証していいです」に基づき、対象の作業ディレクトリと起動元を確認して正常終了・再起動した。製品DB・設定・キーの手動コピー、CI検査、別Codexチャットへの送信は行っていない。

### UI自由制作

実モデルの親が担当を選び、「共同制作の確認」という見出しと本文の下書きを作成した。本文だけを変更し、見出し・配置など他の値が変わっていないことを比較した。実ArtifactHostの保存ボタンで保存し、会話から通常担当へ戻った。再起動後も保存作品を取得・表示できた。

通常のWeb画面は読取り確認で描画エラー・HTTPエラーなし。検証会話は通常のmain会話と分け、同じArtifactHost・Web adapterを使う確認画面で1440pxと390pxを確認した。フォームを含まない保存作品への任意のform読取りは、契約どおり `target_not_found` となる。作品の表示失敗とは区別した。

### 新Pipeline

通常の親から共同編集へ入り、30分・60分の初稿を作成した。二つ目を45分に修正した後、次の実際の利用者入力で40分と題名の追随を指定し、さらに別の入力で現在版の実行を確認した。

- 未確認の段階で子実行・タイマーは0件。部分修正後も一つ目と元依頼を保持した。
- 確認した定義と実行側に保持された定義は一致。親のcomposer呼出しは0、子の操作は2件だった。
- 保存済みの接続を通して、実際に1800秒・2400秒のタイマーが作成された。
- 同じsession・同じchildの保存済み完了観測から「30分と40分のタイマーは、どちらも開始済みです。」と返った。送った利用者入力は4件のままで、ホスト観測が利用者発言を増やしていない。
- 検証用の2件だけを取り消し、担当を通常会話へ戻した。既存タイマーには触れていない。

初回に明示した題名も自動で変わると仮定したr7は合格扱いにしていない。r8は、追加の利用者発言で題名の扱いを指定した同じ実セッションの継続確認であり、再生による実行成功ではない。

最後の表示修正は、採用済み説明を返す実APIの結合試験と、保存した実結果・返答の読取り専用再描画で確認した。PC・スマートフォンとも内部JSONの表示、描画エラー、横はみ出しはない。表示確認のための再生成はしていない。

## 検査の範囲と記録

生ログ・snapshot・失敗した試行は、無視対象の `verification-reports/collaboration-integration-2026-11-06/server-acceptance/` に保持している。以前の有料API比較は `verification-reports/collaboration-integration-2026-11-05/` に残す。重複した試験数は合算しない。

最終の関連10領域verifyは14工程すべて成功した。バックエンドは **1578件・12359 assertions**、画面は **125件**、表示部品は **58件** が成功し、失敗は0件。snapshot digestは `388163f41c4803e921351b79c4ff11c7d62d1725f6ce3e18d747f03a0588644b`。実行IDと原ログへの参照は機械可読記録に集約した。途中の全体検査では、既存のrouter書き出し試験1件が5秒上限を超えた。単独では同じ基準で5件すべて成功し、起動・ブラウザー確認を重ねず再検証した。待ち時間や期待値を変更して成功させていない。

## API費用と残る制限

共通の10USD台帳を継続し、失敗・結果不明の予約も含む保守的計上は **6.765742USD**。今回の稼働確認は、製品に保存済みのキーなしCodex接続と既存のChatGPTログインを使用した。有料APIキーによる追加呼出しは0。既存ログイン経由の利用と、APIキーの費用台帳を区別している。

- Lunaの保存済み経路で上記を確認した。以前のClaude比較では、UIの保存状態の説明と二文制約が未合格であり、その結果は変更していない。
- interactの会話pilotは既定の無効状態を維持。隔離したHTTP・実ブラウザー試験では、実行ledger、撮影の明示承認、認証付きWebP取得・削除、質問・回答・忘却を確認した。製品の実外部サイト操作の受入は行っていない。
- 音声の実スピーカー・マイクによる3ターン受入は実施していない。ヘッドレスブラウザーは消音した。
- 基本の導入は共有checkpoint `bc916e27` に含まれる。追加修正と記録は検証完了時点では未commitだった。後続の全差分のcommit/pushは利用者から依頼されており、反映履歴はGitを正本とする。
