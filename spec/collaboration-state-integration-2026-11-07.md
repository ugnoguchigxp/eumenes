# 出所付き条件状態の製品接続

2026年11月7日。承認された共同作業ライブラリ品質改善計画のA・Bを、既存のsession、推論回数、単一writer、出所・忘却経路へ接続する。CIと製品サーバーの操作は行わない。

## 契約と接続

- session bindingの任意の `agent.collaborationState: true` を新revisionで宣言する。旧bindingは従来どおり動作し、本文・schemaを上書きしない。
- 有効な利用者入力では、既存4行動とstateUpdateを同じモデル呼出しで返す。別の推論ループや追加の推論回数は設けない。ホスト観測によるターンは従来どおりreplyだけであり、状態や承認を作らない。
- 状態はdialogueがsession単位で所有する。出所は同じ会話の実利用者messageをhostが解決し、失効・元発言の訂正・session/epoch・作品の版を採用直前に再検査する。モデルが出所台帳を編集しない。
- 状態と操作receiptは同じwriter transactionで保存する。手編集などで作品の版が変われば古い提案を拒否する。観測していない操作の成功を、状態へ推定で確定しない。
- 保存形式のmigrationを追加し、旧sessionは空の状態から初期化する。非対応状態を空で上書きしない。
- 実際の忘却hookから、依存fact・承認の保持文・参照を同じtransactionで除去する。参照台帳の失効は単調に進め、遅い結果で復活しない。
- 状態機能を宣言した有効なsessionは、再起動時に進行中runだけを取り消し、epochを進めて保存済み作業を保持する。期限切れ・closing・旧bindingの終了規則は維持する。未確定操作を再送しない。
- confirmedは操作権限ではない。既存のimpact・権限・承認経路は維持し、条件状態から権限を発行しない。正式なレビュー操作を接続する場合は、認証済みの利用者操作として承認スナップショットを保存し、コアの照合APIで再検証する。モデルの道具には公開しない。

## 検証

固定モデルと実writerで、条件の採用・部分訂正・無関係条件保持、手編集との競合、receiptの原子性、世代変更・遅い結果、再起動・忘却を先に通す。既存の行動・session試験を維持する。実モデル・実UI・製品DB経路の受入は、固定試験と分けて記録する。製品のデータ・設定・秘密を検証用DBへコピーしない。

有効にする新登録版は、collaboration.pipelineとcollaboration.interactのtoolchain/binding revision 2、ui.composeのtoolchain revision 11とui.studio binding revision 5である。元の定義とbindingを保管し、Artifact・文書・実行の既存接点を再利用する。新しい公開toolや独自実行ループは追加しない。
