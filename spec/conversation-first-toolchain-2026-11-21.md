# 会話の解釈から担当の選択まで

2026-11-21。利用者は、会話 LLM が依頼内容を判断し、既存の Toolchain 検索で担当を見つける方針に合意した。通常会話から独立した自動 Router を撤去する。この方針は [Router の選択方式](router-package-integration-2026-11-04.md#2026-11-14-選択方式への切替) の会話前・ツール専用の判断経路を置き換える。

## 会話と委任

1. テキスト・音声の利用者発言を、最近の会話と `State` を持つ既存の会話エージェントで受ける。既存の履歴範囲と忘却規則に従い、範囲内の先頭がユーザー発言ならそのまま渡す。会話か実行依頼かを判断し、依頼なら作業・対象・範囲・指定担当と、元の確認や仕事との関係を読み取る。返事または既存のツール呼び出しで判断を表す。
2. 新規の委任には、単独で通じる依頼を `find_toolchain` に渡す。既存の Toolchain 検索が利用可能な候補を返し、会話エージェントが候補から選ぶ。候補の実行条件、引き渡し、パイプラインの計画・実行には現在の登録と実行機構を使う。
3. 会話エージェントが書いた依頼を保存し、確認文も同じ依頼から作る。既存の確認への回答・取り下げ、仕事への回答・変更・取消は、会話モデルが参照を選び、ホストの既存操作で処理する。訂正で旧案を閉じた後も会話を続ける。元の作業のうち利用者が維持した条件を訂正版に残す。
4. 承認時には同一会話・有効期限・提示済みの確認・対象と版をホストが検査し、保存された依頼を一度だけ引き渡す。既存担当の質問への回答は元の仕事へ渡す。別作業への切替時の未保存作業の破棄は、ホストで提示済みの切替の同意と対象・版を検査する。通知・予約からの権限は既存の受付規則に従う。

Eumenes の会話から Router 用の推論と候補索引の更新を撤去する。保存済み履歴・適用済み migration・過去の比較に使う検証資産は参照できるよう保持する。既存の Toolchain 検索は現在の LARM 設定を使う。埋め込みモデルの比較と切替は別の判断とする。

## 検証条件

- 部分。雑談では作業の検索と委任が発生せず、依頼では会話モデルの検索呼び出しが先行する。既存検索が返した複数の候補からだけ委任できる。
- 結合。担当変更と範囲訂正を含む複数ターンで、元の対象、作業、指定担当が訂正版の確認まで残る。承認前の引き渡しは0件、承認後は1件。古い確認、再承認、純粋な取り下げで新しい仕事が始まらないことも確認する。保留質問、既存作業、パイプラインに既存の実行操作が届くことを確かめる。
- 通し。dialogue と利用側 domain の部分・結合試験を実行し、通常の入力から仕事の受付と回答までを確認する。稼働版の差し替えや実モデルの測定は、既存手順と接続条件に従う。
