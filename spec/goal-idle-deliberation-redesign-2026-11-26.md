# 登録目標を「待機中の思考の連続」で進める再設計

2026年11月26日。**設計案・利用者の合意前・未実装。** 利用者の方針（2026-11-26）:「スケジューラーでただループしているのは意味がない。待機中と判定する → 目標が未達 → 前回どこまで何をやったか調べる → まだ継続できるか判断する → どういう方法なら達成できるか考え、影響度を見積もる → 実行に移す、という思考の連続の結果であるべき」。

対象は[登録目標を離席中も進める設計](registered-goal-autonomy-2026-11-23.md)§3の「次に起こすもの」と、Agency の[判断契約](../../eumenes_agency/spec/goal-decision-contract-2026-11-23.md)の呼び出し単位。[停止の補修](goal-idle-stall-repair-2026-11-26.md)の§3.3〜§3.5（時刻による再確認・停止の通知・連続失敗の歯止め）は本書に統合し、§3.1・§3.2（読取許可の失効・登録検査の提示条件）は本書の前提として残す。

## 1. 現行の動きと問題

| 現行 | 実測（目標1、11月26日 09:28〜09:39） | 問題 |
| --- | --- | --- |
| 結果・資料・構成変化が届くたびに、同じ目標の判断ジョブを即座に積む | 11分で試行8件、完了した7件すべて失敗。進行版は109から239 | 振り返らずに次の一手を出し続ける。費用だけが増える |
| 1回の判断で「次の一手」だけを返す（`decideGoalStep`） | 同じ趣旨の依頼（関連試験を実行して）を言い換えて7回出した | 前回までの経過、続ける意味、方法の比較、影響の見積もりを経ない |
| 受付中の作業は5秒ごとに照会し、そのたびに進行版を上げる | 13:28〜13:30 に進行版が22上がった。状態のJSONは約155KB | 変化のない照会でも大きな行を書き直す |
| 会話の状態と無関係に動く | 利用者が話している間も判断ジョブが動く | 「待機中に考える」になっていない |

## 2. 新しい流れ

目標の判断は「思考の1周」を単位にする。1周は次の6段を順に通る。どの段で止まっても、その時点の結論を記録して終える。

| 段 | 担当 | 入力 | 出力 | LLM |
| --- | --- | --- | --- | --- |
| 1. 待機の判定 | ホスト | 前景推論（会話・ASR・TTS）、会話の生成ジョブ、利用者の最終発話時刻、全停止・自発行動の設定 | 待機中か否か | なし |
| 2. 未達の確認 | ホスト | 目標の版、達成条件の状態、前回の1周以後に届いた事実 | 考える目標と、その理由（新しい事実／見直し時刻の到来／待機に入った直後） | なし |
| 3. 前回の振り返り | Agency | 試行と観測、証拠、質問、許可・能力の変化、前回の1周の記録 | どこまで何をやったか、分かったこと、失敗とその原因、前回から変わったこと | 1回目 |
| 4. 継続の判断 | Agency（同じ呼出し） | 3の結果 | 続ける／待つ（条件と次に見直す時刻）／本人に聞く（一点）／取り下げを提案 | 1回目に含む |
| 5. 方法の考案と影響の見積もり | Agency | 3・4の結果、使える能力・検査・許可 | 方法の候補（最大3件）と影響の見積もり、選んだ方法と理由 | 2回目（「続ける」のときだけ） |
| 6. 実行 | ホスト | 選んだ方法の計画のうち、次の一手 | 既存の受付・検査の経路で1件の試行または検査 | なし |

段5は最初の一手だけでなく、方法を手順の列（最大5手）として返す。各手には「何が観測できれば次へ進むか」を書く。6の結果は記録し、§2.3の条件で次の手へそのまま進むか、振り返りから考え直すかを決める。

### 2.3 考える段を省く条件と、省かない条件

利用者の方針（2026-11-26）:「思考ラウンドは省略できるなら省略したいが、何も考えず実行しようとして失敗し続けるのは愚か」。考える段は、計画どおりに進んでいる間だけ省く。

| 直前の状況 | 次に行うこと | LLM |
| --- | --- | --- |
| 前の手が `succeeded` で、計画に次の手が残り、許可・能力・資料に変化がない | 段6へ直行し、計画の次の手を実行する | なし |
| 検証が全条件で合格 | 完了の確定と報告（既存の経路） | なし |
| 段2で、前回の1周から新しい事実がなく、見直し時刻も来ていない | 何もしない | なし |
| 前の手が `failed`・`partial`・`rejected`、または検証が不合格 | 段3から考え直す。省略しない | あり |
| 許可・能力・資料が変わった（計画の前提が変わった） | 段3から考え直す | あり |
| 計画の手を使い切ったのに条件が未達 | 段3から考え直す | あり |
| 見直し時刻の到来、本人の返答 | 段3から考え直す | あり |
| 初めての1周 | 段3から | あり |

段4で「続ける」になり、残りの計画がまだ有効だと判断した場合（`keepPlan: true`）は段5を省き、計画の次の手から再開する。失敗の直後に、振り返りを通らずに次の手を実行することはない。

### 2.1 1周を始める起点

| 起点 | 条件 |
| --- | --- |
| 待機に入ったとき | 段1が「待機中」に変わった時点で、段2の対象があれば1周を始める |
| 待機中に新しい事実が届いたとき | 試行の結果、資料の保存、構成の変化、本人の返答。待機中でなければ記録だけして、待機に入ったときに扱う |
| 見直し時刻の到来 | 段4で「待つ」を選んだときに決めた時刻。決まった間隔で回すことはしない |

同時に考える目標は1件だけにする。優先度の高い目標から順に1周ずつ行う。

### 2.2 待機の判定

次をすべて満たすとき待機中とする。画面が開いているかどうかは問わない（離席中も進める既存の方針を保つ）。

| 条件 | 使う既存の値 |
| --- | --- |
| 前景推論がない | `inference.foregroundBusy()` |
| 会話の生成・読み上げが進行中でない | `conversationBusy`、読み上げ未了の発話 |
| 利用者の最後の発話から2分以上たっている | 会話の最終発話時刻 |
| 全停止・自発行動の無効化がない | 既存の目標スコープの制御と `agency.actions` の設定 |

利用者が話し始めたら、考え中の1周は打ち切り、その周の記録は「中断」として残す。受付済みの外部作業は止めない（止めるのは既存の全停止だけ）。

## 3. 各段の出力

### 3.1 振り返りと継続の判断（1回目の呼出し）

```json
{
  "review": {
    "done": ["背景色の選択と保存の実装を4回読んだ（background.ts, HiyoriViewControls.tsx）"],
    "learned": ["会話画面の「モデルの表示調整」から色を選び、localStorageに保存する実装がある"],
    "failures": [
      {"approach": "開発監督に関連試験の実行を頼む", "count": 7, "cause": "監督の判断入力が上限を超え、即時に失敗した"}
    ],
    "changedSinceLast": ["読取許可が再発行された（コミット c2fc0969）"]
  },
  "judgment": {
    "decision": "continue",
    "keepPlan": false,
    "reason": "登録済みの固定検査を直接実行する方法をまだ試していない"
  }
}
```

`decision` が `wait` のときは `until`（待つ対象の参照と成立条件）と `recheckAt` を、`ask` のときは質問の一点を、`withdraw` のときは理由を返す。

### 3.2 方法の考案と影響の見積もり（2回目の呼出し）

```json
{
  "candidates": [
    {
      "approach": "登録検査 avatar-background-behavior を実行して条件 root を検証する",
      "steps": [
        {"kind": "verify", "checkRef": "goal-check:…", "criterionId": "root", "proceedWhen": "検査が終了0で合格"}
      ],
      "impact": {"changes": "none", "reversible": true, "inferenceCalls": 0, "minutes": 2, "ifFails": "未達の理由が試験の出力として残る"}
    },
    {
      "approach": "開発監督に設定画面の実装箇所を読ませてから検査する",
      "steps": [
        {"kind": "act", "capabilityRef": "goal-capability:…", "proceedWhen": "設定画面の背景色の実装箇所が証拠として残る"},
        {"kind": "verify", "checkRef": "goal-check:…", "criterionId": "root", "proceedWhen": "検査が終了0で合格"}
      ],
      "impact": {"changes": "none", "reversible": true, "inferenceCalls": 6, "minutes": 10, "ifFails": "同じ入力上限で失敗する可能性が高い"}
    }
  ],
  "chosen": 0,
  "reason": "変更なし・推論0回で、条件を実物の試験で確かめられる"
}
```

### 3.3 ホストが採用する条件

| 規則 | 内容 |
| --- | --- |
| 影響の上限 | `impact.changes` はモデルの申告だが、採否はホストが能力・検査の効果（読取／書込み／外部送信）と許可から決める。許可を超える一手は採用せず、その周を「本人に聞く」に置き換える |
| 同じ方法の繰り返し | 同じ条件に対して同じ方法（能力・検査と依頼の趣旨）が新しい証拠なしに2回失敗していたら、その方法を選んだ周は採用しない。`changedSinceLast` に変化がある場合だけ再び選べる |
| 同じ入力の再思考 | 段3に渡す入力のdigestが前回の1周と同じなら、LLMを呼ばずに前回の結論（待つ・聞く）を維持する |
| 1周の上限 | 1周の推論は最大2回。計画の手は最大5手で、ホストは1手ずつ実行する。各手の採用時に許可・能力の版を照合し直す |
| 省略の条件 | §2.3の表だけで決める。失敗・部分達成・拒否・検証の不合格のあとは、必ず段3から考え直す |
| 連続して進まないとき | 3周続けて達成条件の状態が変わらず、新しい証拠もなければ、段4は「待つ」か「本人に聞く」しか採用しない。見直し時刻は1時間から倍にし、上限24時間 |
| 本人への質問 | 既存の質問配送で元の会話へ1回だけ届ける。同じ目標版・同じ一点は再送しない。発話休止・全停止の既存規則に従う |

## 4. 記録と表示

| 記録 | 内容 | 所有 |
| --- | --- | --- |
| 1周の記録（新設） | 目標ID・版、起点、段ごとの出力、入力digest、採否と理由、開始・終了時刻、中断の有無 | Agency の目標台帳（`goalMigrations` に追加） |
| 試行・証拠・許可・報告 | 既存のまま | 既存 |
| 進行の状態 | 1周の結論（続ける／待つ／聞く／取り下げ提案）と次に見直す時刻を持つ。受付中の照会で変化がなければ進行版を上げない | 既存の進行レコード |

`list_goals` と `GET /api/agency/goals` は、最後の1周の振り返り・判断・選んだ方法と影響の見積もり・次に見直す時刻を返す。利用者が「目標はどうなってる？」と聞けば、この記録で答える。

ログは `agency.goal_cycle` を1周ごとに1行出す。項目は目標ID（`subjectId`）、起点、結論（`decision`）、推論回数、採否の理由コード（`reason`）だけ。本文は出さない。

## 5. 責務の分け方と置き換えるもの

| 変更 | 担当 |
| --- | --- |
| `decideGoalStep`（1回で次の一手）を、振り返りと判断・方法と影響の2つの呼出しに置き換える。旧呼出しとスキーマは削除する | Agency（`eumenes_agency` で実装し、配布物を取り込む） |
| 1周の記録の台帳と migration | Agency |
| 待機の判定、起点の管理、1周の直列実行、§3.3の採用規則、実行の受付 | 本家の `goal-progress.ts` とその周辺 |
| 結果到着時の即時判断ジョブを廃止し、記録と起点の通知だけにする | 本家 |
| 受付中の照会で変化のないときの進行版の更新を止める | 本家と Agency の進行ストア |

置き換えないもの: 永続キュー、許可と範囲の照合、開発監督・Claude の受付と照会、独立検証、完了報告、忘却、全停止。§3.1・§3.2の前提（読取許可がコミットで失効しない、実物を読んだ作業先の登録検査を出す）は同じ変更で実装する。

## 6. 移行

既存の進行レコードは、そのまま最初の1周の入力にする。過去の試行・証拠は「前回までの経過」として振り返りに渡す。旧形式の判断結果（`lastDecision`・`review`）は読み取りだけ行い、新しい記録は1周の記録に書く。実行中の受付は既存の照会で回収する。

## 7. 受入

| 段階 | 合格条件 |
| --- | --- |
| 固定試験 | 会話中は1周が始まらない。待機に入ると1周が1回だけ始まる。前の手が成功し前提が変わらなければ、推論0回で計画の次の手へ進む。失敗のあとは必ず振り返りの推論が1回入り、振り返りなしに次の手が実行されない。同じ入力では推論0回。同じ方法の2回失敗後は同じ方法を採用しない。許可を超える一手は質問に置き換わる。3周進まなければ見直し時刻が倍になる。利用者の発話で考え中の周が中断される |
| 本家 | 利用者の再起動後、会話をしない状態で目標1の1周の記録が残り、振り返り・判断・方法と影響が `list_goals` で読める。11分で同じ趣旨の試行が繰り返されない。登録検査を選べる場合は検査を実行し、合格なら完了報告1件、不合格なら未達の理由と次の見直し時刻が残る |
