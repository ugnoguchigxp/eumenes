# LARMへの逐次音声認識API追加依頼

状態: Eumenes利用者が2026-11-15に依頼書の作成を承認。以下は提案する契約であり、LARMの実装済みAPIではない。別チャットへの送信は行っていない。

## 達成したい動作

発話中から音声を少量ずつ送信し、同じ認識状態を継続して途中結果を返してください。発話終了時は残りの音声だけを確定し、既に送った録音全体を最初から認識し直さない方式を希望します。最終補正で全文再認識が必要なエンジンの場合は、その事実と測定した終了待ち時間を区別して公開してください。

Eumenesが確認した現行catalogは `speech.stt` / `openai.audio-transcriptions.v1`、`POST /v1/audio/transcriptions` です。現行OpenAPIには音声追記・逐次結果の契約がありません。モデル・profileの名前をEumenesに固定せず、保存済み設定とcatalogから選べるようにします。

## 発見・認証

- 提案capability: `speech.stt.stream`、protocol: `larm.audio-transcription-session.v1`。名称はLARMの規約に合わせて確定してください。
- catalogとclaimの両方で接続URL、PCM形式、対応レート、チャンネル、上限、最終補正方式を明示してください。
- Provider credentialはbackendだけが保持します。EumenesのブラウザーにLARMのURL・秘密を直接配布しません。
- claimの取消、設定変更、lease終了でセッションも失効してください。別の接続先へのリダイレクトでcredentialを転送しないことを前提とします。

## 一つの認識セッション

WebSocket等で双方向に接続し、次の操作・イベントを持つ形を希望します。HTTP＋SSEでも同じ契約を満たせれば構いません。

| 操作 | 必要な内容 |
| --- | --- |
| start | callerのrequestId/utteranceId、実行時に得たmodel、言語設定、PCM形式。acceptedでsessionIdとgeneration、上限を返す |
| append | 単調なsequence、開始sample offset、追加分だけのPCM16 LE mono 16 kHz。重複sequenceは同じ内容だけ冪等受理し、欠落・重なり・不一致は拒否 |
| acknowledged | 受理済みの連続sample offset。受理と認識済みの位置を区別し、送信待ちを上限内に抑えられること |
| transcript | 単調なrevision、全文snapshot、暫定/確定の区別、認識済みsample offset。暫定結果は前の暫定結果を置換可能。語句の重複をEumenesの正規表現で消す処理は不要な契約にする |
| commit | 最後のsample offset。重複commitは同じ確定結果。未受理音声を飛ばして成功にしない |
| completed | 最終全文、最終revision、言語、使用量、録音長、認識完了位置。最終結果は一度だけ採用可能 |
| cancel / cancelled | 対象session/generation。キュー待ちと実行中の両方を終了し、遅い結果を抑止。取消がGPU処理の中断か結果破棄のみかを明記 |
| failed | 機械可読コード、再試行可否。途中全文を成功結果に昇格しない |

EumenesのML VADが発話開始・終了を管理するため、Provider側の自動VAD/自動commitを無効化できる必要があります。意味理解、言い直しの解釈、会話への回答は既存の会話LLMが担当します。

## 容量・切断・再試行

- 希望する送信単位は80〜200ms。エンジンの推奨単位と実際の途中結果の頻度を公開してください。エンジンが数秒分を必要とする場合、音声受理の通知と文字生成を区別します。
- Eumenesの発話上限60秒を扱えること。上限、同時実行数、待機数を公開し、超過は早期に拒否してください。マイクを開いているだけで推論枠を占有しない設計を希望します。
- 音声と暫定結果は有界のメモリで扱い、確定・取消・期限切れ時に解放。録音や途中結果をSSD・ログへ常時保存しないでください。
- 切断時の失効時刻、ハートビート間隔、再接続の可否を定義してください。再接続可能なら同一session/generationとacknowledged offsetで再開し、同じ音声の二重認識や二重確定を防ぎます。
- 再接続できない場合は明示失敗を返してください。Eumenesは無断の全録音再送や自動送信を行わず、復旧結果を下書きにします。
- 既存のクラウド経路への切替条件を変える場合は、その仕様を別に示してください。途中結果を表示した後の再試行でも、暫定表示を確定結果として採用しません。

## 計測と受入

会話本文・音声・認証情報を記録せず、requestId/sessionId/generation、音声byte数、sample offset、時刻・時間だけで追えるようにします。受付待ち、準備、最初の音声受理、最初の暫定文字、最終音声受理、確定処理、結果配信を分けてください。

短い返答、60秒の発話、途中の言い直し、複数の無音区間、混雑、取消、切断、重複append/commit、世代変更を検証してください。特に「発話終了→最終結果」の中央値・p95、最初の途中結果までの時間、追加音声あたりの計算量、batch認識との精度比較、取消後の処理枠解放を提示してください。改善目標は終了後の再認識をなくし、終了後に残る待ちを小さく保つことです。未測定の速度を保証値にはしません。

契約と最小の成功・失敗例、fixtureが揃えば、Eumenesは既存の推論記録・権限検証に最小adapterを接続します。旧preview経路は復活させません。
