## 既存機構と変更範囲

文書APIの一覧にある namespace/path/title/sourceId を渡し直す。フォルダは論理パスの各階層を表示用に組み立てる。意味の分類や保存先の選択は新設せず、保存先や保存操作の契約も変えない。名称・パスの部分一致は一覧内の検索として扱う。

DesignSystemのMarkdownWorkspace内に一覧コンポーネントを置く。既存Table系・Tabs系の表示とアクセシビリティを確認して再利用し、フォルダ階層は同じフォルダを親として開けるツリーとする。既存TreeMenuは子を持つ行のクリックが選択ではなく開閉になっており、そのままではフォルダを選べないため、一覧専用の最小の階層表示を同じ部品配下に置く。

既存のAPI、登録済みArtifact action（library/open/select/more）、Plate編集、保存queue、ブラウザー下書きを再利用する。ビュー、フォルダの開閉、検索文字は表示用stateに限定する。保存状態は既存backendの値から表示する。保存済み文書の種類・状態と、作業用文書を区別する。

一覧のnamespaceは実応答から、フォルダは文書のpathから作る。ページの続きがあれば「続きを読み込む」を表示し、未取得の階層を全件取得済みとして見せない。読込み・空一覧・失敗を分け、失敗で編集中の文書を消さない。

保存API、DB schema、認証、文書ID・ETag、履歴、移動、フォルダ作成、削除、共有、更新日時や所有者の取得は対象外。画像内の名称は配置の例で、実データとして表示しない。

## 実装と検証の順序

1. 既存Markdown画面5件とWeb adapter3件を基準として実行。
2. namespace/pathを一覧propsへ渡し、読込み・失敗状態を接続。
3. 一覧・フォルダ・パンくず・検索・作業用文書と編集への導線を実装。
4. 一覧切替時にエディタを保持し、既存の保存・復元処理へ接続。
5. 部分（階層・検索・一覧操作・入力保持）→Web adapter結合→`verify -- --domain markdown --domain artifact`→実画面の順で確認。

canonical verifyが既知の保管コピー内の試験一覧で止まる場合は、除外や期待値を変えず、停止を記録して対象の検査を個別に実行する。サーバー操作は利用者が行う。ViteのHMR/watchは無効なので、最終のbuildと固定試験を済ませてから反映のための再起動を案内する。変更途中に実画面の成功を宣言しない。

## 追加依頼: 保存アイコンとSSD cacheの自動保存

利用者追加指定: 「Doclingに保存」は SaveIconButton。「cacheに保存はボタンを押さなくても保存されていい」「バージョニングとは違う扱い」。cacheは既存のSSD一時ファイル機構を指す、と明確化された。

確認した既存実装: `api/domains/scratch/service/store.ts` の `put` が `<dataDir>/scratch/<bootId>/<uuid>` に書いてrenameする。起動中だけ保持、2 GiB/LRU、貸出中の保護あり。同じIDに違うdigestを渡すと `request_conflict`。現在のAPIは添付を作る入口と読出しであり、編集中の同じ文書を更新する入口は無い。既存の添付や参照中のファイルの内容を上書きすることはできない。

### 追加案（不採用・後述の利用者訂正を優先）

- 既存scratchに「文書ごとの最新cache」を扱う公開操作 `putLatest`/`latest` を加える。論理的な単位は会話ID＋文書IDで、UIに履歴を作らず最新1件だけを返す。
- SSDの書込み・容量・起動停止は既存storeを使う。新しい内容を確定してから最新を差し替え、古いcacheファイルを片付ける。参照中ならその参照の読取りが終わるまで旧ファイルを保持し、添付ファイルや無関係のcacheは変更しない。
- 最新cacheの索引は既存storeと同じくメモリー上だけ。再起動・容量整理で消える。同一内容を重複保存せず、並行する古い自動保存が新しい内容を上書きしないよう内部revisionを比較する。この番号は競合防止用で、利用者の版履歴にはしない。
- Markdown domainは既存の一時入力と作業用文書のrevision検証を使い、本文・Plate編集状態・取込原文・題名を1つのJSONファイルとしてcacheへ渡す。applicationの注入portでscratchにつなぎ、同じ階層のdomainを直接参照しない。
- 利用者の入力停止後に自動保存。日本語変換中、読み込み中、競合中の保存を抑制し、保存中の追記は次の自動保存に残す。Doclingへの書込みはSaveIconButtonからだけ実行する。一時保存の成功はDocling保存済みとは表示しない。
- ブラウザー内の既存下書き保持は維持する。SSD cacheの失敗をDocling成功として扱わず、一時保存失敗を表示する。本文・資格情報をログへ出さない。
- SaveIconButtonは既存SaveButtonの `iconOnly` を使う共通部品として公開する。既存にはSaveButtonはあるがSaveIconButtonという名前の公開部品は無かった。

必要な追加検証: 同一文書の連続自動保存で最新1件、同一内容の重複なし、別文書不変、参照中の旧内容保持、遅い古い保存の不採用、cache失敗時の入力保持、再起動後のcache不存在とDocling不変。固定SSD/結合→画面自動保存の順に確認する。

この項目は共有cacheの更新契約に関わるため、実装前に設計確認を行う。一覧UIの実装は並行して進める。
