# Memoryパッケージの実運用への接続

## 目的・範囲

既存のEumenesのDB、会話、設定、記憶を初期化せず、独立パッケージの公開APIと既存のMemory担当を使う。ユーザーが許可したSeedを未確認候補として追加登録する。既存の同じキーの記憶は上書きしない。

変更はMemoryの出典接続・Seed登録API/CLI、Memory担当へ渡す情報と共通指示、および必要な回帰試験。既存のwriter transaction、忘却ジャーナル、ContextWindow、stewardのprepare→infer→settleを再利用する。新しいチャット用ツール・担当・画面は作らないので、bundle・adapterの新規登録は不要。World側の進行中の変更には触れない。

## 調査で確認した差分

- 配布済みのSQLite契約は版8。現在のパッケージとの差はState一覧のafter/nextCursorの追加で、既存migrationの変更はない。配布物を更新し、ホストは同じ読み取り内で全ページを取得する。
- Eumenesは既にパッケージを利用し、会話の依頼をstewardが計画しホストが適用する。検証用ExamplesやCodex専用クライアントを製品へ移す必要はない。
- Memory担当の入力には、指示で再利用を求めているsemantic keyとoriginがない。これを渡す。共通の信頼境界、述語・条件の保存、分類、訂正の極性を契約に合わせる。
- 出典は会話メッセージに限定されている。外部の未確認Seedを会話の本人発言と偽らないため、ホスト所有の候補資料として保持する最小の接続が必要。

## Seedの契約

JSONLの分類は抽出時のLLM判断として受け取る。コードが本文やscopeの語句から分類・期限・権限を推測しない。

- State候補28件だけをagent_inferredで追加する。本文、適用範囲、利用場面、条件・例外、未確認であることを一緒に渡す。reviewは自動削除期限にしない。
- 手順18件と案件4件は登録対象外として結果に明示する。手順を実行指示へ昇格せず、案件の候補を会話をまたぐ恒久的な個人の好みに変換しない。
- 同じ識別キーがあれば保留する。これは上書き権限の制約であり、意味が同じだという判定ではない。異なるキーでの同義・矛盾は通常のLLMによる整理で扱う。
- 初期登録は1データセットのみ。全件の構造・容量を検査し、State・候補資料・本文を持たない受付記録を単一transactionで確定する。失敗時は全件巻き戻す。同一データの再実行は何もしない。
- 候補資料は元Seedと出典参照を保持し、根拠は候補資料内の文字列を指す。元のCodex会話を読んだり、Eumenesのユーザー発言を作ったりしない。
- 登録後は通常の会話から訂正・停止・忘却する。忘却の既存の派生削除hookで候補本文も消す。古いDBの復元でも既存のblock journalから登録済みのdigestを復元し、同じSeedを再投入して戻さない。

4. 架空のSeedで部分→公開API結合→利用側のdomain検証。既存状態の保持、再実行、訂正、部分忘却、再起動、古いDB復元を確認。
5. 実Seed50件を公開APIで確認し、許可されたState候補だけを既存環境へ追加。既存DBを初期化しない。登録前後の件数・ID・revisionを比較する。
6. 手順・結果・残る制約をdocs/memory.mdと検証記録へ残す。固定試験と実モデル・実環境で観測した範囲を区別する。

### 起動障害への範囲追加

通常起動が `tool:web.lookup@1` の `capability_revision_conflict` で停止した。直前commitで検索schemaの説明が変更されたが、toolの版は1のままで、登録済みschemaHashと衝突していた。強制上書きやDB初期化で隠さず、既存の旧版保全処理と登録経路を再利用した。

旧 `lookup` validatorは直前版の説明も含むschemaに固定し、現行schemaを `lookupV2` として追加。`tool:web.lookup@2` を新設し、作業中のdata-driven Web bundleの検索tool参照とpinだけを新版へ合わせた。実行は既存のWeb操作を使い、新しい意味判断や専用実行器は追加していない。旧版の保存内容を保つ移行・再seed・新packageのvalidateを回帰試験に追加した。元のbundleの担当・Skill・結果契約・実行方針は変更していない。

詳細は[検証記録](verification/memory-package-adoption-2026-10-16/README.md)。
