## 2026-11-07 調整の実施方針

利用者の「調整してもらえますか」と、追加確認への「管理操作の追加を許可する」を受けて進める。通常の変更を会話から扱う設計は維持し、本人用の一括整理・復帰だけを認証済み管理APIへ追加する。削除、外部への送信、接続設定の変更、新しい意味分類器は範囲外。サーバー再起動は、検証後に別途許可を得る。

- Memoryは既存パッケージのdeactivate/reactivateを再利用する。傾向と短期メモも各所有domainの公開操作で利用状態だけを切り替える。本文・出典・未確認状態を保持し、忘却した内容は復帰できない。復帰時も版・保存上限・引用元の有効性を検査する。
- Worldは主張と資料のID・版に結び付く利用除外をWorld domainへ保持する。元の主張を誤りとして撤回せず、資料のwithdrawn（忘却・取下げ）とも分ける。通常の一覧・検索・主張取得・引用採用は同じ除外を確認する。管理照会だけが保管対象を明示して読める。
- 管理APIは対象一覧のpreviewとapplyを分ける。scopeはホスト固定、ID・版を指定し、1件でも見付からない／版が違う場合は全体を拒否する。無指定の全件操作や、語句による選別は設けない。
- 引用が提示されているのに元発言に見付からない場合は保存を拒否し、無関係な元発言全体へ置き換えない。引用未指定の既存の明示依頼経路は維持する。保存内容の意味的な裏付けの判断はLLMが担う。
- 記憶担当には、既存記憶の文を新しい発言へ付け替えないこと、完了した単発作業を長期目標として残さないことを明確化する。Worldは継続案件や再利用する外部事実を中心とし、一般説明・一時的な天気や株価・検証用の数値を自動で積み上げない方針へ調整する。
- 反映対象は前回の棚卸しと現在の一覧を照合して確定する。未確認の本人情報を新規作成しない。個人記憶の具体的な初期候補は本人の確認待ちとし、設定・原会話・成果物・Routerの例示データは変更しない。

完了条件は、部分・結合・影響domainの検証を通し、許可後のAPI反映で対象件数と非対象の本文hashを照合すること。保管後の通常検索で旧情報を返さず、版が変わった対象と忘却済み対象を復帰できず、処理中の古い引用を採用しないことを確認する。live未実施の場合は実装完了と実データ整理完了を分けて報告する。
