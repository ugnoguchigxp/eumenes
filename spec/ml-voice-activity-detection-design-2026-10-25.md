# 学習済みモデルによる発話検出（VAD）設計

- 日付: 2026-10-25
- 状態: 合意済み（2026-10-25、Q1〜Q3は推奨どおり）・P0〜P2 実装・固定試験済み。P3（実機の録音による受入）は未実施
- 対象: `web/src/domains/audio`（録音・発話検出）、`web/src/domains/voice-dialogue/hooks`（設定の受け渡しのみ）
- 関連: `docs/toolchain.md`（音声入力）、`api/domains/larm/service/transcription.ts`（ASR の判定言語による除外）

## 1. 背景

音声入力の発話検出は、フレームの音量（RMS）を雑音レベルの3倍と比べる方式だけで判定している。2026-10-25 に次を確認した。

| 観測 | 根拠 |
| --- | --- |
| 雑音レベルの推定が話し始めの声で持ち上がり、声が検出されなかった（静かな部屋でも雑音の10倍未満の声を2秒話して未検出） | 試算。直近1.5秒の最小値による推定へ修正済み（未commit） |
| キーボード音が発話として検出され、ASR が「seis」などの他言語の短文を作り、会話の入力になった | 20:42:30 の入力「seis」。利用者がキーボード雑音で起きると確認 |
| 自分の回答の再生中に新しい入力が届き、再生中の回答が取り消された | 20:42:08・20:42:30。前者は本人の発話の可能性、後者はキーボード雑音 |

音量だけでは「人の声」と「キーボード・物音」を区別できない。ASR の判定言語による除外（`larm.asr_transcribed`）は後段の安全装置で、日本語として書き起こされた雑音は防げない。

## 2. 目的と対象外

| 目的 | 対象外 |
| --- | --- |
| キーボード音・物音・咳払いを発話として検出しない | ASR モデル自体の精度改善 |
| 小さめの声・短い返事（「はい」「うん」）を検出する | 話者識別（本人以外の声の除外） |
| 話し始めを欠かさずに ASR へ送る | 再生音のエコー除去そのもの（ブラウザの `echoCancellation` に任せる） |
| 既存の区切り（無音1.5秒）・60秒上限・途中表示・送信の流れを変えない | サーバー側の処理の変更 |

## 3. 方式

Silero VAD（v5、MIT ライセンス）の ONNX モデルを、onnxruntime-web（MIT）でブラウザ内で実行する。16kHz の 512 サンプル（32ms）ごとに「人の声である確率」を返す、状態を持つモデルである。

### 3.1 構成

| 部品 | 場所 | 役割 | 変更 |
| --- | --- | --- | --- |
| `recorder.worklet.ts` | AudioWorklet | マイクの 128 サンプル単位をまとめて主スレッドへ送る | 変更なし |
| `controller/index.ts` | 主スレッド | フレームを受け、検出結果で録音の開始・区切り・送信を決める | 判定の呼出しを非同期の検出器へ差し替える。発話と確定する前の音を残す時間を 0.5秒→1.0秒 |
| `controller/speech-detector.ts`（新規） | 主スレッド | フレームを 16kHz・512 サンプルの窓に変換して worker へ送り、確率から発話の開始・終了を判定する | 新規。現行の `VoiceActivityDetector` を置き換える |
| `worklet/vad.worker.ts`（新規） | Web Worker | onnxruntime-web のセッションを持ち、窓ごとに確率を返す。モデルの状態（`state`）を保持し、区切りで初期化する | 新規 |
| `audio/models/silero_vad_v5.onnx`（新規） | 静的資産 | モデル本体（約2MB）。録音 worklet と同じく `?url` で取り込み、同一オリジンから配信する。CDN は使わない | 新規（vendor） |
| onnxruntime-web の wasm | 静的資産 | 推論の実行環境。`?url` で取り込み、同一オリジンから配信（`ort.env.wasm.wasmPaths` で指定） | 依存の追加 |

16kHz への変換は、WAV 化に使っている `createIncrementalEncoder` の低域フィルタ付き再標本化を再利用する（同じ実装を2つ持たない）。

### 3.2 判定規則

| 規則 | 値 | 現行との違い |
| --- | --- | --- |
| 声の窓 | 確率 ≥ 0.5 かつ 窓の RMS ≥ 設定の `threshold`（既定 0.008）で声になり、確率が 0.35 未満になるまで声のまま（音量の下限は声になるときだけ見る。語尾の減衰で途切れないように） | 音量比較を確率に置き換える。設定の `threshold` は「小さすぎる音を無視する下限」として残す |
| 声でない窓 | 確率 < 0.35（0.35〜0.5 は直前の状態を保つ） | 新規（ヒステリシス） |
| 発話の確定 | 声の窓が合計 200ms（途中の 200ms 未満の途切れは許す） | 240ms → 200ms。短い返事を拾うため。無音の区切りも 32ms の窓単位で数える |
| 発話の区切り | 声でない窓が 1.5秒続く（設定 `silenceMs`） | 変更なし |
| 確定前に残す音 | 直近 1.0秒 | 0.5秒 → 1.0秒。話し始めの欠けを防ぐ |
| 雑音レベルの学習 | 廃止 | 確率で判定するため不要。音量の下限は固定の設定値 |
| 60秒上限・途中表示・送信待ち2件で停止 | 変更なし | ― |

### 3.3 自分の回答の再生中（割り込み有効時）

Silero は再生音に混ざった自分の回答の声も「人の声」と判定するため、エコーはこの方式だけでは防げない。再生中だけ、次の条件を加える。

| 規則 | 値 |
| --- | --- |
| 再生中の発話の確定 | 確率 ≥ 0.8 の窓が合計 400ms |
| 再生終了後 | 500ms（既存の出力遅延の余裕 `OUTPUT_TAIL_MS`）は再生中と同じ規則 |

値は受入（§6）で調整する。割り込み無効時の動作（再生中は入力を無視）は変えない。

### 3.4 読み込みと失敗

| 状況 | 動作 |
| --- | --- |
| マイク開始時 | worker とモデルを読み込む。読み込み中は入力準備中（`inputPhase: "starting"`）のまま |
| 読み込み失敗（モデル・wasm の取得失敗、初期化失敗） | 音声入力を開始せず、「音声検出を準備できませんでした」を表示する。音量方式への切替（フォールバック）は行わない（§7 Q1） |
| 実行中の推論失敗 | マイク喪失と同じ扱いで入力を止め、エラーを表示する |

現行の音量方式（`VoiceActivityDetector`）と、その試験は削除する。

## 4. 処理の流れ

```text
マイク → AudioWorklet（2048サンプル）→ 主スレッド
  ├─ 録音バッファ（確定前は直近1.0秒だけ保持）
  └─ 16kHz 変換 → 512サンプルの窓 → worker（Silero）→ 確率
        → 判定（§3.2・§3.3）→ 発話開始: onSpeech / 区切り: WAV を onSegment
```

推論は窓ごとに非同期で返る。判定は確率が返った順に行い、録音バッファはフレーム到着時に積むため、推論の遅れで音は欠けない。推論の遅れが 300ms を超えた場合は計測ログ（`browserTiming`）に記録する。

## 6. 受入

録音の評価資料を `tests/browser/fixtures/vad/` に置き、確率と判定結果を出す評価スクリプトで測る。録音は利用者の実機・実環境で行う。

| 資料 | 内容 | 基準 |
| --- | --- | --- |
| 発話 | 普通の文10件、短い返事10件（「はい」「うん」「OK」など）、小さめの声5件 | 25件中24件以上で検出し、話し始めが欠けない |
| キーボード | 60秒の連続タイピング | 発話の検出 0件 |
| 物音 | 机を叩く・マウス・咳払い 各5回 | 検出 2件以下 |
| エコー | 回答の再生中に話さない 10回（スピーカー出力） | 誤割り込み 0件 |
| 割り込み | 回答の再生中に話しかける 10回 | 9件以上で割り込める |

固定試験（fixture）の結果と、実機の受入結果は分けて記録する。
