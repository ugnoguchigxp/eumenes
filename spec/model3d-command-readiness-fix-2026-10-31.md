# 3Dモデル依頼の命令作成が接続待ちで終了する問題

2026-10-31。利用者の「では改修してください」に基づく不具合修正。

## 目的と範囲

3Dモデル依頼が、生成開始前の命令作成で失敗した。12:45:34のLARM接続は
`pending / waiting`、12:46:18に`local_timeout`。生成ジョブは未作成だった。

既存の[接続再利用設計](larm-connection-cache-design-2026-10-25.md)と
[期限設計](toolchain-time-limits-design-2026-10-18.md)を再利用する。
LLMのprofile・SKILL・入力・操作選択には問題の証拠がないため変更しない。
修正対象は共通の接続入替順序と命令作成の期限のみ。DB・公開API・モデル選択・
優先順位・fallbackは変更せず、発話や3D専用の分岐も追加しない。

## 修正内容と根拠

1. 補助接続を入れ替える際、古い接続の`close`完了を待ってから代替接続を作る。
   現状は`close`を開始した直後に別clientの接続を作れてしまう。
   DELETEを保留したfixtureで、主接続と補助2本に加えて4本目を要求することを再現した。
   接続枠は解放処理中も使用中なので、既存設計の「解放してから使う」順序に戻す。
   当日の接続待ちがこの競合によるものだったと断定する証拠はない。
2. 命令作成の45秒打切りを外し、既存の会話期限から返答用15秒を引いた期限を使う。
   LARMの準備上限は既に60秒であり、45秒は準備中に先に尽きる。
   55秒経過後に命令が返るfixtureで、会話期限内でも操作が始まらず失敗することを再現した。
   会話全体の期限とLARM準備上限は延ばさない。取消・権限失効・期限後の結果は採用しない。

## 完了条件と検証

- 部分: DELETE保留中は代替接続を作らず、解放後は命令が実行される。
  解放待ちの取消で新たな接続を作らない。
- 結合: 55秒相当の準備後でも命令を一度だけ実行し、会話期限を過ぎた命令と
  取消後の命令は操作を開始しない。
- 通し（fixture）: `bun run verify -- --domain larm --domain dialogue --domain model3d`
  と、変更したapplicationの回帰試験および3D adapter・mesh clientの試験を実施する。
- 実LARMでの生成と本番反映はfixtureと区別する。サーバー起動・停止・再起動は
  別途明示許可が必要なため、この改修指示だけでは実施しない。
- 担当外の失敗は記録して修正しない。無関係の作業差分を維持する。

## 結果

- 修正前: 55秒相当の準備後の命令実行と、DELETE保留中の代替接続要求の2件が失敗。
  後者は主接続＋補助2本の解放前に4本目を要求した。既存7件は成功。
- 修正後: 同じ2件が成功。解放待ちの取消、命令作成中の取消、返答用15秒の予約、
  会話期限後の未採用も確認した。新規の回帰は計6件。
- 部分・結合: 3D adapter、mesh client、補助接続、命令待機の21件が成功。
  整形後の命令待機・3D adapter・タイマーツールチェーンの結合23件も成功。
  タイマーを使って共通経路を試し、3Dの語句に依存しないことを確認した。
- domain verify: larm・inference・dialogue・model3d・voice-dialogueを選択しpass。
  backend 1,171件、Web 107件、DesignSystem 21件（計1,299件）、型・境界・整形・lintも成功。
  [検証report](../verification-reports/runs/2026-10-31T03-58-16-661Z-56b647a7-5f48-4dd7-9846-ee777a033a07/report.json)。
- Browser E2Eは省略。変更はbackendの期限と接続管理であり、画面変更はない。
  Web・DesignSystemの固定試験は上記verifyで実施した。
- 上記fixture完了時点では、実LARMの新規生成・稼働サーバーの反映は未実施だった。
  その後の本番確認は下記に分けて記録する。
  当時の一覧502の原因とLARMが待機した理由そのものは確定しておらず、
  本修正で実生成が成功したとは扱わない。
- 製品変更は2ファイルのみ。既存LLMの判断・情報・toolを維持し、専用の意味判断、
  新しい優先順位、fallback、DB変更は追加していない。担当外の差分は編集していない。

俯瞰評価: 再現→修正→取消・期限の確認の3段階で新しい根拠が増え、
残作業がdomain verifyと本番反映に減ったため継続した。検証実行中の製品コード編集や
根拠のない再試行は行わず、正常に進むverifyを中断せず完了を待った。
