# 音声出力の責務の確認

## 要求と完了条件

利用者の指定は「音声を発生させるのはブラウザだけで有るべき。他の方法があっては行けない」。別タブ・最小化を再生停止の条件にする要求ではない。目的は、利用者の Web ブラウザーだけを可聴出力の経路とし、サーバー・CLI・常駐処理・検証用の見えないブラウザーから音を出さないこと。生成、保存、配信、LLM の判断、取得周期、既存の再生条件は変更しない。

今回の完了条件は、既存の出力経路の調査、要求を作業規則へ記録すること、確認済みの責務と未特定の現象を区別して報告すること。現象の原因特定や修正完了を、この文書の完了と混同しない。

## 調査結果

- `bun run logs -- --level warn --limit 15` を確認。音楽 provider 情報の取得失敗はあるが、これは音声の出力元を示す記録ではない。
- 製品の音楽再生は `web/src/domains/music/use-music-runtime.ts` / `use-library-runtime.ts` が認証済み音声を取得し、DesignSystem の `MusicPlayer` の HTMLAudioElement で行う。読み上げなどの AudioContext と設定試聴の Audio も Web 側にある。
- `api/domains/music/service/handlers.ts` は LARM で音声を生成し、応答の音声データを保存する。`service/playback.ts` は曲を検索・選定してプレイリストへ保存する処理で、OS の再生処理ではない。CLI の既存設計もマイク・音声再生を再現しない（`docs/cli-chat.md`）。
- backend / CLI / 起動スクリプトを調べた範囲では、OS の音声再生コマンドやネイティブなスピーカー出力は見つからない。
- 音楽の live 検証用スクリプトは Playwright の headless ブラウザーで再生時間などを検証する。現行の Playwright 実装は headless 時に `--mute-audio` を追加する。対象スクリプトにこの既定引数の除外はない。これはコード上の確認であり、実スピーカーでの受入ではない。
- 利用者から「サーバー停止で音が止まった」と報告を受けた。調査時に別ウインドウの YouTube が再生中だったため一時停止したが、今回の音の原因とは確認できていない。

## 変更と未確認

AGENTS.md に可聴出力の責務を明記。製品の再生条件、ページ非表示時の挙動、接続断時の挙動は変更していない。今回の編集は文書のみのため、製品試験・サーバーの起動・再生による再現は実施していない。既存の別作業の差分は保持する。

音が鳴っていた時点の出力プロセスとブラウザーの再生状態は取得できておらず、今回の現象の原因は未特定。原因確定には再発時の出力プロセス・再生状態の観測が必要。音声再生 API が Web にあることだけを根拠に、不具合が解消したとは報告しない。
