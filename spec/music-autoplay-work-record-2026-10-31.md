# 楽曲完成後の自動再生の修正

## 目的・範囲・完了条件

楽曲作成画面を開いて待っていても完成曲が自動再生されない問題を修正する。既存の生成完了検知と共通プレイヤーを使い、履歴表示による再生、取消済み結果の採用、LLMの意味判断、生成APIやDBの仕様は変更しない。完了条件は、原因の再現、完成後の一度の再生、履歴表示時の停止、曲の切替・画面終了時の停止、関連領域の検証、実画面での再確認。

## 原因と修正

- 修正前の実画面で2秒の検証曲を生成し、完成後のaudioが`paused=true`・`currentTime=0`・`played.length=0`になることを確認した。ブラウザの自動再生拒否を示すボタンの強調はなかった。
- 通常の生成中→完成の固定試験は成功したが、アプリと同じReact StrictModeで登録済み画面を描画すると、自動再生後に停止して回帰試験が失敗した。
- 新しく表示されたプレイヤーのeffectをStrictModeが再実行すると、ホストが開始した再生を`usePlayback`のcleanupが停止していた。既存の再生要求は一度だけなので、再実行後には開始されなかった。
- 共通プレイヤーのcleanupで、DOMから外れた音声は従来どおり直ちに停止する。同じ要素が接続されたままeffectを再実行するときは、microtaskで再接続を確認し、本当の終了だけを停止する。再生要求の再送や新しいフォールバックは追加しない。

## 検証結果

| 段階 | 結果 |
| --- | --- |
| 単体fixture | MusicPlayer 17件成功。StrictModeでの一度の開始、実unmountの停止、曲の切替・音量・再生拒否を確認 |
| 結合fixture | 自動再生hook・登録画面・MusicArtifactの18件成功。修正前にStrictModeの回帰試験が失敗することを確認 |
| domain検証 | `bun run verify -- --domain music --domain artifact --domain tool-runtime` 成功。backend 407件、Web 120件、静的検査・共通部品の型検査とビルドを通過 |
| ブラウザfixture | `bunx playwright test tests/browser/music-autoplay.spec.ts tests/browser/music-volume.spec.ts` の10件成功。開発用ReactのStrictModeで実際の音声再生時間が進むこと、一度だけ再生すること、履歴を開くだけでは再生しないこと、音量の保持を確認。実CSS・ArtifactPanel・登録済み画面とフォーム受付を通し、720×660・720×480・390×844で再生開始時と再生中の下端差2px以内、外側パネルの余分なスクロール範囲なしを確認。試験用サーバーは起動しない |
| 実接続・実画面 | 利用者がサーバーを再起動した後、5秒の「自動再生修正確認」を生成。再生操作なしで、検証曲の終了後に既存の連続再生で次の履歴曲まで進行し、確認時のaudioは`paused=false`・`played.length=1`・`currentTime=1.426667`。確認後に停止 |

実スピーカーの可聴音の聴取は、この記録の検証に含めない。生成した検証曲3件は履歴に残している。サーバーの停止・起動・再起動はエージェントでは実行していない。

## 完成直後にプレイヤーが浮く問題の追加確認

利用者から配置の崩れを指摘され、実画面で15秒の「再生位置確認」を生成した。外側パネルの下端660pxに対し、再生中のプレイヤー下端473.5px、外側パネルのscrollTop185.5pxを観測した。非表示のジャンル見出し（legend）が外側のRendererを位置基準としていたため、スクロール領域の外へはみ出していた。

実CSSの固定試験でも594pxのパネルに1265pxのscrollHeightが生じて2件失敗することを確認。ジャンルのfieldsetへ`position: relative`を設定して非表示見出しの位置基準を内側へ収め、10件のブラウザ試験を通過した。配置・列幅・プレイヤーの高さ・画面定義は変更していない。

追加CSSを含む最終domain検証は成功（`verification-reports/runs/2026-10-31T05-00-23-476Z-c391a703-95fb-49c0-9e77-584cc60be719/report.json`）。そのビルド後にブラウザ10件を再実行して成功した。Webサーバーへの反映後の実画面確認は未実施。ブラウザ再読込だけでは既存Viteプロセスが保持する修正前CSSを使っていたため、反映にはWebサーバーの再起動が必要。利用者は自分で再起動すると回答したため、エージェントは再起動していない。ContextStillはcontext_compile 2回・compile_eval 2回。

最終差分では、意味判定を置き換える語句分岐・個別依頼への専用処理・モデル名の固定・担当外ファイルへの編集を追加していないことを確認した。
