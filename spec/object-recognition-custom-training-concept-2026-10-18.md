# 物体認識の判別機の追加学習（コンセプト）

作成日: 2026-10-18。状態: **コンセプト、着手予定なし**。手作業が2〜3日かかるため保留している。撮影と枠付けを自動化できる見込みが立ったら再検討する。

関連: [対象指定とLLM受け渡しの設計案](object-recognition-targets-and-llm-handoff-design-2026-10-18.md)（名前指定の検出は上流のYOLOE-26で別に検討中）、[物体認識の現行仕様](../docs/object-recognition.md)。

## 1. 目的

現行の判別機（YOLO26n、COCOの80クラス）は、家にある決まった物（例: 鍵・特定のリモコン・薬のケース）を見つけられないことが多い。手元の写真で判別機を追加学習し、これらを確実に検出できるようにする。

追加学習では、学習した物しか見つけられない。毎回違う物を言葉で探す用途は、YOLOE-26の名前指定（関連の設計案）で扱う。両方を併用できる。

## 2. 方針

- OSSは変えない。OpenCVは推論の実行部分で、交換するのは判別機の重みだけ。同じUltralyticsのYOLO26から転移学習する。
- 元の80クラスも残すなら、COCOの一部を混ぜて学習する。新しい物だけでよいなら専用モデルを作り、現行モデルと2つを順に実行する（手間はこちらが少ない）。
- 学習は別の機械で行い、推論は今の上流（object-recognition-host、LARMのPC）のまま。Eumenes側はAPIが変わらない。

## 3. 手順

1. **対象を決める**: 最初は3種類程度で一度通して試し、その後10種類程度へ広げる。
2. **撮影**: 実際のカメラ・置き場所で、角度・距離・明るさ・背景・一部が隠れた状態を変えた動画を撮り、`ffmpeg -vf fps=2` で切り出す。対象なしの写真を0〜10%混ぜる。
3. **枠付け**: X-AnyLabeling・Label Studio・CVATのいずれか。YOLOEやSAMで下書きの枠を自動で付け、人が直す。YOLO形式（`<分類番号> <cx> <cy> <w> <h>`、0〜1に正規化）で出力する。学習用と評価用は8:2。同じ動画から切り出した写真はどちらか一方にまとめる。
4. **学習**: `yolo detect train model=yolo26n.pt data=data.yaml epochs=100 imgsz=640 batch=16 device=0`。写真が少ないときは `freeze=10`。
5. **評価**: `yolo detect val` のmAP50と実写真での見た目で判断する。見逃し・誤検出が出た場面を撮り足し、2〜3回繰り返す。
6. **組み込み**: `best.pt`（または `yolo export format=onnx`）を上流に置いて重みを交換し、分類名の一覧を合わせる。

枚数の目安: 試作は1種類あたり100〜300枚。Ultralyticsの推奨（1種類あたり1,500枚以上・1万個体以上）は最高の精度を出すための目安で、必須ではない。

## 4. 学習に使う機械

| 機械 | 評価 |
| --- | --- |
| Windows 11 + RTX 3080 | **第1候補**。PyTorchの公式CUDA版がそのまま動く。10GBでYOLO26n/sを `batch=16` 前後で学習できる。Windowsでデータ読み込みが止まる場合は `workers=0〜2`、またはWSL2を使う |
| Mac（`device=mps`） | 追加の設定が少なく、試作に向く |
| LARMのPC（Ryzen AI MAX+ 395、gfx1151） | 未確認。PyTorchの標準版は計算時に `HIP error: invalid device function` で落ちる報告があり、AMDのナイトリー版かTheRock版が必要。LLMの処理とGPU・メモリを取り合うため、使っていない時間帯に限る |
| クラウドGPU（Colabなど） | 確実だが写真を外部に送ることになる |

## 6. 自動化の構想（再検討の条件）

手作業の大半は撮影と枠付けで、どちらも自動化しやすい。

- **ターンテーブル＋固定カメラ**: 一番安い。対象を回転台に置き、角度を変えながら自動で撮影する。背景が一定なので、背景差分かSAMで枠をほぼ自動で付けられる。照明や背景を変えて何周か撮れば、写真の種類も増える。
- **ロボットアーム**: カメラを持たせて距離・高さ・角度を変える、または対象を動かして置き場所や隠れ方を変える。アームの位置が分かっているので、写る範囲から枠の下書きを作れる。ターンテーブルより写真の種類を増やせる。
- **Eumenesとの連携**（構想のみ）: 物体認識の画面で撮った写真はbackendに保存済み。学習用にAPIで書き出す機能を作れる（製品DBを直接コピーしない）。撮影から枠の下書き・書き出しまでを1つの流れにすれば、人の作業は枠の確認だけになる。

これらが用意できれば、人の作業は1〜2時間程度まで減る見込み。
