## 2026-11-09 条件付き構造判断

採用元は `eumenes_router` の `4b5e83db6e1e7497fd6e5967008b7faa3ed0ecbb`。通常の `route` は、Aの採点で判定が保留されたときだけ `routeWithFallback` 内でBを開始する。Bの開始時に共通期限を設定し、ターン取消とともに構造判断・埋め込み・採点へ渡す。聞き返しへの返答では、Aが元依頼と返答を合わせて読み、Bは現在の発言原文で回答・取消の対象を照合する。

最上位の判断を既存の実行経路へ渡す。Bが複数依頼を確定した場合は、各担当の版が実行時のプランナーの候補に揃っていることを確認する。元発言と別に順序・担当・依存関係を渡し、プランナーの出力がそれを保持していることを実行前に検査する。未確定の場合は、会話担当がツールを持たずに案内または聞き返しを行う。質問したときは従来の質問記録を使う。

配布物・ルーティング結合試験は57件成功。固定の埋め込み・採点・モデル応答を使い、ウォームアップ後に会話応答へ進むターンを各40回計測した。Aは埋め込み1回・採点1回・構造判断0回、Bは埋め込み1回・採点1回・構造判断1回で、会話モデルはどちらも1回だった。受付から会話の完了までのp95はAが6.77 ms、Bが7.24 ms。実環境の計測は下記に記録した。

### `delegate` の結果

| 起きたこと | 返事に返すもの | 返事 |
| --- | --- | --- |
| 仕事を引き渡した | `{"delegated":true}` | そこで終わる（予告が回の答え。結果は従来どおり後で届く） |
| 既存のものを変える・取り消せない依頼 | `{"confirmation":true}` | そこで終わる（host の確認文を言う。次の回の「はい」は Router の `c<n>.approve`） |
| 欄埋めが聞き返した | `{"asked":true}` | そこで終わる（host が質問を言う。聞き返しの記録には返事が書いた `request` を残し、次の回の Router はそれと利用者の答えを合わせて読む） |
| 即答の担当が答えた | `{"answered":true,"answer":…}` | 続く（返事が自分の言葉で伝える） |
| 即答の担当が答えられなかった | `{"answered":false,"code":…}` | 続く |
| 欄埋めが依頼を読み取れなかった | `{"delegated":false,"code":"request_unclear"}` | 続く |
| この返事で見つけていない担当 | `{"delegated":false,"code":"unknown_toolchain"}` | 続く（先に探す） |
| host が断った | `{"delegated":false,"code":<理由>}` | 続く（できなかったと伝える） |

- 返事が道具の前に話した言葉があるとき、host が道具の中で言う文（確認文・質問）はその後ろに、行を分けて続く（画面・読み上げ・保存される答えで同じ順）。

### 確認待ちの依頼の訂正と取り下げ

2026-11-12の会話では、スケジューラーの対象を取り違えた依頼が確認待ちになった。利用者が訂正しても Router は会話に振り分け、返事が取り下げを告げた時点でも確認が開いたままだった。利用者合意に基づき、会話から新しい依頼を作るときは、最新の訂正と利用者が合意した対象・作業範囲を引き継ぐ。対象が定まらない場合は一度確認する。画面を開くことと作業を委任することは別の操作として扱う。

Router が会話に回したとき、担当に頼める会話エージェントには、その会話で有効な確認の参照と内容を渡す。利用者が対象を特定できる形で拒否したか、内容を訂正して元の依頼を無効にした場合に限り、`decline_confirmation` で既存の取り下げを呼ぶ。この道具を提示した回はホストの呼び出し上限を1回増やす。選択した参照が候補にあり、保存時も同じ会話で有効なことをホストが検査する。返事は保存結果を受けて取り下げを伝える。訂正後の作業は新しい依頼として確認し、既存の承認で引き渡す。

回帰試験では、誤った依頼の確認を保存してから、実際の訂正で取り下げる。訂正後の依頼は確認中の送信が0件、承認後は Claude Code が受け取った依頼が1件で、承認を繰り返しても増えないことを確かめる。

## 2026-11-15 判定に失敗した回の返事

ルーターの判定が得られなければ、元の発話を既存の会話エージェントへ渡す。担当が見つからなかったことだけを知らせ、会話と手元の資料で答えられる場合はそのまま答えるよう指示する。会話履歴などの読取りと、会話エージェント自身のメモの読取りを許可する。承認・取消・保留質問への回答の送信・委譲・新規調査など、操作を伴う依頼は未実施のまま、返答の中で必要なことを確認する。判定失敗の記録と会話の返答は別々に残す。利用者が返答自体を取り消した場合は会話へ渡さない。

固定試験では、構造判定の不正を再現し、元の発話からメモ本文の読取り・返答・音声取得・再生完了報告まで確認する。保留中の仕事や承認があっても状態が変わらず、新しい仕事が開始されないことも確認する。
