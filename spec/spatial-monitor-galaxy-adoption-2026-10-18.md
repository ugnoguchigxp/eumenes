# 監視銀河採用版のSpatialへの置換

2026-10-18。利用者依頼: 採用済みの14モデルをEumenesのSpatialへ適用し、実測状態と実際のアニメーションで稼働させる。

## 範囲と再利用

- 既存のSpatialModel/SpatialItem、単一Scene・RAF・解放、useMonitoringItems、設定の共通下書きと登録adapterを使う。別Canvas、別取得経路、監視規則の変更はしない。
- 監視銀河source commit 2faaae57be7e9d78f74a0b9e2a4cba5538a0c153の14点群・光の評価器・段階拡散・表示式を移植する。点群33,460点、初期350%、上限500%。全景40%原型＋6群、近接60%＋4群。拡散操作でカメラ倍率は変えない。
- モデル内の座標・大きさ・自転は固定し、光の位相だけを進める。公転はSceneの配置として独立。health単色、活動の輝度上乗せ10%以内、速度1.15倍上限。unknown/disconnected/stale/reducedは時間変化を停止。
- backendモデルは既存APIのshape=networkへ接続する互換変換をWebの取得境界に置く。APIと監視判定は変更しない。外部連携/LARM4体は観測値がないのでunconfirmedで表示。言語・画像・楽曲サービス自体の機能やAPIは削除しない。
- 設定は新しいsettings.display revisionを追記し、500%・350%と現在の動きの説明を公開する。旧revisionを変更しない。旧自転の保存項目は互換性のため受理するが、新表示では使わない。既存の保存値はAPI経由でのみ更新する。

## 色表現の拡張（2026-10-18 利用者依頼）

利用者から、位置や公転を速めず、星ごとの色差と緩やかな色の移り変わりを追加する依頼を受けた。本節は上記のhealth単色制約を正常時のパレットへ拡張する。監視の判定・取得周期・LARM計測期限・形状・拡散・公転速度は変更しない。

- 正常時は青・シアン・紫の近接色を固定seed・phase・groupから選ぶ。色用のseedは拡散群から独立して派生させ、毎フレーム乱数を引かない。
- 一部の星だけが6/8/10/12/14秒で別の近接色へ移る往復補間を行う。星ごとに周期と開始位相を分散する。対象割合の初期値はidle 45%、starting 60%、working 70%。割合の境界は連続的に混ぜ、一斉変色や点滅を避ける。
- 取得済みutilization（0–1）に応じ、暖色へ寄る星を最大40%まで増やす。未取得は負荷0の実測として扱わず、負荷由来の暖色を付けない。正常時の利用率・活動による割合変更は8秒で補間する。初回観測は即時の初期表示とする。
- pressure/fault/disconnected/unknownは既存health色を即時に優先する。特にfaultの赤を長い色遷移で隠さない。stale・停止・reduced-motionでは色の時間変化と値の補間を止め、固定した色差と現在供給された値を表示する。
- 調整値（パレット、遷移秒数、対象割合、暖色の上限、境界の混合幅）はoptions.tsの一か所にまとめる。設定UI・保存契約・新しい監視データは追加しない。
- 評価器のRGB出力を既存color bufferへ反映する。粒子ごとの配列やColorオブジェクトを毎フレーム作らず、sampleとRGB配列を再利用する。単一Scene/RAF、輝度上乗せ10%以内を維持する。

検証は、粒子別の色差・連続性・非同期性・暖色割合の増加・未取得の扱い・fault即時反映・停止条件・固定形状と既存拡散を対象とする。backgroundと利用側monitoringを選択したverifyを共有distに影響しない検証用コピーで実行する。既存ローカル表示かサーバー起動不要のブラウザ描画で近景・遠景を確認し、実画面未確認の場合は明記する。サーバーを操作しない。

色表現の実装・固定試験を完了。`bun run verify -- --domain background --domain monitoring`は検証用コピーで成功（API 22試験、Web 34試験、型・境界・生成物・サイズ・format・lint・Design System検査）。RGB sampleとbufferの再利用、長時間clock折返しの連続性も確認した。検証レポートは`verification-reports/spatial-colour-2026-10-18/report.json`。

ブラウザ確認は、当初の読み取り限定を理由に自動承認レビューが一度拒否した後、実装依頼のユーザー発言を受けた同じプレビューの一度の再試行で成功した。サーバーを起動せず、現行Scene・粒子・shaderと全14資産をheadless Chromiumで描画し、近景・遠景の8秒差の画像、取得済み高負荷の暖色、faultの即時赤色を確認。33,460点中14,919点の色比率が8秒で変化し、モデルの自転なし・reduced-motionでの停止・描画エラー0件を確認した。遠景の変化は近景より控えめ。画像と結果は同じレポートフォルダの`wide-t1.png` / `wide-t9.png`、`near-t11.png` / `near-t19.png`、`near-high-load.png`、`near-fault.png`、`preview.json`。これは合成観測値の描画確認であり、稼働アプリの実測状態や実GPUの長時間性能の保証とは扱わない。

1. 資産・registry・評価器と表示shaderを置換。既存の停止/解放/失敗表示を維持。
2. カメラの原型基準フレーム、14体の配置、監視snapshotの互換接続を変更。初期値と保存契約・表示revisionを揃える。
3. 部分試験: 14資産hash/点数、状態別発光/停止/固定座標、10%群、倍率固定、実測snapshot接続。
4. 結合: background/monitoring/settings/capabilitiesと利用側の選択verify、設定版の旧seed互換、Web build。対象外の既存失敗は証拠を報告し修正しない。
5. 通し: 許可されたfixtureサーバーでSpatial browser試験、実稼働API読取と画面確認。サーバーの停止/起動/再起動はAGENTSの明示許可条件に従う。

新しいLLM担当や意味分類、LARM計測API、外部連携のhealth判定、DB直接変更は対象外。既存の未コミット物体認識関連変更には触れない。切戻しは本作業の描画・資産・設定新版を戻し、旧登録版を保持する。
