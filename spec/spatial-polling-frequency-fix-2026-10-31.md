# Spatialの監視頻度と重複ログの修正

2026-10-31。利用者の「起動時のログが多い。ローカルも1分に1度でよい」という依頼に対応する。

## 調査・範囲

- Web監視とLARM監視collectorは既に60秒周期。Webのqueryは鮮度指定がなく、再表示・フォーカス復帰で定期周期外の再取得が起き得る。ローカルのCPU・Memory・SSD計測共有は2秒のみ。
- 稼働ログで同じLARM Connectionのsystem-oneが3分間に793回、すべてstatus=ready/next=readyを記録していた。`awaitReady`の状態差分が関数呼出しごとに初期化され、Providerを再利用する確認でも同じログを出していた。
- 既存の監視query・ホスト計測キャッシュ・準備状態差分ログを修正する。LLMへの指示・意味判断は関係しない。監視取得からProviderを起動する仕組みは追加しない。

## 実施内容と依存関係

1. Webの監視queryに60秒の鮮度を指定し、短時間の表示復帰やフォーカス復帰では保存済み結果を使う。既存の60秒周期と表示外の停止を維持する。
2. ローカル計測の既存共有時間を60秒に変更し、複数画面からの連続要求も同じ計測を使う。
3. LARM準備ログの前回状態を同じLease内で共有する。Providerごとに状態が変わった場合だけ記録し、別接続の初回・失敗・復旧は残す。準備確認・claim・取消・更新の通信や待機間隔は変更しない。
4. 部分試験→監視・LARMと利用側の標準検証→反映後の実画面・ログ確認の順に行う。

## 完了条件・検証

- ホスト計測は同時要求と59,999ms以内の要求で1回、60,000msで次の1回となる。
- Webは起動時と60秒ごとに取得し、60秒以内の再表示・フォーカス・通信復帰では増えない。非表示中は停止する。
- 同じ接続の同じ準備状態を連続取得してもログは1件。状態悪化・復旧・別Provider・別接続を省略しない。
- `bun run verify -- --domain monitoring --domain larm --domain background --domain inference --domain voice-dialogue --domain audio` で対象と利用側を確認する。稼働Webの共有生成物を壊さないよう検証用コピーで実施し、対象ファイルの一致を確認する。
- 新しい根拠のない再試行・担当外修正はしない。失敗は原因と影響を記録する。fixture成功と本番確認を区別する。
- 公開API・DB・接続設定・LLM選択・fallback・音声再生方式・サーバー操作は変更しない。再起動は明示許可なしに行わない。
