# 記憶入力の重複削減：訂正失敗の反復比較

2026-11-08。利用者から、前回の訂正失敗が入力変更に関連するか、同じ入力でも起きるモデルの揺らぎかを反復で切り分け、品質を維持してtokenを減らせる場合だけ採用するよう依頼された。

## 固定する対象

前回保存した旧版・候補のmessages.tsを使う。指示、出力schema、意味判定・引用検査・Memoryの保存処理、モデルの設定、12ケースと期待値は変更しない。製品コードは旧版のまま実験し、合格時だけ保存済み候補を適用する。前回の結果は新試験へ混ぜず、上書きしない。実データ、製品設定、サーバー、他作業の差分は変更しない。

## 回数と実行順

1. 元の訂正ケースを旧版・候補各20回（計40生成）。各対で先後を反転し、ABBAの順序を均衡させる。毎回新しい合成ストアを作り、原入力と初期の記憶は同じにする。実際のparse/apply後の保存結果で判定する。
2. この予定された中間点で、候補の失敗増が片側Fisher正確検定p≤0.025なら不採用として停止。境界でのみ判断し、途中の良い結果で早期採用しない。
3. 中間点で悪化を確定できない場合は、訂正を各60回まで拡張する（追加80生成）。引用不一致と訂正失敗を別に数える。最終点の片側p≤0.025を関連の検出基準とし、2回の判定の合計を0.05以下に抑える。各variantの反復内で出力・成功/失敗が変わるかも記録する。pが大きいことを品質維持の証明としない。
4. 訂正で候補の観測失敗数が旧版より多い、または新しい危険な誤更新があれば不採用。統計的な差を確定できなければ「揺らぎと入力変更の影響を区別する根拠が不足」と報告し、採用しない。
5. 訂正の確認を通過した場合だけ、残る11ケースを旧版・候補各3回（追加66生成）。最大186生成。全ケースを通した品質、引用、保存された内容、token使用量を確認する。

各dispatchを記録してから送信し、原出力・usage・失敗も保持する。通信不明やusage欠落で止め、意味失敗を引き直さない。1呼出し300秒上限。同じ問いの反復は独立した新規問題ではない。温度等を変えず、cache usage、先後、provider識別hashを記録する。統計値は同じ問い・同じ設定に条件づけた診断であり、モデル全体の品質や完全な独立試行を保証しない。

## 採用条件

- 予定した最終比較を完了し、各ケースで候補の観測合格数が旧版以上。引用不一致の頻度も増えない。既存の不合格は不合格として残し、新しい危険な失敗形式を認めない。
- p値だけで採用せず、原出力と実保存結果の意味の点検で品質維持を確認する。観測が一貫しない、または判断が不十分なら現状を維持する。
- 入力・入出力合計・非cache入力の実usageが減る。provider・設定・dataの同一性を照合する。
- 採用する場合は候補を適用し、部分→結合→影響domainのverify、差分点検を通す。サーバー再起動は行わない。

不採用の場合も、実験器の部分試験、保存された出力を既存検査へ通す結合試験、製品コードが旧版のままというhash照合を行い、結果・限界・次の判断を記録する。

手法の根拠：[Fisher正確検定の定義](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.fisher_exact.html)、[NISTの比率の区間推定](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。有意差なしを同等性と読み替えない。

## 結果

同一入力内で旧版・候補ともに出力と成功/失敗が変わり、揺らぎが確認された。固定チェックでは57/60→50/60。片側Fisher p=0.037399で、事前の0.025基準では入力変更の影響を確定できない。ただし、品質維持を示す結果でもない。

実保存された肯定/否定まで別途点検すると、固定チェックが否定の反転を見落としていた。正しい肯定で訂正できたのは旧版50/60、候補36/60。原集計は変更せず、意味点検の別記録に残す。入力48.21%減、入出力合計47.22%減だが採用しない。製品コードは全期間を通して旧版のまま。[結果と限界](verification/steward-input-repeat-2026-11-08/README.md)。
