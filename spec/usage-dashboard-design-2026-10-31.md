# 利用状況アーティファクト：LiveとCodex SDK

状態: 2026-10-31、Asia/Tokyo。利用者が画像生成後の実装を指示し、独立メニューから開くアーティファクトと指定。既存のアーティファクト枠内へ表示し、全画面・アプリのナビゲーションは追加しない。サーバーの起動・停止・再起動と課金を伴う試験は行わない。

## 1. 目的と範囲

設定画面で「Liveの接続にどれだけ使ったか」「Codex SDKのLunaにどれだけ使ったか」を別々に確認できるようにする。時間・トークンの実測値、単価からの概算、取得できない量を区別する。数字を見るためにLLMを呼び出さない。

最初の対象は、期間別の概要、Liveセッションの集計・明細、Codex SDKの接続・モデル別集計、概算に使う単価の管理。既存のAI利用記録から必要な項目を再利用し、同じ記録をブラウザ側で二重集計しない。

この計画に、自動停止、利用上限の強制、モデルの自動切替、APIキーの再登録、OpenAI全体の請求情報や他アプリのCodex履歴の収集は含めない。既存のLLMへの指示・担当選択・実行経路は変えない。集計は保存済みの数値と識別子に対する処理であり、意味分類を新設する必要はない。

## 3. 外部仕様から決まる表示

### Live

- 料金の基礎はAPIの利用秒数。発話・無音・backendの作業待ちを含む。マイクOFFは接続終了ではない。[公式の課金対象](https://developers.openai.com/api/docs/guides/voice-latency-cost#voice-session-costs)
- session.usage.updatedは累計値。12秒→15秒なら合計15秒で、27秒ではない。終了時はsession.closedの有効なusage.secondsを最終値として保存する。[公式の利用量・終了仕様](https://developers.openai.com/api/docs/guides/live-conversations#usage-and-graceful-close)
- `session.closed`なしの切断・再起動では、最後に受信した秒数を残して「最終量未確認」とする。ゼロ円・利用なしにはしない。ローカルの接続経過時間を出す場合は別の推定値とする。
- 音声時間と、委任先のCodex等のトークンは別の消費。Live料金にbackendの消費が含まれる表示にしない。

### Codex SDK

- 入力総数、入力中のキャッシュ読取、出力総数を分ける。推論出力が得られた場合は出力の内訳とし、出力へ再加算しない。
- app-serverではthread/tokenUsage/updated、turn/completed、model/rerouted等を区別できる。実行モデルの変更が通知された場合は、要求したモデルと実行されたモデルを混同しない。[公式イベント](https://learn.chatgpt.com/docs/app-server#turn-events)
- lastを常にturn全体として扱わない。P0で導入済みCLIのイベント契約を確認し、累計total・turn境界・複数通知から呼出しの消費を一度だけ計数する。スレッド再開では既存累計を今回分に含めない。仕様が不明な場合は「受信分・完全性未確認」とする。
- APIキーのAPI料金と、Codexのクレジット・契約内利用を分ける。トークン量から契約残量や追加請求額を断定しない。[公式の課金区分・クレジット単価](https://learn.chatgpt.com/docs/pricing#token-rates)

**Lunaの個別集計:** 「Codex SDK」内で、保存設定の現在のモデルを初期選択し、その完全なモデル識別子で絞る。利用者がLunaを選べば、そのモデルだけのカード・日別推移・明細を表示する。モデル名に特定の文字を含むかで分類せず、別モデルへ変更された期間もモデル別に残す。接続名の変更・削除があっても過去の表示は実行時の値を使う。

Live設定にはこの画面のLiveタブへのリンクを置く。既存の「記録 / AIの利用」は維持し、新画面の明細から既存の実行情報を参照できるようにする。

## 5. 金額と集計のルール

1. **取得できた利用量と概算費用を別に表示する。** APIが最終usageを返したことは、請求額の確定を意味しない。単価換算は常に「概算」。請求書との完全一致はこの画面の保証にしない。
2. **利用量が不明ならnullと件数。** 空欄や0で埋めず「利用量未取得」「キャッシュ量未取得」「単価未設定」を区別する。既知の小計と欠測件数を併記し、不完全な小計を「総費用」と表示しない。
3. **課金対象になり得る失敗も含める。** accepted=1の回答だけに限定しない。失敗・取消・再試行・結果の不採用でも、受信済みの消費は残す。同じ送信の再表示・通知再送は増やさず、実際の別attemptは別に数える。
4. **試用も初期状態で含める。** Liveの音声試用とサービス試験も課金され得る。識別できる通常・試用・検証を絞り込めるが、不明な過去記録を発言内容やIDの見た目で推定しない。既存usageのprobe除外を集計へ無条件に流用せず、保存済みの実通信も対象とする。
5. **モデル・接続・課金区分は実行時の値。** 設定変更後のモデル名や単価で過去の実行を黙って付け替えない。モデル不明の過去分は「不明」に残す。
6. **通貨を混ぜない。** Liveの概算USDとCodexのtokensを並べる。API-key課金と確認できるCodex消費ならUSD概算を別枠で出す。Codex契約・課金単位が不明ならtokensのみを出し、USD・credit・残量を作らない。
7. **単価のある範囲だけ計算する。** Liveは秒数×秒単価（表示単価が分なら60で換算）。Codexのtoken単価換算は、Providerの入力にキャッシュが含まれる契約を確認して通常入力・キャッシュ・出力を分ける。キャッシュや推論tokenを重複加算しない。欠けた内訳が価格に必要なら金額も不明とする。
8. **金額は内部で丸めず、表示時だけ丸める。** 保存・計算には単位の明確な整数の利用量と固定小数精度の単価を使う。USD合計を作る場合も、報告金額と単価換算の概算を分け、二重加算しない。
9. **集計は全保存対象に適用する。** 現在のページや直近100件の合計ではない。期間フィルターは半開区間としてbackendで検証し、全カード・日別・明細を同じ条件で読む。

期間の初期ルールは、セッション・attemptの**開始日時基準**、Asia/Tokyo。日付をまたぐLiveは開始日の行へまとめ、画面に「開始日で集計」と表示する。これは月次請求の利用日別配分とは異なる。請求期間に厳密な秒数按分が必要になった場合は、途中のusage観測と時刻の対応を使う別段階とし、推定配分を実測と呼ばない。接続中の現在値は期間集計と分けて表示し、期間外ならその旨を示す。

## 6. 収集・保存の設計

### Liveの所有domainで補完するもの

- 開始時のモデル識別子、接続ID・表示名・世代、通常/試用、開始時刻。現在の設定を後から参照して履歴を埋めない。
- 最後にAPIから受けた累計秒数と観測時刻、最終秒数、終了時刻、終了理由、計測品質。途中値・最終値・ローカル経過時間を別の項目にする。
- usageイベントはセッションに対応付けて検証し、重複・順序逆転・不正値・別セッションの通知を採用しない。終了値に矛盾がある場合も黙って合計せず診断可能にする。
- 切断・再起動・保存失敗で最後の観測量を消さない。終了の最終量がない状態を明示する。試用字幕の削除と、課金計数の保持を分ける。

### inference/Codexの所有domainで補完するもの

- 実通信が使うapp-serverイベントの入出力・キャッシュ・推論内訳と、モデル変更、thread/turnを正規化する。型にあるが受信されない値は未取得とする。
- イベント重複で同じusageを加算しない。スレッド累計を毎turn加算しない。1turn内の複数呼出しを最後の1件だけで上書きしない。
- usage受信後に失敗・取消になっても、取得済みの計数をattemptに残す。権限失効後の回答を採用しない規則は維持し、実際に行われた通信の計数だけは残す。
- 接続ID・実行時の表示名・接続種別・モデル・課金区分・session_role・task_idなどを公開読み取りへ追加する。providerの生応答、認証情報、会話本文は集計に保存しない。
- Liveに対応付くrunは既存live_voice_runs、子の制御要求は親参照を使う。対応がない独立作業は「起点不明」とし、時間の近さでLive起因と推定しない。Codex単独集計には含める。

### 過去データ

有効な秒数を持つ保存済みLive usageと、保存済みinferenceの数値は利用する。旧Liveで未保存のモデル・終了日時・途中量、旧Codexで欠けたキャッシュ・契約種別は復元できると約束しない。後付け推定で「確定済み」へ昇格しない。画面には計測改善の導入日と、過去分の欠測が分かる表示を置く。

利用台帳の保持期間や会話削除との関係は実装前に既存の削除契約を確認する。会話やAPIキーの削除を、過去に消費した利用量のゼロ化や、消費記録の無期限保持の口実にしない。数値記録だけを扱う保持・削除方針を明記し、集計対象期間外は「記録保持範囲外」とする。

## 7. 責務と既存機構の再利用

Liveとinferenceがそれぞれの利用事実を保存し、各domainの公開読み取りで期間・モデル等の集計素材を返す。画面やCLIからDBを開かない。

集計と単価換算は、両domainより上位の小さいusage domainに置く案とする。Live/inferenceを直接互いに参照させず、公開操作をapplicationで接続する。このdomainは期間・単位・単価履歴・集計契約だけを持ち、二重の会話台帳や汎用分析基盤は作らない。SQLは各データの所有domain内に置き、上位側が下位のテーブルを直接JOINしない。

単価はSQLiteの改訂付きデータとして、モデル・課金経路・通貨/credit・単位・適用開始・確認日・出典を保持する。単価改訂は追記し、過去の根拠を保持する。モデル名やprofile名、料金を製品定数・ファイル名へ固定しない。価格変更前後を混ぜた平均単価で履歴を再計算しない。

新画面はbundle＋登録adapterとして追加する。artifact名はusage.dashboard。groupなしlauncherで独立メニューへ公開し、既存のアーティファクトホスト・Rendererで表示する。既存のSelect、Table、日付入力を再利用し、不足する集計表示だけを再利用可能なDesignSystem部品として追加する。初期表示・フィルター変更・明細ページングは読み取り専用query、料金編集は登録済み操作の受付・保存経路を使う。

単価データの文書・保存操作はusage側が所有し、設定domainから上位domainを参照しない。共通のフォーム・下書き・変更確認のUIを再利用することと、settings文書専用の保存処理へ別domainのデータを押し込むことは分ける。新しい登録adapterはusageの公開操作だけを呼ぶ。

APIは、期間とフィルターに対するsummary、daily series、ページングしたLive/SDK明細、filter候補と単価履歴を返す案。各応答に集計時点・対象期間・タイムゾーン・計測品質・既知/不明件数・適用単価の改訂を含める。画面表示中のみ数秒～十数秒間隔で保存値を再読し、Providerへ計数や料金照会の追加呼出しを発生させない。

APIキーや上位権限の請求用キーは追加要求しない。管理者向けUsage/Costs APIとの照合、他アプリのSDK利用、契約残量の取得は別の接続・権限・設計が必要なので今回の前提にしない。

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |

MVPの到達点はLive時間・概算USDとCodexモデル別tokensを正しく見られること。Codexの実請求額・残量や未確認のcredit換算を完成条件へ紛れ込ませない。

## 9. 検証計画

| 入力・条件 | 期待する結果 |
| --- | --- |
| Live累計12→15→15、最終18秒 | 最終18秒。途中通知を加算しない |
| 無音・マイクOFF・担当の作業待ち | Providerが返す時間を計上。発話秒数で割り引かない |
| 途中15秒で切断 / 再起動 | 15秒は受信分として残り、最終量未確認。0円と表示しない |
| 試用の終了と字幕削除 | 試用の利用量は集計に残り、字幕は削除規則を維持 |
| 同一SDKイベントの再送、同一thread再開、turn内の複数呼出し | 一度だけ計数し、前回分の再加算と最後だけの過少計上がない |
| 入力1000・キャッシュ400・出力100 | 入力総量1000、内訳400、出力100。合計へキャッシュを再加算しない |
| SDK失敗・取消・結果不採用の前にusage受信 | 使用量は残る。回答は既存の採用条件に従う |
| モデル/接続名/単価の変更、model reroute | 変更前の記録を現在値へ付け替えない。要求/実行モデルを区別 |
| 単価なし、契約種別不明、cache内訳なし | 取得済みtokensは表示し、必要な概算は未算定と表示 |

## 10. 代替案と今回の判断

- 直近usage一覧のブラウザ内合計: 全期間にならず、再表示で重複や条件不一致が起きるため採用しない。
- OpenAI全体の請求APIだけを正本にする: Codex契約とLiveの実行中量を同じ条件で扱えず、追加権限も必要。将来の照合用とし、今回の前提にしない。
- tokenや秒数をLLMへ送って料金を推測させる: 不要な費用と誤差を作るため使わない。契約・単位が明示された数値計算で行う。
- Codexを一律にAPI料金へ換算: 契約や課金単位が違うため採用しない。
- 予算到達で自動停止: 会話や実行の権限・停止方式を変えるため、本計画には入れない。
