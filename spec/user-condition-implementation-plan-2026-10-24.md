# 一時的なユーザー状態の実装計画

作成日: 2026-10-24。状態: **計画のみ・保留・未実装**。
Memory・WorldModel・ContextWindowの大改修が完了した後、利用者の着手指示を受けて再開する。本書は現行仕様を変更せず、改修後の責務・API・文脈構造を優先して見直す。

## 目的と初版の範囲

疲労・意欲・リラックス・怒りなど、一時的な状態を必要な期間だけ保持し、会話の提案や説明の負担を調整できるか検証する。初版は本人が明言した状態を同じ会話内で扱う。推測による状態、会話間の共有、長期の性格評価、音声・表情からの推定、専用UIは対象外。

## 実装方針（改修後に再確認）

- 既存の記憶担当と短期記憶を再利用する。現在の候補は`steward`と`continuity`。Worldへの新規保存や二重の正本は初版では作らない。汎用の短期メモだけで要件を満たせるなら専用構造を追加しない。
- 状態は複数併存できる短い記述とし、出典、明言／推測の区別、観測時刻、適用範囲、有効期限を保持する。意味の判断・更新・応答への使い方はLLM、参照・版・期限・忘却の検査はコードが担う。感情ごとの固定応答や語句による分類は作らない。
- 新しい根拠なしに、要約・再保存だけで有効期限を延長しない。期限切れは「状態不明」として提示を外す。訂正・忘却後に古い処理結果で復活させない。
- ContextWindowには有効な状態だけを出所付きの資料として毎回提示する。現在の候補は末尾寄りの`state.userCondition`。固定指示・長期プロフィールには置かず、不明なら空にする。上限は最大3件・合計300推定tokenを試行値とし、既存予算内で測定する。
- 会話は最新の発言を優先し、背景での状態更新を待たない。状態は応答方針の命令にせず、事実の正誤や本人の希望を上書きしない。更新失敗時は有効な既存状態だけを使い、期限切れは通常の会話文脈で応答する。
