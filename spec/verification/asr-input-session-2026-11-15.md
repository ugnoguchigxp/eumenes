# 音声入力経路の置き換え: 検証記録

日付: 2026-11-15。基準commit: `bf4af7d3`。

## 対象と状態

[承認済み設計](../.todo/asr-input-session-redesign-2026-11-15.md) のEumenes側を実装。旧preview APIと定期再認識を削除し、受付・認識結果の直接通知・下書き所有権を統一した。現行LARMのbatch認識契約を使う。発話中の文字生成は未実装で、[LARM向け追加仕様](../.todo/larm-asr-streaming-contract-request-2026-11-15.md) を作成済み。

別作業による画像・音楽連携等の変更が同時進行しているため、基準commitに今回の所有ファイルだけを重ねた一時コピーで検証した。製品DB・設定・秘密はコピーしていない。最終照合では `settings-integration.test.ts` のASRモデル切替試験追加と `useWorkspace.ts` のASR設定を開く操作が別作業で追加されており、保持した。これらの追加は固定コピーの試験件数に含めない。作業場所全体の型検査も別途通過した。

## ブラウザー・稼働環境

利用者の再起動後、通常環境の `/api/status` がready、新しい `/api/voice/turns/:id/input-events` の存在を読み取り確認。未存在IDへの409 `voice_input_not_ready` は新しい経路の応答確認であり、実際の認識成功を意味しない。通常画面はマイク停止・入力欄空を確認。利用者の発言・設定は操作していない。

消音ブラウザー・試験用LARM・専用DBによる `tests/browser/voice-input.spec.ts` は成功（1件、試験本体12.2秒）。3つの録音中に聞き取り中表示が出ること、発話中はcommitが0件であること、最後に結合した入力を1回だけ送信して1回答を表示すること、前の入力がmergedになること、ProviderのASR実行が録音と同じ3回であることを確認した。試験サーバーは終了済み。

通し試験の準備には、旧fixtureと現行契約のずれを修正した。接続はcatalog確認だけではidleになるため、公開の音声開始操作でASRを準備してからreadyを確認。試験用LARMには状態取得時のprovider情報、gzip要求の展開、LLMへの割当contextWindow応答を追加した。製品の契約検証は変更していない。

旧 `speech.wav` は発話検出モデルの270区間すべてで開始閾値未満（最大0.463）だった。別の固定例文を保存済みLARM設定のsample APIで合成し、`asr-utterance.wav` として試験に用いた。同モデルで88区間中65区間が閾値以上。モデル閾値は変更せず、音声は再生していない。試験音声の出典・クレジットはfixture隣の説明に記録。最後の録音確定直後に送信される正常系に合わせ、未送信の確認は各録音の発話中へ配置し、最後の送信回数1件・回答1件の期待値を維持した。
