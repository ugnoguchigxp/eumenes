# 会話本文の生成中表示の検証

2026-11-15。利用者の「その設計案で進めてください。文字を生成中から表示するように実装して、取消や失敗時に途中の内容が残らないことも確認してください」に基づく。[承認した設計](../.archived/conversation-text-stream-design-2026-11-15.md)の範囲で実装した。

## 実装

- 既存の `AnswerStreams` の現在の本文を、進捗SSE・共通client・既存の会話画面へ接続した。全文のスナップショットに生成IDと連番を付け、生成中から文字を表示する。
- 暫定本文はメモリだけに保持する。文字の通知ごとにDBを読んだり書いたりしない。保存済み会話へ途中の文章を追加しない。
- 取消・失敗・生成signalの中止・run削除で本文を消去する。新しい生成の開始時も旧本文を消し、旧生成や重複・逆順の通知を採用しない。
- 接続が切れた場合は表示を一旦消し、再接続では現在の生成だけを表示する。旧接続からの遅い通知・終了で現在の表示を戻したり消したりしない。401/403/404は再接続せず消去する。
- 確定回答は保存された本文へ置き換える。同じrunの履歴が届いたら暫定行を除き、二重に表示しない。

モデル・指示・接続先・意味判断・保存スキーマ・認証方式は変更していない。特定の発言への条件分岐や固定応答は追加していない。音声で実際に聞かれた部分を記録する既存の契約は保持した。

ブラウザー試験は実client・hook・表示部品へ段階的なSSEを流す固定試験。通信相手と外側の画面はfixtureであり、利用者の稼働画面でのlive受入とは区別する。検証用サーバーを起動せず、音を出していない。

`bun run verify -- --domain dialogue --domain conversation --domain voice-dialogue` は、作業場所に残っている古いソースコピーをinventoryが拾って停止した。現行ファイルを固定した一時コピーではinventoryは成功し、既存の `web/src/components/domains/conversation/MessageList.tsx` が `dialogue/contracts/agency-status` を直接参照する境界違反で停止した。この参照はHEADにも存在し、今回変更していない。検査の上限や期待値を緩和せず、後続の静的検査とverifyが選んだdomain試験を個別に実行した。

音声の既存試験2件（`streaming-speech` と `settings-integration`）は「生成中のprogress本文が空」を前提としていた。承認済みの表示契約に合わせ、生成中の本文と生成ID・連番を検査するよう更新した。保存済み回答がまだないこと、および音声の句・抑揚・重複なしの検査は保持した。取消後は本文が空かつ暫定情報がnullであることを検査する。後者の更新後は当該ファイル14件・型・format・lintを確認し、製品コードを変えていないため135ファイル全体は再実行していない。

残った `api/application/agency/autonomy.test.ts` の失敗はcatalogが空になる問題であり、文字表示の製品変更7ファイルをHEADへ戻した別コピーでも同じ行で再現した（`baseline-autonomy.log`）。この既存の問題は今回の範囲外とし、試験を無効化していない。

時間はCLI試験の開始を起点とする。通常完了では22件、取消では10件の進捗通知を観測した。取消後は時間を置いた再照会でも回答保存0件・空本文を確認した。いずれも1回の観測であり、一般的な速度向上率とはしない。これらは公開APIの実測で、利用者の画面での描画時間や音声の実機器受入ではない。画面の除去と二重表示なし、および失敗時の除去は上記の固定ブラウザー・公開API試験で確認した。稼働設定を壊して障害を起こすlive試験は行っていない。

実装・反映・今回の検証は完了。モデルが最初の文字を生成するまでの待ちや外部検索自体の時間は残る。今回の変更は、生成済みの文字を回答の確定まで待たせないためのもの。
