## 実装

- run.inputMessageIdに対応する原文とホスト内の位置をGenerateInput.currentRequestへ保持。添付画像の解決後も同じ位置を参照する。現在の依頼を末尾のuserメッセージから推定しない。
- 先頭のsystem指示で参考文脈・実行状態の役割を示し、原文の直前にCURRENT_REQUESTと入力IDを明示。原文の後ろに追加されたホスト状態はEXECUTION_STATEとして原文より前へ配置する。原文と添付は変更しない。
- 候補選択の過去2件はreferenceContextとして提示。参照対象の補完と継続条件の理解に利用する。選択、自然文の後の経路再判定、既存の1回の修正、結果回答へ同じ境界を渡す。
- inference公開契約の短いdelegatedTaskRulesを、通常Web・SDK調査・history・World worker、要件検証、登録adapterと固定backendの共通操作担当、音楽生成・再生、画像、描画の計画担当で使う。
- 子のデータ項目・メッセージ数・履歴の範囲・ツール予算は増やさない。workerは依頼と状態および取得資料の3メッセージ、操作・メディア計画は2メッセージ。workerの64 KiB上限、資料32 KiB上限を維持し、増えた短い指示の容量は既存の計算へ含める。
- 確認再開は既存のinteractionに凍結されたrequest/originalRequestとpreviousQuestionsを使用。原文を回答だけに置き換えない。権限、期限、取消、遅延結果の拒否は維持。
- DB変更、公開API変更、意味判定用の追加モデル呼出し、個別の地名・話題に対応する製品分岐は追加していない。描画は出力schemaの重複生成を除き、既存の行数制限内に収めた。
