# dots連携 コードレビューと修正 — 2026-10-11

対象は今回の未コミットの dots 製品統合差分。共通 tasks／capabilities／dialogue の再利用、MCP 所有者認証、Events、保存・削除、Session の照合、質問とリマインド、設定画面を確認した。別チャットへの送信、実製品設定の変更、実 dots の操作は行っていない。

## 修正した指摘

| 指摘 | 修正と確認 |
| --- | --- |
| Session開始前の blocked が queued 状態から採用できない | 既存の状態遷移を経て質問待ちへ移す。最初の報告が質問でも成功する試験を追加 |
| Sessionを作れなかった failed を報告できない | 完了報告にはSessionを要求し、失敗報告は未開始でも保存する |
| Session数の許可を減らすと全子の停止確認を拒否する | 作業開始の許可と停止照合を区別し、保存済み全子の停止確認を受け付ける |
| 停止コマンドの期限切れで停止確認が永久に止まる | 同じ commandId／lease を更新し、期限の更新を配送の重複排除キーにも反映 |
| 許可した既存Sessionも前のタスクに紐付くと続行できない | 紐付けをタスク単位に移行。同じ接続・プロジェクト、明示した参照と続行権限、同時使用の禁止を検査。旧DBの移行・保持期限の試験を追加 |
| 未開始タスクがあるローカル接続を別のOAuth所有者へ渡せる | コマンド履歴だけでなく未開始・実行前取消の保存済み依頼も確認し、変更をtransaction内で拒否 |
| 質問への回答・再起動で予定が失効し、再開後も同じ予定を紐付け直せない | reminder を維持し、利用者が明示的に再登録したときに現在の権限で更新 |
| 無効な接続で購読が切れると残った停止を配送できない | 有効な停止コマンドが残る間だけ、同じ所有者の受信登録の更新を許可 |
| JWTのexpが長いと購読が最大認証年齢を越える | exp と iat+1時間の早い方までに制限する実署名試験を追加 |
| Webhook署名とtimestampが秒境界で不一致になる | 一つの時刻を全署名とヘッダーで共有し、秒境界をまたぐ試験を追加 |
| 長い日本語の原文と作業内容の二重保存でtask上限を超える | 整理した内容はtask.request、原文はsnapshot.sourceRequestに固定。既存の単一メッセージ読み取りを使う |
| 会話の質問回答・完了条件と保存先でUTF-8上限が合わない | ツール引数の検査を保存先の上限に合わせる |
| 文字数だけ満たした日本語の報告が保存上限を超える | 共通報告本文を12,000 UTF-8 JSONバイト以内としてMCP契約で明示・検査 |
| 完了済みタスクへ no_next_work で新しいSessionを追加できる | 終了後の新規Session紐付けを拒否 |
| 次の質問に前の回答が残る | 下書きをquestionIdに紐付け、ブラウザで二つ目の質問が空欄であることを確認 |
| 予定IDを入力し直すと保存済みcommandの指示文に別のIDが入る | 指示文は保存済みscheduleRefから生成し、クライアントの戻り値も型付け |
| dotsのmaintenance失敗がallSettledで見えなくなる | 既存のログ形式で失敗を記録 |

意味理解、委任先やサブエージェントの選択は引き続きLLMに委ねる。追加した処理は権限・状態・外部契約・保存上限の検査と実行に限定し、個別の発話・語句を判定する製品分岐は追加していない。移行済みSQLと既存のSkill版の本文は変更していない。
