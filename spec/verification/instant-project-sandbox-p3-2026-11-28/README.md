# Works P3の画像生成と保存素材

2026-11-28 JST。専用のSQLiteと固定版 `3.0` を一時ディレクトリに用意した。

| 検証 | 結果 |
| --- | --- |
| Chromeと固定応答 | 許可した機能に合わせて機能一覧を返し、保存画像と生成結果を作品別プレビューに表示した。作品からの画像案を採用した後、本体パネルで生成を確定するまでPOSTは0件だった。作品AからBの生成の照会・取消・取得を拒否した。 |
| 再送と保存 | 生成中に作品を保存して新しいプレビューを表示した。同じ操作IDが新しいページに結果を届け、LARMへの通常の生成POSTは1回。再送後も開始時の入力版と期限が同じだった。 |
| 取消と許可失効 | 稼働中の操作の取消と許可の失効を試した。遅れて届いた画像、失効した保存素材、無効になった生成の取得を拒否した。 |
| 応答喪失 | 既存のLARM生成クライアントで `generation_unknown` になり、同じ操作の再送で新しい生成POSTが発生しなかった。 |
| 作品単体 | 固定版の共通CLIで起動し、同じ画面がサンプルと表示され、同梱画像を読んだ。Eumenes APIへのリクエストは0。 |
| 実LARM | 保存済み設定の接続先で能力を発見し、許可した保存画像と実生成の226,419バイトを作品Bの同じChromeプレビューに表示した。同じ操作の再配送を含め生成POSTは1回。生成ジョブは76.7秒で、試験画像は終了後に削除した。 |

作品パネルから受付し、主会話への発言追加、画像計画の推論、会話向け画像の一覧と活動への登録はいずれも0件だった。固定応答と実LARMの両試験で、一時DBを使うWebとプレビューをループバックで配信し、終了時に待受が閉じた。 [検証結果](result.json)
