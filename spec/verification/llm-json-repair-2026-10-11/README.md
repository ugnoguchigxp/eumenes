# LLM生成JSONの共通補正（2026-10-11）

## 目的と実装範囲

LLMが生成したJSONを受理する境界で、通常解析→一回の構文補正→各domainの契約と採用条件の検証を行う。補正後も不正な場合だけ、既存の会話・worker・coding-supervisionのモデル修正を一回使う。モデル修正がない処理へ新しい推論ループは追加していない。

共通処理は `api/infrastructure/llm-json.ts`、依存は `jsonrepair@3.15.0`。会話のfunction引数、workerの操作・要件検証、Codexの最終制御応答（共通worker parser経由）、音楽生成・再生計画、監督判断、音声言語判定、World抽出に接続した。通常の本文、HTTP/SSEの通信envelope、設定、DB保存値、手入力のJSONは対象外。

引用符・カンマの補正だけを採用する。元と補正後のキー・scalar・コロン・括弧を字句として比較し、値補完・型変換・項目削除を拒否する。重複キー、途中切断、配列の欠落要素、複数JSON、深さ64超過も拒否する。容量制約と各domainの公開ツール・権限・根拠・期限・取消の採用検査は維持した。字句検査はJSONの制約の強制に限定し、業務語句や個別シナリオによる意味判断を追加していない。

会話のモデル修正には、違反パス・コード・期待する型と、不正引数の抜粋（最大2呼出し、各4096文字、切断フラグ付き）をuserデータとして渡す。固定のsystem指示でこの資料内の命令を採用しないことを指定する。ログは固定分類と容量だけで、生応答を保存しない。
