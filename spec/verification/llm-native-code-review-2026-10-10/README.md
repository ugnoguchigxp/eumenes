# LLM Native 実装のコードレビューと修正

対象は `llm-native-implementation-plan-2026-10-10.md` の実装差分、接続設定の環境変数撤去、その利用側と検証処理。既存の未コミット変更を保持した。同時進行の別チャットへメッセージを送っていない。

## 修正した指摘

1. **P1: enumが他の制約を無効にする。** 導入済みZodのJSON Schema変換はenumから先に返り、minimum/maximum、minLength/maxLength、formatを適用しない。有限数や文字列型だけを検査する既存の前処理では防げず、範囲外の候補値をsatisfiedにできた。公開schemaの限定構文を確認した後、enumと元の型・制約をintersectionに変換する。object/array内でも同じ処理を適用する。数値・文字列・日時・入れ子の回帰試験を追加した。外部ライブラリの変換仕様を補う処理に限定し、要件の意味判断は追加していない。
2. **P2: 有効期間の日時を文字列で比較する。** `00:00:00Z`と`00:00:00.001Z`の辞書順は実際の前後関係と逆になる。profile provenanceと外部ルールの双方で、UTC形式検査後に時刻へ変換して比較する。正順と逆順の回帰試験を追加した。
3. **P2: 検証対象の変更検知に過不足がある。** 生成された `spec/verification` のJSONやdesign-systemのbuild出力を変更とみなし、通った試験を最後に失敗扱いにする。一方、実行時に読むMarkdownのLLM指示が対象外だった。指示・コード・設定・試験データ・HTML・配布資産・lockを入力に含め、生成先だけを除く小さい処理へ分離した。結果の追加ではhashが変わらず、指示や資産の変更・コードの改名や削除では変わることを回帰試験で確認する。
4. **P2: same-hostの初期設定で起動できない。** 接続URLの環境変数を撤去した結果、URL未設定とsame-hostを組み合わせると設定schemaで起動に失敗する。未設定の状態を許可する。登録されたURLのloopback制約、実際の接続時の制約は維持する。初期設定とLAN接続先の拒否を回帰試験に追加した。
5. **P2: 公開クライアントの読み込みがPlaywrightの変換で失敗する。** deliveryのimport前にあったexportをimport後へ移した。ブラウザfixtureも公開 `createClient` を使うように戻し、実際の読み込み経路を検証する。最初の通し検証でNode ESMのJSON import属性不足が判明したため、JSON資産に `with { type: "json" }` を追加した。限定されたspecの起動だけでは検知できなかったので、ブラウザ全specの収集を追加の部分検証に含める。
6. **P2: live評価の起動失敗が記録に残らない。** 保存済み接続の読み込み・portの作成がtryの外にあり、失敗するとresults/summaryを出さず終了する。作成も同じ失敗処理の中へ入れ、作成済みのportだけ終了する。不存在の隔離DBによる起動失敗を2回記録して停止する回帰試験を追加した。製品DBや秘密を試験へ渡していない。

## 再レビュー

修正後に公開契約、profileのCASと失効、要件凍結のrollback、証拠と検証receiptの採用、取消、タイマーの一回性、音声言語判定、利用側import、差分を再確認した。今回の対象範囲で追加の修正が必要な指摘は残っていない。

LLMの意味判断を置き換える語句辞書・シナリオ別分岐・固定回答は追加していない。追加した処理はJSON Schemaと時刻の形式契約、接続先の制約、検証入力の変更検知、評価の失敗記録を担う。
