# Memory CLI・MCPの稼働確認（2026-11-07）

通常起動にMemoryHostの受付がなかった問題を修正し、利用者の明示許可を得てAPI・Webを再起動した。API・LARM・MemoryHostはready、Memoryはenabled/healthy、WebはHTTP 200。新しい起動のログで `memory.host_ready` を確認した。

Eumenes CLI、専用Memory CLI、2つの独立したMCPプロセスとAPIの参照結果は全件で一致した。MCPの7ツールを列挙でき、snapshotのread、一方の切断後の他方の継続、再接続も成功した。再起動でホストのepochが変わり、既存の認証設定・権限・有効な記憶の参照結果は保持された。今回の起動でMemoryの警告はない。

実環境は参照のみで確認した。有効な記憶は再起動の前後とも0件だったため、実データのitem出典の読取りは対象がない。保存・訂正・忘却・出典・複数クライアントの相互参照は、個人データを使わない結合試験で確認済み。稼働DBを直接開いたり、個人の記憶へ試験データを書いたりしていない。エージェントの既存設定は変更していない。

修正の結合試験30件と型検査3,129ファイルが成功。固定したソースでMemory・Steward・Dialogue・Worldの標準検証を実施し、Bun 1,028件、Web 15件が成功した。既存の生成済み試験コピーを含まない別環境を使用し、検証用コピー内の既存3ファイルだけ整形を正規化した。実作業ツリーの無関係な変更は保持している。検証した起動関連8ファイルのhashは最終確認時も一致した。
