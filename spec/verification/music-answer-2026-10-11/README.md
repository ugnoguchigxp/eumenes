# 音楽プレイヤー表示後の案内

目的は、プレイリストを見せる依頼が完了した際に「プレイヤーを開きました。どうぞ」程度で案内し、内部IDや表示済みの一覧を読み上げないこと。変更範囲はdialogueの共通会話指示と音楽操作後の指示、live回帰評価に限定した。画面表示の実装・DB・API・音声合成は変更していない。

原因: 従来の指示はcompleted時に曲名や検索条件とArtifactでの再生案内を要求していた。結果のtrackIdsは曲名でなく再生用の参照であることを指示していなかった。実LLMで、過去のID列挙を含む履歴と説明要求に対してIDを再び読み上げることを再現した。

既存指示を再利用し、表示完了なら短い案内、説明要求なら取得できた情報、空結果なら該当曲なし、失敗・取消ならその状態を伝えるよう整理した。IDを曲名として扱わず、通常の返答で内部名称を読み上げない。意味判断はLLMが行い、製品コードには発話別の条件分岐・正規表現・固定応答を追加していない。

検証順序: 変更前の音楽結合試験8件 → 修正後の音楽結合・選択試験10件 → dialogue domain gate（backend120/Web6） → 実LLMで最終回答8ケースと楽曲制作完了1ケース → 全体gate。結合試験はfixtureであり、モデルの指示遵守の保証とは区別する。

live回帰評価: `bun scripts/music-answer-live.ts --run`。保存済みLARM設定をbackendの読み取り専用操作から取得し、同じ既存接続を使用した。ツール選択・検索計画・曲取得は隔離fixture、最終回答だけ実LLM。再現発話、言い換え、メイド口調、過去のID列挙がある履歴、説明要求、空結果、失敗、取消を評価した。初回修正では過去履歴の件数説明が残ったため、表示済み情報を繰り返さない指示を補強し、全8ケースを再実行した。

最終結果: 表示依頼4ケースはすべて「プレイヤーを開きました。どうぞ。」、ID・曲名一覧・件数・Artifactの説明なし。説明要求は未取得の曲情報を作らず、空結果・失敗・取消はそれぞれの状態を報告した。自動評価の禁止文字列・短さ・状態表現の確認に加え、全回答を目視確認した。楽曲生成fixtureの完了コンテキストを実LLMに渡す追加確認では「楽曲の制作が完了いたしました。どうぞ。」で、空プレイリスト扱いにならなかった。実際の楽曲生成や製品曲の変更はしていない。

差分点検: 着手前から音楽再生・Opus等の未コミット差分があったため保持した。本修正では上記の指示2箇所と評価スクリプト・本資料だけを追加変更した。評価スクリプトの語句判定は試験の採点のみで、製品の意味判断には使わない。

未実施: 実ブラウザからの音声依頼・実スピーカーの聴取。画面と音声合成の経路は今回変更しておらず、読み上げ元の最終回答を確認した。live試験は最終回答の遵守の確認であり、実機器での音声受入とは扱わない。

全体gate: 405733 msでブラウザfixtureにより失敗。静的確認、型、backend1486成功/1skip、Web299、client329、DesignSystem1097、buildは成功。browserは34成功、4失敗、1skip、6未実行。失敗はcspの設定画面読み込み（取得先と手順ボタンが現れず、設定API接続エラー表示）、dotsのserver unavailable、research-routesとtimersのfixture_not_ready。原因は未確定で、本指示変更との因果も断定していない。担当外のfixture起動・設定画面は修正せず、全体gateを合格とは扱わない。開始時の入力hashは `bb0caef5de1ffadf33af896099662d65aa041690940deee72202fa023813da09`、終了後の再計測は `ad606fea4b39f3e9a147b3a429c6c66198172c2869101c7c09e9dfd515d25250` で一致しなかった。本作業の製品コードと評価スクリプトは検証中に編集していないが、全体入力の同一性は確認できていない。失敗によりverify本体の最終hash検査には到達していない。

残作業: 音楽の回答修正とそのlive確認は完了。全体gateの未確認・失敗を解消するには、別途依頼の範囲で上記fixtureの起動・接続失敗を調査する。既に起動中のEumenesへの反映にはbackendの再起動が必要で、本作業では稼働プロセスを再起動していない。

並行変更の観測: 着手時には存在しなかったresearch-result-context、inferenceのCodex adapter・execute・試験、logger、package.json/bun.lock等の差分が検証終了時に追加されていた。codex-output.tsの削除とcodex-failure.ts/codex-launcher.tsの新規追加も確認した。これらは本作業の編集ではなく、保持した。全体入力hashの不一致とブラウザ失敗の因果は確定していない。
