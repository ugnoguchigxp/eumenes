2026-10-25 JST。[合意済み設計11節](../../../ocr-correction-region-qr-design-2026-10-25.md)を実装した。**実装と固定試験は完了。実LLMの品質受入は未達（最終候補5/9資料合格）。** 稼働サーバーへの新版登録と実カメラでの受入は未実施。サーバー操作、製品設定や共通推論の変更は行っていない。

## 実装

- `ocr.correct@3`のProfile/Skill/Packageを追加し、新規補正候補の実行先を接続した。@1と@2の定義全体のdigestを確認し、既存登録→@2→@3の追加と再投入の冪等性を試験した。旧版に結び付いた処理は従来の完成文契約を使う。新版失敗時の旧方式への切替は行わない。
- OCR domain内の内部編集計画として、保持範囲、訂正、元行を参照する段落・セル、接続、不確実性と除外行を受け取る。部分文字列は元行内の一意な一致だけを許す。明示的な`wholeLine:true`なら元行そのものを参照し、訂正前文字列の再転記を省ける。
- 保持範囲に重なる編集、不一致・曖昧な参照、重複した編集・元文参照、未使用の編集、参照されない内容、表の範囲・重なり、不確実性の説明漏れを拒否する。全体が有効な場合だけ、元文へ編集を適用して既存の公開補正結果へ変換する。接続文字は空文字か半角空白に限定する。
- 保存・取得・会話追加、元資料revision/digest、取消、receiptの採用、所有者の検査は再利用した。公開APIやDBの形式、画面、QR、接続先、推論回数は変更していない。

コードが保証するのは**LLMが正しく指定した保持範囲と参照の整合性**である。LLMが数値の行を別の行と取り違えたり、保持対象を指定し忘れたり、訂正後の文章自体に語句の脱落や追加を含めた場合まで、意味をコードで判断して止めることはできない。この限界を伏せて「型番・数値を必ず保持できる」とは扱わない。

## 実LLM評価

実行は`scripts/ocr-correction-live.ts --run --edits`。人手正解を持つ合成画像と、意図的な誤認識を含む固定OCR観測を、保存済みLARM接続の実LLMへ渡した。LLMには正解を渡していない。元資料3件と、別の語句・型番・数値・固有名詞・表・英語・見出し・既に正しい敬語・脱字を含む6件の計9件を使った。実OCRや実カメラの評価とは区別する。

比較した旧版は直前の@2。初回に9件の旧版結果を保存し、指示・内部参照表現の調整後も同じ旧版結果を用いた。新方式は3候補を各9件で評価した。途中候補を製品へ登録したわけではなく、隔離環境で新版@3の受入前候補を調整した。最終候補のbundle digestは[results.json](results.json)に記録した。

| 資料 | 最終結果 | 残った問題 |
| --- | --- | --- |
| 利用者例を含む文章・型番・単位 | 不合格 | 型番と単位を保持し、`など尋部`と敬語は修正したが、`取扱方法`の1文字を落とした |
| 元の表 | 不合格 | LLMが保持する行と訂正する行を取り違え、`1.25 kg`を`重量`へ置換した |
| 覆いのあるコード・命令文を含む資料 | 不合格 | 覆いを不確実と判断したが、他の段落のuncertainが欠落し、契約検査で拒否 |
| 別の説明文・型番・値 | 合格 | 誤字・語尾・文中改行を修正し、型番と値を保持 |
| 既に正しい敬語 | 合格 | 語句・型番を変えず文中改行を統合 |
| 脱字のある文 | 不合格 | 脱字と型番・値は正しく扱ったが、日本語の文中に不要な半角空白を追加 |
| 見出し・固有名詞 | 合格 | 見出しを分離し、本文の誤字と改行を修正、名前・型番を保持 |
| 英語 | 合格 | 誤字を修正し、単語間の空白を補って文を連結、型番・値を保持 |
| 別の表・型番・温度・長さ | 合格 | 表の形と値を保持し、通常語彙の誤字を修正 |

旧版結果、訂正後本文、構造化された編集計画、各判定を[最終結果](results.json)へ収録した。[候補1](attempt-1.json)は2/9合格、[候補2](attempt-2.json)は3/9合格だった。候補ごとの指示はattempt-1-guidance.json、attempt-2-guidance.jsonに保持した。途中で確認した失敗を隠す再実行、正解の変更、条件の緩和、個別語句の置換はしていない。

CERは旧来の空白を除外した文字誤り数であり、余計な空白や段落・見出しの保持は別に完全一致を検査する。単に文字誤り数が減ったことを合格にはしていない。最終候補は8件で公開補正結果を返し、1件は契約不正で拒否された。全集合の品質受入成功や、拒否によって補正品質そのものが改善したとは主張しない。
