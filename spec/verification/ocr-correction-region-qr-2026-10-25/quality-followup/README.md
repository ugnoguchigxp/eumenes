# 補正品質の継続調査

2026-10-25 JST。型番を保持し、語句を追加せず、誤字脱字と文中の改行を修正するという追加依頼に対する記録。**品質受入は未達。今回試した指示は製品へ登録していない。** 製品bundleが調査前と一致することを[summary.json](summary.json)のdigestで確認した。

## 実LLMによる切り分け

保存済み接続先をsettings domainの読取り専用操作で取得した。同じ合成画像とOCR観測を使用した10回の診断であり、上流の実OCRや実カメラの受入ではない。正解をLLMへ渡していない。新しいサーバー、製品設定、モデルの固定値は追加していない。

| ラウンド | 仮説と変更条件 | 観測結果 |
| --- | --- | --- |
| 1 | 現行@2の画像あり・なし、保持対象を明示した短い指示を比較 | @2は両方で`AB-10O`を`AB-100`へ変更。短い指示は型番を保持したが、誤字を本文へ反映せず注記へ残した |
| 2 | 通常文の修正を本文へ反映するよう指示 | 誤字の一部を修正したが、型番を変更し、`ご確認ください`へ`して`を追加した |
| 3 | 英語で修正と保持の範囲を分離し、入力後にも作業を明記 | 型番保持と文中改行の除去は成功。本文の誤字はそのまま残った |
| 4 | 段落・表・根拠を外してtext一つの診断用形式へ縮小。画像あり・なしを比較 | 簡単な形式でも型番変更、改行残留、原文にない語句が出た |
| 5 | 利用者例とは異なる日本語の校正例を追加 | 型番保持と一部の誤字修正は成功。冒頭の誤字と文中改行が残った |
| 6 | 訂正箇所と保持範囲を指定する編集計画を試作 | 元文と一致しない訂正範囲、型番への変更案が出た。検査で拒否したため成功扱いにしない |
| 7 | 型番の保持との競合を調べるため、文章3行だけをテキスト入力 | 本文の誤字が残り、文中改行も除去できなかった。処理分割だけで改善する根拠は得られなかった |

3・6ラウンド後に結果と方針を見直した。画像の影響だけ、JSON構造の複雑さだけ、型番保持との競合だけでは説明できず、現行の接続先と指示の組合せでは安定して受入条件を満たせていない。同じ指示の再実行は続けない。

最初の3回はProviderのJSON schema指定付き、それ以降は製品と同じJSON object指定とhost検査を使用した。この差もあるため、異なる指示の単純な優劣比較や製品の通し検証とは扱わない。`scripts/ocr-correction-probe.ts`は診断の再現用であり、簡略形式や文章のみの診断を品質受入に数えない。

原資料の期待値は変更していない。語句辞書・専用置換・型番抽出の正規表現・自動再推論は追加していない。新候補が原資料を通らなかったため、一般化資料を増やして受入を行う段階には進めていない。

## 次の設計案と限界

[設計書の11節](../../../ocr-correction-region-qr-design-2026-10-25.md)に、完成文の再転記から元文への編集計画へ切り替える案を記した。これは型番への変更案を契約検査で止めるための設計案であり、誤字の修正品質まで達成したものではない。試作では不正な案を拒否できたが、有効な補正案は得られていない。

新しい内部契約・判断の優先順位に関わるため、合意前に製品実装しない。合意後も、位置指定の安定化、保持対象の見落とし、不確実性の扱い、一般化資料と元の3資料の受入を必要とする。現行の推論先で品質が成立するかは別途確認する。設定や共通推論方式を無断で変更して改善済みにしない。

## 差分点検と確認範囲

今回追加したのは診断スクリプト、実験記録、設計書10・11節である。診断スクリプトのlintと型検査（依存先を含め228ファイル）は成功し、`git diff --check`は問題なし。製品のProfile/Skill/bundle、補正API・公開契約・実行処理、QR、画面はこの継続調査では変更していない。既存差分と並行して増えたdots・voice等の変更は担当外として点検のみ行い、編集していない。

製品変更を採用していないため、前回成功したdomain検証とブラウザ結合を今回再実行する理由はなく、省略した。診断を製品の部分・結合・通し検証の成功に置き換えない。新設計を実装する場合は設計書11節の順序で改めて実施する。今回のcontext_compileとcompile_evalは各1回、この会話の累計は各3回。

再現時は`bun scripts/ocr-correction-probe.ts --run`へ`--guidance`で同フォルダのdraftを渡す。最初の3条件は`--strict`、英語の比較は`--task-last`、簡略形式は`--simple`、文章のみは`--simple --prose-only --modes draft-text`を指定する。出力先はignoredなverification-reports配下であり、ここに収録した結果を上書きしない。
