# 受け渡し機能のレビューと改善

2026-10-22。利用者の「コードレビューし、改善点がなくなるまで改善」の依頼に対応する。

## 範囲・計画・完了条件

前回追加した資料契約、実行への接続、アーティファクト内の編集・メディア選択を対象とする。既存のLLM指示、資料と実行指示の分離、版検査、認証済み一覧、共有プレイヤーを確認し、まずその再利用で修正する。別作業の差分、認証方式、DBスキーマ、判断方式、サーバーの起動・停止・再起動は対象外。

1. 通常経路と境界条件を読み、具体的な失敗を再現する。
2. 入力の保持、保存中の操作、JSON値の保持、非表示時の試聴、遅れた一覧操作を既存部品の状態・契約検査で修正する。意味判断を追加しない。
3. 部分→ホスト接続→ブラウザの順に確認し、関連domain verify・型・ビルドを実行する。
4. 最終差分を改めて読み、今回の範囲に未解決の具体的な不具合がないことを確認する。担当外の失敗は分けて記録する。

当初の作業：再現試験、修正、部分試験、接続／ブラウザ確認、関連検証、再レビュー、結果記録。いずれも完了。

## 指摘・修正・再現結果

| 優先度 | 問題と影響 | 修正と確認 |
| --- | --- | --- |
| P1 | 調査手順で、選択した本文等の容量を予約せずに取得資料を登録し、資料が増えた時点で `required_context_overflow` になる | `workerContext` の既存予算から渡す資料の容量を引いてからEvidenceCatalogへ登録する。全文と登録済みの根拠を落とさず、同じ資料を次の調査ラウンドでも読めることを確認。修正前は例外、修正後は成功 |
| P2 | 本文・固定の値を入力したまま「反映」を押すと、選択に追加されていない入力を失う | 未追加の入力がある間は反映を止め、追加またはクリアを案内。参照元を切り替えても入力を保持。修正前の再現試験が失敗し、修正後に成功 |
| P2 | 反映を待つ間も資料や入力を変更でき、その変更が送信内容に含まれず閉じられる | 保存中・ホスト処理中・更新競合時は既存のフォームをfieldsetで無効化。保存失敗なら入力を保って再び編集可能。非同期の反映待ちを固定して確認 |
| P2 | JSONの `1e400` や入れ子の `-1e400` がInfinityとなり、保存時にnullへ変わる | JSON解析時に有限数を検査し、表現できない数値は入力エラーとして保持。勝手にnullへ変えない。平坦／入れ子の両方を再現して確認 |
| P2 | 試聴中に別の曲を選ぶと、共有MusicPlayerの継続再生が働き、選んだだけで新しい曲が鳴る | 選択画面のプレイヤーだけ曲IDで作り直す。共有プレイヤー自体の動作は変えない。実ブラウザで再生呼出しが修正前2回、修正後1回になることを確認 |
| P2 | アーティファクトは非表示でもマウントを保つため、別タブへ移っても試聴が続く | 非表示時は一覧リソースを非アクティブにし、試聴プレイヤーへ渡す曲を解除。選択中の画面と検索は保持し、戻っても自動再生しない。表示状態を切り替えるhook試験で確認 |
| P2 | 結果の項目選択が契約より一段浅く、利用可能な6階層目を選べない | 既存の参照契約とUIの列挙上限を一致させる。6階層目の実際の項目を参照として保存でき、未対応の7階層目は候補にしないことを確認 |
| P3 | 閉じた／非表示の選択画面から遅れた追加読込や再取得が来ると、一覧取得を再開できる | 表示・参照元・検索語・取得中状態を確認してから既存の取得操作を呼ぶ。閉じた後と非表示中の追加読込／更新で取得回数が増えないことを確認 |
| P3 | 選択に変更がなくても反映でき、サーバーの `no_change` 拒否がエラーになる | 変更のない反映を無効化。値を変えてからだけ既存のsource applyを呼ぶ |

## 実施と結果

- 変更前：追加したUI再現試験4件、非表示リソースの試験1件、継続再生のブラウザ試験1件、調査の容量境界1件、6階層目の項目選択1件で問題を確認した。
- 部分：UI 27件・Web 19件・調査／資料／子実行29件が成功した後、項目の階層境界と非表示時の取得抑止も追加した。
- 結合：会話・API・Artifact・実行の4ファイル23件が成功。本文・原文プロンプト・選択したメディア参照が、保存・公開を経て実際の子担当入力へ届く従来の試験も維持。
- 関連domain：`bun run verify -- --domain pipelines --domain agent-runtime --domain tool-runtime --domain capabilities` がpass。Bun 282件、Web 31件、DesignSystem 28件が成功。境界・SystemContext・サイズ・整形・lint・型・DesignSystemビルドを含む。
- 正式レポート：`spec/verification/reports/runs/2026-10-22T12-46-54-573Z-a163ab48-5f05-48a6-b74e-703b2fb409d8/report.json`。
- ブラウザ：対象 `tests/browser/pipeline-handoff.spec.ts` の3件が成功。狭幅のアーティファクト、小さいモーダル、画像デコード、全文保存、取消、試聴の開始と破棄に加え、試聴中の別曲選択で再生しないことを確認。
- 全体型：`bun check` が成功（2,366ファイル）。Webビルドも成功。既存のチャンク容量・backgroundの混在import警告のみ残る。
- 3ラウンド後の俯瞰：新しい証拠と残作業を確認して進め方を通知。再現した不具合と契約境界に修正を限定し、その後は編集を止めて関連検証と再レビューを完了した。

## 再レビュー

修正後に、全受け渡し種類の保存・解決、UIの入力保持、競合・取消、非同期待ち、一覧キャッシュと表示状態、プレイヤーの寿命、資料と指示の分離、容量予算を再確認した。今回の変更範囲に未修正の具体的な指摘は残っていない。

変更は既存の資料予算・状態管理・数値契約の検査に閉じている。LLMへの指示や意味判断方式、DBスキーマ、権限、既存revision、サーバー状態は変更していない。別作業の差分を保持し、無関係な修正を加えていない。差分のwhitespaceエラーなし。

実ライブラリ・実モデルを使うlive受入は未実施。今回の検証は固定API／モデルと実部品のブラウザ操作であり、実モデルによる資料解釈の評価を追加したものではない。サーバーの起動・停止・再起動は行っていない。

このレビューラウンドのcontext_compileは1回、compile_evalは1回（useful）。残作業はなし。
