# Pursuitの行動分析

対象は11月8日の技術比較・博物館比較の完了二件と、その後のpartial二件。目的は、単発検索の反復が遅さの原因かを検証できる時系列データを渡すこと。

1. 既存の実行記録、使用量、運用ログ、Web取得結果をrun/job/attempt IDで照合する。
2. モデル呼出し・外部検索・本文取得・実行待機・保存をJSONとCSVへ出力する。時刻はJST、経過時間は依頼開始からの秒。情報が取れない内部操作・検索語は不明と明示する。
3. 呼出し数・所要時間・直列実行・検索失敗・本文を得た時刻と報告内容の対応を確認し、観測と仮説を分けてMarkdownへまとめる。
4. 件数、全usageの合計、IDの一意性、時間区間、既存集計との一致、出力列の機密情報混入を確認する。

製品コード・アルゴリズム・設定の変更、サーバー操作、新しい推論や検索、製品DBのクライアント直読、別チャットへの送信は行わない。追加の固定試験やlive試験はせず、保管済みの結果を分析する。

完了条件は、根拠を追える四件の時系列と集計、検索の逐次実行を示す具体例、検索以外の時間と不足データの説明を揃え、成果物を利用者へ渡すこと。

完了: 公開APIによる156件の関連usageと、保管ログの相関を照合。317行の時系列、29件のWeb操作表、四件の構造化データ、分析レポートを出力した。算術・件数・一意性・区間の検査は成功。既存製品15ファイルに変更なし。完全な内部操作列は未取得と明示した。Context MCP累計6/6。
