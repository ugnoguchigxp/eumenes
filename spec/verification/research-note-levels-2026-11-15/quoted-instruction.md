# HTTP キャッシュにおける `max-age` と `no-cache`

`max-age` は指定秒数のあいだ応答を新鮮として扱う指示です。`no-cache` は保存を禁じるのではなく、再利用の前にオリジンサーバーで検証するよう求めます。

## 対象と確認日

HTTP 応答の `Cache-Control` に付けるキャッシュ指示について、RFC 9111（2022年6月発行）を2026年11月15日に確認。

## 違い

- `Cache-Control: max-age=秒数` — 応答の経過時間が指定秒数を超えると、キャッシュは応答を古いものとして扱います。新鮮な間は、通常、検証なしで再利用できます。
- `Cache-Control: no-cache` — キャッシュへの保存自体は禁止しませんが、別のリクエストに応答を使う前にオリジンサーバーへ転送して検証し、成功する必要があります。
- したがって、`no-cache` は「キャッシュしない」ではなく「再利用前に検証する」という意味です。保存も禁止したい場合の指示は `no-store` です。
