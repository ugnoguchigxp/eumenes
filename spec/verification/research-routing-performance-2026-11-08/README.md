# 自然文中止・担当選択・計測の再検証

2026-11-08。修正・固定検証後、利用者による再起動済みのAPIで実接続を再検証。担当選択は今回のケースで改善したが、自然文取消は未達。通常二件は両方partialで終了し、計測と保存読戻しを完了。調査完了の受入は不合格。[作業計画](../../research-routing-performance-2026-11-08.md)。

## 修正

- 中止候補には、表示用の短縮済み題名だけでなく、既存TODO台帳の依頼本文を渡す。引用された本文は既存の未信頼区切りに置く。候補は既存の有限参照であり、会話・版・状態・取消後の結果採用検査は維持する。
- `web.search@10` と `web.research@7` の正の能力説明に、単発確認と複数資料の比較・Markdown保存の境界を明記する。旧revisionは不変。
- `skill:pursuit.research@5` / `package:pursuit.research@5`。重複する指示を整理し、元依頼・保存済み下書き・本文根拠・独立した完了照合を維持する。実行回数・時間・検索上限は変更しない。
- 独立最終検証へ実行担当のSkillを重ねず、すでに元依頼・回答案・根拠を含む検証packetを一度だけ渡す。採点基準は変更しない。
- `pursuit.model_finished` は、目的・相関ID・時間・報告された入力/出力トークンだけを記録する。本文やProvider生応答を記録しない。総トークンの正本は既存の全件usage APIを使う。

## 実接続の準備

入力と期待結果は `cases.json`、固定hashは `cases.sha256`。通常の調査2件、元の比較依頼の担当選択、短い事実確認、自然文中止と引用文、複数作業の曖昧な中止・対象を指定した中止を確認する。最初の制御失敗を確認後、通常の調査2件を開始し、残る制御ケースと前半を重ねた。通常二件は約32秒差で開始し、初期数分には制御用の調査も実行された。前回の開始間隔とは異なるため、その負荷条件も残して保存完了まで測る。未達を確認した場合は対象の検証仕事を既存公開操作で止め、実行中の入力・実装を編集しない。

実接続では現在保存されている接続設定・モデル・router入口と閾値を維持する。通常2件はそれぞれの前回と同じ入力を使うが、開始間隔・他の検証仕事・Webキャッシュが前回と同じではないため、経過時間へ単純な改善率を付けない。呼出し数、入力・出力と合計、未報告件数、推論時間、待機、取得、保存、経過時間を別々に残す。利用者が再起動したAPIのbootIdは `16a27d58-cd97-48ee-85a6-182f2625e4a2`。この検証ではサーバーを操作していない。


## 再起動後の制御検証

入力抽出で旧履歴の開始文を取消文と取り違えていた準備上の誤りを、live開始前に修正し、旧入力と修正理由・hashを保存した。期待条件は変更していない。実行中の製品・入力は変更していない。

| シナリオ | 結果 |
| --- | --- |
| 前回誤配した博物館比較 | `web.research`へ選択。新規Pursuit一件。担当切替なし |
| 短いMDN事実確認 | `web.search`へ選択し、39.5秒で出典付き非同期APIの回答を通知。Pursuit文書タスクなし |
| 中止文を引用した意味の質問 | 取消せず回答。新規調査なし、既存調査を維持 |
| 博物館調査の明示中止 | **失敗**。「中止しました」と応答したが仕事はactive。新規調査はなし |
| 元の自治体調査の明示中止 | **失敗**。取消を新規`web.research`へ配送、Pursuitがもう一件増えた |
| 二件ある状態で曖昧な中止 | 実際の取消・新規調査はなし。ただし対象を確認せず、中止したと返すため**全体は失敗** |
| 避難所だけを指定した中止 | **失敗**。両仕事がactiveのまま、指定した中止を実施したと返答 |

失敗後は対象会話の検証TODOだけを既存公開操作で中止した。selection一件、自治体二件、複数対象二件がcancelled/archived、active・通知・成果物0。後続の観測でも文書・通知は増えていない。自然文による中止の成功へ数えない。既知の同じ失敗を繰り返すだけになる最後の図書館中止文は送らず、明示操作で後片付けした。

根拠は `live/*-start.json` / `*-cancel.json` / `*-ambiguous.json` / `*-selective-cancel.json` と `*-late-check.json`。起動監視のraw ID差分は全会話を含むため、長いWeb検索待機中に開始した後続技術比較のIDがsingle-factのraw差分にも入った。`live/launch-attribution.json`で当該IDを除外し、操作選択・TODO・通知で照合した。raw結果は消していない。

全候補を含むRouterの記録では、博物館中止はconversation 0.480 / cancel 0.232、元の自治体中止は新規research 0.416 / cancel 0.135。取消候補がhostへ存在しない問題ではない。候補説明だけの改善を成功と扱わず、同じ説明調整の再試行は止めた。

既存構造経路の読み取り専用probeも実施。保存済み8秒、会話経路、既存v8/schema、有限参照を使い、設定・仕事の状態を変更していない。正しいtransport parserを使った五件では、明示取消二件が想定参照、引用文と曖昧な対象は誤取消、博物館取消はtimeout。通し試験の成功・恒久切替の根拠にならない。最初のprobeはtransport envelopeを内部parserへ渡してしまい、期限内応答を無効と測った。その結果を`structure-readonly-probe.json`へ残して採点対象外とし、製品が使う`parseTurnResponse`へ接続して一回だけ比較し直した。出力を捏造・補正して成功へ変えていない。

三ラウンドの整理で、説明の追加修正から原因記録・計測へ方針を変更した。既存の意味判断・閾値・入口の変更や、取消フレーズの条件分岐を製品へ加えていない。自然文取消を解決済みとする完了条件は満たしていない。

総量は、旧集計のPursuit＋関連Agencyに加え、依頼開始から完了通知までに開始した同一会話の記憶整理も含めた値を`baseline/total-with-memory.json`へ追加した。基準値は技術比較1,187,744 tokens、博物館比較637,654 tokens。旧値を消さず範囲の差を明示した。担当判定の未報告tokensは含まない。通知後に開始する記憶整理は計測範囲外。再検証にも同じ範囲を適用する。


時間の切り分けでは、Pursuitの各stepが共通の `inference.llm` を要求し、稼働serverの枠は1であることを確認した（`api/domains/pursuit/service/jobs.ts`、`api/application/server-core.ts`）。これは今回もresource_busyの待機として観測された。前回は推論51回/27回とその入力の蓄積に加え、複数調査の共通枠の待機が大きい。記憶整理は別のaux枠2を使うため、同じ枠の待機として一括りにしない。本文取得の遅延・モデルの処理時間・スケジュール待機も分ける。上限や優先順位を検証中に変更せず、保存270–332msを長時間調査の原因とは扱わない。

既存hostの`deferInTransaction`は検索・外部取得の上限を実行直前に検査するが、ツール一覧には残り0でも検索を提供し続け、上限例外で親stepを閉じる。LLMが残量を守らず再検索したことと、初期下書きしか残らない終了経路が今回の具体的な失敗点。保存上限・時間予算を増やして試験を通す変更はしていない。

両方のMarkdownは一時ファイルとDoclingの`eumenes/research/`へ保存し、公開APIから両方を読み戻して内容一致・タイトル・担当切替なしを確認した。技術比較は出典付き、博物館比較は出典なしである。`live/performance-technical-report.md` / `performance-museum-report.md`が保存した実内容。保存確認は成功、調査完了は不合格として分ける。

`live/input-integrity.json`では製品15ファイルと固定入力hashに変更なし。再起動済みserverの同じbootを使用し、サーバーの起動・停止・再起動をしていない。固定試験を今回再実行して成功件数を水増しせず、実接続結果を追加した。別作業のcommitや既存の未整理差分を巻き戻していない。

残作業は自然文取消と報告内容の未達の修正、および修正後の固定→結合→実接続受入。調査時間・トークンの改善成立は保留。取消の入口変更に関する[追加設計案](../../research-routing-followup-design-2026-11-08.md)は未合意・未実装であり、現在の保存設定は維持した。

Context MCP利用は累計 `context_compile` 5回 / `compile_eval` 5回（今回各1回）。`initial_instructions`は会話開始時の一回だけで、今回再実行していない。


## 追加計測：入力・キャッシュ入力・出力

既存の公開`artifact:usage.dashboard@2` / `usage`を日付指定で全11ページ参照し、前節の35＋31＝66試行をattempt IDで照合した。全件一致、キャッシュ件数の欠損0。保存済み値を読むだけで、推論の再実行・製品DBのクライアント直読・製品改修をしていない。根拠は`live/cache-breakdown.json`。
