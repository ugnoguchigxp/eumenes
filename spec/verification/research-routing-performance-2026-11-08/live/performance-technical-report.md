# オフライン対応の個人用メモアプリ：IndexedDBとWeb Storageの比較

## 結論
メモ本文や添付ファイルなど、構造化されたデータを複数件保存・検索する中心領域にはIndexedDBが適しています。IndexedDBは非同期で、構造化クローン可能なオブジェクト（ファイル／Blobを含む）を扱い、トランザクションやインデックスを備えるためです。一方、少量の単純な設定値などにはWeb Storageの`localStorage`が手軽ですが、同期処理なので大量データの読み書きには注意が必要です。MDNの資料はAPIの性質を説明していますが、アプリ自体をオフラインで起動・利用できることまで保証するものではありません。

## 比較表
| 観点 | IndexedDB | Web Storage（主に`localStorage`） |
|---|---|---|
| 同期・非同期 | 非同期。処理はアプリケーションをブロックしない。 | `localStorage`と`sessionStorage`はいずれも同期的で、処理完了まで他のJavaScript実行をブロックする。 |
| 保存できるデータ | 構造化クローンアルゴリズムで対応するオブジェクト。MDNは構造化データやファイル／Blobを挙げる。オブジェクトストア、キー、インデックスを使うデータベース。 | キー／値ペアを保存する仕組み。本文で確認できた範囲では、具体的な値の型・シリアライズ方法の詳細はここでは断定しない。 |
| 保持・削除 | クライアント側ストレージの容量割当や上限到達時の削除基準は単純ではなく、ブラウザーによって異なる。 | `localStorage`は同一オリジンで共有され、ブラウザーを閉じて再度開いても保持される。`sessionStorage`はタブ単位で、タブを閉じるとそのデータが破棄される。MDNは容量・上限超過時の扱いを別資料へ案内しており、ここで確認した本文だけから具体的上限値は決められない。 |
| 個人用メモでの用途判断 | 本文、複数のメモ、検索用インデックス、添付ファイルなど、比較的大きい・構造化されたデータの保存候補。 | 少量の単純な設定値などの保存候補。メモ本文の主保存先にする場合は、同期処理によるブロックとデータ量に注意する。 |

## 判断できない点・限界
- 実際に使える保存容量、上限到達時の具体的な動作、削除される条件はブラウザーや環境に依存するため、この2ページだけでは一律の数値や保証を示せません。MDNのIndexedDBページは容量・削除の説明がブラウザーで異なるとしています。
- Web Storageページは容量・上限超過時の扱いを別の「Storage quotas and eviction criteria」資料へ案内していますが、その資料本文は今回の確認対象に含まれていません。
- MDNのAPI説明だけでは、アプリのHTML・JavaScript・必要な資源をオフラインで利用可能にする方法や、データのバックアップ／同期方針は決まりません。IndexedDBやWeb Storageを使うことだけで、アプリ全体のオフライン対応が完成するとは判断できません。
- Web Storageに保存する値の型・変換の詳細は、今回確認した本文範囲を越えて断定していません。
