# 記憶担当の入力重複削減：比較と不採用

2026-11-08。**候補を実装して比較したが、品質維持の条件を満たさず不採用。製品コードは開始時の内容へ戻した。**

## 変更した候補

Stewardが自分で書く指示と`OUTPUT_SCHEMA`を外し、既存Inferenceの`operationOutputMessages`で先頭systemへ一度だけ追加した。会話・記憶本文、引用、出典、origin、期間、coverage、構造化出力schema、権限、保存・忘却の検査は維持した。検索、要約、再推論抑制、core/hostパッケージは変更していない。

最初に提案した本文の番号参照化は、現行の会話入力が短縮・結合されるため今回の製品変更へ含めなかった。確実に同じ契約を送っている箇所だけを比較した。

## 条件

- `manifest.json`へ12種類の合成ケース、期待値、旧新の交互実行順、最大24生成、ソース・指示・保存済みLARM設定のhashを実行前に固定した。
- 同じ設定・同じproviderで旧新を各1回。12組すべてで出来事・記憶・依頼等のdataが完全一致した。独立入力6問、共有会話入力6問。共有入力の先頭は合成の短い会話であり、実ユーザーの会話ではない。
- 既存Steward fixtureのprepare・parse・apply、実Memory SQLiteと忘却journal、共通Inferenceの入力整形と既存LARM呼出しを使用した。実アプリの通常稼働経路全体やクラウド経路の実測ではない。
- Providerが返したprompt/completion/cache usageを使用した。見積りtoken数も別に保存したが、実測の代わりに使っていない。
- 採用には新規品質失敗0、危険な誤保存等0、旧版以上の合格数、実token削減を要求した。

## 不採用の根拠

`correction`では、同じ「今は紅茶ではなく緑茶が好きです」という入力に対し、変更前は正しい連続引用で更新が適用された。候補は引用を「前は紅茶ではなく緑茶が好きです」に変えたため、既存の引用検査が拒否した。誤った更新を防ぐ仕組みは動作したが、依頼された訂正が反映されず、以前の紅茶の記憶が残った。候補だけの失敗が1件あり、採用条件に反した。

`other-owner`は両方とも妹の好みを本人用Stateへ保存し、`bounded-time`は両方とも固定正解のStateでなく短期goalへ振り分けたため不合格。期待値やラベルは変更していない。意味の点検では、条件付きの好みを習慣へ強める出力、根拠にない開始時期も両方に見つかった。これらを今回の変更による新規の劣化とは数えず、既存の課題として区別する。

実装者自身が24応答と保存後Stateを点検した。独立した人間評価ではない。一例一観測であり、一般的な失敗率や因果は断定しない。今回の観測で品質維持を確認できなかったため、この候補は採用しない。

## 試験と復帰

- 変更前の対象部分26件、候補の部分・結合130件が成功。
- 元の作業先の標準verifyは、既存`artifacts/`内の試験コピーをinventoryが拾って停止した。検証ルールは変更していない。
- ソースを固定した隔離コピーで、既存依存を参照し、`verify --domain steward --domain memory --domain dialogue --domain inference`が全13段階pass。最初のコピーはpackage固有の依存参照が不足して停止したため、既存のworkspace依存も参照して再実行した。製品データ・設定・秘密はコピーしていない。
- 固定検証には担当外の既存警告と、候補用application試験がSteward内部を参照する境界警告があった。候補用試験は不採用時に製品側から除き、その内容を`candidate-sources.json`へ保存した。警告を解消した候補として扱わない。
- 不採用後、製品側3ファイルと既存試験2ファイルを開始時のhashへ復帰。復帰後の対象22試験が成功。
- 実データの変更、サーバー起動・停止・再起動、commit、他チャットへの送信はしていない。他作業の差分は保持した。

初回は模擬モデル向けfixtureの短いdrainが実モデルの応答前に終了した。未完了の1dispatchは`attempt-1/`へ保存し、usageは不明。応答を取得していないため、完了待ちを修正して比較を再固定した。上表は完了した24生成だけで、この未計測dispatchを0 tokenとして扱っていない。実験全体では計25 dispatch。意味失敗を再生成した結果で置き換えていない。

## 記録

- `baseline-sources.json` / `baseline-identity.json`：開始時の対象ソースと既存作業差分。
- `candidate-sources.json` / `candidate.patch`：不採用候補の実装・試験。
- `manifest.json` / `results.json` / `summary.json`：固定条件、合成入力・出力・実保存結果・usage、集計。
- `acceptance.json`：採否、組ごとのdata一致、意味の点検、制限。
- `candidate-verify-report.json`：隔離環境で候補を検査した時点の結果。復帰後の製品ソースの全体検証ではない。
- `restored-sources.json` / `restored-tests.log`：復帰の照合と対象試験。

`scripts/steward-input-eval.ts`はこの凍結比較の実行記録を作った評価器である。既存の結果を上書きせず、source/設定のhashが違う状態でも実行を拒否する。製品コードの復帰後に、現在のソースを評価済み候補と読み替えて再実行することはできない。
