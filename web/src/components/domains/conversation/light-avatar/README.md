# SAAA 光のアバター

[SAAA — 光のアバター](https://saaa-light-voice-study.ugnoguchi.chatgpt.site)の B（光の精霊）を会話画面に透過表示する。描画素材は SAAA のローカル実装から移植した。Site の画面や音声 UI は埋め込まず、外部通信をせずに Three.js 0.186.1 で透過 canvas を描画する。

参照元: `/Users/y.noguchi/Code/SAAA/src/features/chat/avatar/`、HEAD `28616e61ce5fe853383d4af6ec14e5b5d542c076`。参照元ファイルは作業時に HEAD との差分なし。SAAA の checkout、製品 DB、設定、秘密は変更・コピーしていない。

移植時に formatter を適用し、未使用引数の名前とリソース解放時の不要な配列化だけを変更した。形状、色、camera、shader、透過描画は維持している。元の pose 関数は初期姿勢と13種類の動作に使う。Eumenes の avatar domain が listening / thinking、および採用済み音声句に付いた Laya の動作を再生する。音声の実再生開始で発話cueを開始し、8秒の話す動作と感情の動作を音声終了まで繰り返す。通常の身振りは元の半分に抑え、瞬きの深さは維持する。発話中は頷き・手振りを重ね、うなだれる・照れる・眠そうな動作には小さめに重ねる。判断がない場合も通常の話す仕草を行う。句の終了・割込み・取消では0.7秒で通常姿勢に戻り、待機中の呼吸・揺れ・光の動きを続ける。発話ではない状態動作は最大8秒で待機へ戻る。

`LightAvatarBackground.tsx` が canvas の生成、サイズ変更、破棄を所有する。設定・辞書画面への移動、タブ非表示、unmount 時に GPU リソースを解放する。遅れて import が完了しても破棄済み画面には canvas を追加しない。WebGL 非対応や描画失敗時も会話は利用できる。`prefers-reduced-motion` では静止姿勢だけを表示する。表示中は待機12fps、身振り24fpsを上限として更新する。表示全体の時計と句の時計を分け、句の切替でも呼吸や光の時計を巻き戻さない。口の振幅同期と音声の pause/resume は未実装。

Three.js のライセンスを `THREE-LICENSE.txt` に同梱する。

待機動作は `idle.ts` で表示全体の時計から生成する。6秒周期の上下移動、首・身体のゆっくりした揺れ、8秒周期の腕の動き、数秒おきの瞬きを重ねる。上下移動の振幅は初期実装の0.008から0.065へ増やし、静止して見えるほど小さな動きを避ける。句の切替でこの時計をリセットせず、身振りの終了や取消後も待機動作へ自然に戻す。静止設定では時計を0に固定し、待機姿勢と開いた目を維持する。

約30秒間隔で4.8秒だけ、体を左右に軽く振る仕草を入れる。左右の順番を交互にし、開始と終了で振幅と速度を0へ近づける。回答動作や発話に入ると0.7秒かけて抑える。読み上げ直しでも採用済みの音声とmotionを一緒に返し、HTMLAudioElementのplayingで発話cueを開始する。終了・取消・消音と遅い旧イベントは音声対話と同様に扱う。

開発用の依存キャッシュは `node_modules/.vite/development`、ブラウザfixtureはfixtureごとの一時ディレクトリに分ける。異なる環境のViteサーバーが同じキャッシュを置換すると、実行中の開発画面が古い依存URLを参照し、動的importが504で失敗してアバターが消える。Three.jsは起動時の依存最適化に含める。描画hostの `data-avatar-state` で読み込み・描画失敗・非表示・非対応を切り分ける。初期化失敗のconsole警告にはエラーの種類だけを渡す。

2026-10-09以降は、回答全体からLayaが選んだ5種の感情をmotionへ対応させる。親しみ→agreeing、喜び→joyful、寄り添う→listening、興味→curious、驚き→surprised。発話の頷き・手振りは別のcueとして重ねる。待機の呼吸・瞬き・時折の体振りは判断の有無にかかわらず継続する。会話の名前横にはmotionではなく同じ感情の絵文字を表示する。通常・低確度・fallback、および旧motionだけの回答には感情アイコンを付けない。判定と保存・取消の現行仕様は [Laya計画](../../../../../../spec/laya-voicevox-avatar-plan.md) の現行仕様節を参照。
